# 007001009_WPF 数据绑定高级实例

以下实例均面向**工业上位机、视觉检测、设备控制**等复杂业务场景，覆盖嵌套对象绑定、多值转换、动态模板、数据校验、集合视图、命令绑定等进阶特性，是落地完整 MVVM 架构的核心技能，所有代码可直接复用到工位软件、检测系统中。

前置基础：已掌握基础单向 / 双向绑定、`INotifyPropertyChanged`、`ObservableCollection`。

## 通用辅助类（所有实例复用）

### 1. ViewModel 基类

csharp:

```c#
using System.ComponentModel;
using System.Runtime.CompilerServices;

public class ViewModelBase : INotifyPropertyChanged
{
    public event PropertyChangedEventHandler PropertyChanged;

    protected void OnPropertyChanged([CallerMemberName] string propertyName = null)
    {
        PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(propertyName));
    }

    protected bool SetProperty<T>(ref T field, T value, [CallerMemberName] string propertyName = null)
    {
        if (EqualityComparer<T>.Default.Equals(field, value)) return false;
        field = value;
        OnPropertyChanged(propertyName);
        return true;
    }
}
```

### 2. 命令基类（RelayCommand，MVVM 命令必备）

csharp:

```c#
using System.Windows.Input;

public class RelayCommand : ICommand
{
    private readonly Action<object> _execute;
    private readonly Func<object, bool> _canExecute;

    public RelayCommand(Action<object> execute, Func<object, bool> canExecute = null)
    {
        _execute = execute;
        _canExecute = canExecute;
    }

    public event EventHandler CanExecuteChanged
    {
        add => CommandManager.RequerySuggested += value;
        remove => CommandManager.RequerySuggested -= value;
    }

    public bool CanExecute(object parameter) => _canExecute?.Invoke(parameter) ?? true;
    public void Execute(object parameter) => _execute?.Invoke(parameter);
}
```

## 实例 1：多级嵌套属性绑定 + 空值兜底

### 场景

工业项目中 ViewModel 通常会嵌套多层对象（工位→相机→参数），需要绑定深层属性；同时要处理对象为空时的绑定异常，保证界面稳定性。

### ViewModel 嵌套模型

csharp:

```c#
// 相机参数类
public class CameraParams : ViewModelBase
{
    private double _exposure = 1500;
    public double Exposure
    {
        get => _exposure;
        set => SetProperty(ref _exposure, value);
    }

    private double _gain = 1.2;
    public double Gain
    {
        get => _gain;
        set => SetProperty(ref _gain, value);
    }
}

// 工位视图模型
public class StationViewModel : ViewModelBase
{
    private CameraParams _guideCamera;
    /// <summary> 引导相机参数（嵌套对象） </summary>
    public CameraParams GuideCamera
    {
        get => _guideCamera;
        set => SetProperty(ref _guideCamera, value);
    }

    public StationViewModel()
    {
        GuideCamera = new CameraParams();
    }
}
```

### XAML 绑定（多级路径 + 空值兜底）

xaml:

```xaml
<StackPanel Margin="30" Spacing="10">
    <!-- 多级路径：用点号分隔，直接绑定嵌套对象的属性 -->
    <TextBlock Text="{Binding GuideCamera.Exposure, StringFormat=曝光时间：{0} μs}"/>
    <TextBlock Text="{Binding GuideCamera.Gain, StringFormat=增益值：{0:F1} dB}"/>

    <!-- 兜底1：FallbackValue 绑定失败时显示（比如属性名写错、对象为空） -->
    <TextBlock Text="{Binding GuideCamera.TriggerMode, FallbackValue=模式未知}"/>

    <!-- 兜底2：TargetNullValue 数据源为null时显示 -->
    <TextBlock Text="{Binding GuideCamera.SerialNumber, TargetNullValue=未连接}"/>
</StackPanel>
```

### 核心要点

1. **多级路径**：用 `.` 分隔嵌套属性，层级无限制，如 `Station.Camera.Params.Exposure`；
2. **空值安全**：`GuideCamera` 为 null 时不会抛异常，界面自动显示兜底值；
3. **两种兜底区别**：
   - `FallbackValue`：绑定完全失败（路径错误、类型不匹配）时生效；
   - `TargetNullValue`：绑定路径正确，但数据源值为 null 时生效。

## 实例 2：多值绑定 + `IMultiValueConverter`

### 场景

一个 UI 属性由多个数据属性共同决定，典型工业场景：

- 缺陷框的 X、Y、宽、高四个属性，共同决定 Canvas 上的位置大小；
- 设备运行状态 + 告警状态，共同合成最终的指示灯颜色。

本例实现：**运行状态 + 告警状态 → 合成指示灯颜色**。

### 第一步：实现多值转换器

csharp:

```c#
using System.Globalization;
using System.Windows.Data;
using System.Windows.Media;

/// <summary>
/// 双状态合成颜色：运行+无告警=绿色，运行+告警=黄色，停机=红色
/// </summary>
public class StatusToBrushConverter : IMultiValueConverter
{
    public object Convert(object[] values, Type targetType, object parameter, CultureInfo culture)
    {
        // values[0] = IsRunning（是否运行）
        // values[1] = IsAlarming（是否告警）
        if (values[0] is bool isRunning && values[1] is bool isAlarming)
        {
            if (!isRunning) return Brushes.Gray;       // 停机
            if (isAlarming) return Brushes.Orange;     // 运行中告警
            return Brushes.LimeGreen;                  // 正常运行
        }
        return Brushes.Gray;
    }

    // 反向转换一般不需要实现
    public object[] ConvertBack(object value, Type[] targetTypes, object parameter, CultureInfo culture)
        => throw new NotImplementedException();
}
```

### 第二步：XAML 多值绑定

xaml:

```xaml
<Window.Resources>
    <local:StatusToBrushConverter x:Key="StatusToBrushConverter"/>
</Window.Resources>

<StackPanel Margin="30" Spacing="10">
    <!-- 状态指示灯：填充色由两个属性共同决定 -->
    <Ellipse Width="60" Height="60">
        <Ellipse.Fill>
            <MultiBinding Converter="{StaticResource StatusToBrushConverter}">
                <Binding Path="IsRunning"/>
                <Binding Path="IsAlarming"/>
            </MultiBinding>
        </Ellipse.Fill>
    </Ellipse>

    <CheckBox Content="设备运行" IsChecked="{Binding IsRunning, Mode=TwoWay}"/>
    <CheckBox Content="触发告警" IsChecked="{Binding IsAlarming, Mode=TwoWay}"/>
</StackPanel>
```

### 核心要点

1. 适合**多输入单输出**的场景，比写多个触发器、多个转换器更简洁；
2. 任意一个绑定的属性变化，都会重新执行转换，更新 UI；
3. 工业扩展：可接入 3~N 个状态，合成更复杂的设备状态显示。

## 实例 3：`DataTemplateSelector` 动态数据模板

### 场景

集合中是不同类型的对象，需要根据类型自动匹配不同的 UI 模板。

典型场景：缺陷列表包含**点缺陷、线缺陷、面缺陷**，每种缺陷显示的字段、图形都不一样。

### 第一步：定义异构数据模型

csharp:

```c#
// 缺陷基类
public abstract class DefectBase : ViewModelBase
{
    public double X { get; set; }
    public double Y { get; set; }
    public bool IsCritical { get; set; }
}

// 点缺陷
public class PointDefect : DefectBase
{
    public double Diameter { get; set; } // 直径
}

// 线缺陷
public class LineDefect : DefectBase
{
    public double Length { get; set; } // 长度
    public double Width { get; set; }  // 宽度
}

// 面缺陷
public class AreaDefect : DefectBase
{
    public double Area { get; set; } // 面积
}
```

### 第二步：实现模板选择器

csharp:

```c#
using System.Windows;
using System.Windows.Controls;

public class DefectTemplateSelector : DataTemplateSelector
{
    // 三个模板，在XAML中赋值
    public DataTemplate PointDefectTemplate { get; set; }
    public DataTemplate LineDefectTemplate { get; set; }
    public DataTemplate AreaDefectTemplate { get; set; }

    public override DataTemplate SelectTemplate(object item, DependencyObject container)
    {
        return item switch
        {
            PointDefect => PointDefectTemplate,
            LineDefect => LineDefectTemplate,
            AreaDefect => AreaDefectTemplate,
            _ => base.SelectTemplate(item, container)
        };
    }
}
```

### 第三步：XAML 使用

xaml:

```c#
<Window.Resources>
    <!-- 1. 定义三种缺陷的模板 -->
    <DataTemplate x:Key="PointDefectTemplate">
        <StackPanel Orientation="Horizontal" Spacing="10">
            <Ellipse Width="16" Height="16" Fill="Red" VerticalAlignment="Center"/>
            <TextBlock Text="{Binding Diameter, StringFormat=点缺陷 直径：{0}mm}"/>
        </StackPanel>
    </DataTemplate>

    <DataTemplate x:Key="LineDefectTemplate">
        <StackPanel Orientation="Horizontal" Spacing="10">
            <Rectangle Width="20" Height="4" Fill="Orange" VerticalAlignment="Center"/>
            <TextBlock Text="{Binding Length, StringFormat=线缺陷 长度：{0}mm}"/>
        </StackPanel>
    </DataTemplate>

    <DataTemplate x:Key="AreaDefectTemplate">
        <StackPanel Orientation="Horizontal" Spacing="10">
            <Rectangle Width="16" Height="16" Fill="Purple" VerticalAlignment="Center"/>
            <TextBlock Text="{Binding Area, StringFormat=面缺陷 面积：{0}mm²}"/>
        </StackPanel>
    </DataTemplate>

    <!-- 2. 实例化选择器，关联三个模板 -->
    <local:DefectTemplateSelector x:Key="DefectTemplateSelector"
                                  PointDefectTemplate="{StaticResource PointDefectTemplate}"
                                  LineDefectTemplate="{StaticResource LineDefectTemplate}"
                                  AreaDefectTemplate="{StaticResource AreaDefectTemplate}"/>
</Window.Resources>

<Grid Margin="30">
    <!-- 3. 列表绑定模板选择器 -->
    <ItemsControl ItemsSource="{Binding DefectList}"
                  ItemTemplateSelector="{StaticResource DefectTemplateSelector}"/>
</Grid>
```

### ViewModel 集合

csharp:

```c#
public ObservableCollection<DefectBase> DefectList { get; set; } = new();

// 初始化混合类型的缺陷
public void InitDefects()
{
    DefectList.Add(new PointDefect { X = 100, Y = 200, Diameter = 0.12, IsCritical = true });
    DefectList.Add(new LineDefect { X = 150, Y = 180, Length = 2.5, Width = 0.05 });

```

### 核心要点

1. 解决**异构集合**的展示问题，每种类型对应独立的 UI 结构；
2. 选择器逻辑可扩展：不仅按类型，还可以按严重程度、优先级选择模板；
3. 完全符合 MVVM，数据和视图彻底分离。

## 实例 4：`ICollectionView` 集合筛选、排序、分组

### 场景

对已有集合做**筛选、排序、分组**，不修改原始数据源，只操作视图层，适合列表查询、过滤、分类展示场景。

典型场景：缺陷列表 “只显示严重缺陷”、“按坐标排序”、“按类型分组”。

### ViewModel 实现

csharp:

```c#
using System.ComponentModel;
using System.Windows.Data;

public class StationViewModel : ViewModelBase
{
    public ObservableCollection<DefectBase> DefectList { get; set; } = new();

    // 集合视图：用于筛选、排序、分组
    public ICollectionView DefectView { get; }

    private bool _onlyShowCritical;
    /// <summary> 只显示严重缺陷 </summary>
    public bool OnlyShowCritical
    {
        get => _onlyShowCritical;
        set
        {
            SetProperty(ref _onlyShowCritical, value);
            // 刷新视图，重新应用筛选
            DefectView.Refresh();
        }
    }

    public StationViewModel()
    {
        // 获取默认集合视图
        DefectView = CollectionViewSource.GetDefaultView(DefectList);

        // 1. 设置筛选逻辑
        DefectView.Filter = item =>
        {
            if (!OnlyShowCritical) return true;
            return item is DefectBase defect && defect.IsCritical;
        };

        // 2. 设置排序：按X坐标升序
        DefectView.SortDescriptions.Add(
            new SortDescription("X", ListSortDirection.Ascending));

        // 3. 设置分组：按缺陷类型分组
        DefectView.GroupDescriptions.Add(
            new PropertyGroupDescription(nameof(DefectBase.GetType).Name));
    }
}
```

### XAML 绑定视图

xaml:

```xaml
<StackPanel Margin="30" Spacing="10">
    <CheckBox Content="只显示严重缺陷" 
              IsChecked="{Binding OnlyShowCritical, Mode=TwoWay}"/>

    <ListBox ItemsSource="{Binding DefectView}" Height="300">
        <!-- 分组标题样式 -->
        <ListBox.GroupStyle>
            <GroupStyle>
                <GroupStyle.HeaderTemplate>
                    <DataTemplate>
                        <TextBlock Text="{Binding Name}" 
                                   FontWeight="Bold" Background="#EEE" Padding="5"/>
                    </DataTemplate>
                </GroupStyle.HeaderTemplate>
            </GroupStyle>
        </ListBox.GroupStyle>

        <ListBox.ItemTemplate>
            <DataTemplate>
                <TextBlock Text="{Binding X, StringFormat=位置X：{0}}"/>
            </DataTemplate>
        </ListBox.ItemTemplate>
    </ListBox>
</StackPanel>
```

### 核心要点

1. **不修改原始数据**：筛选、排序都是视图层行为，原始 `ObservableCollection` 保持不变；
2. **性能更好**：比 “重新生成一个过滤后的集合” 更高效，无需频繁创建销毁集合；
3. 扩展能力强：支持多条件筛选、多字段排序、多级分组。

## 实例 5：输入参数校验（`ValidationRule`）

### 场景

工业参数配置必须限制输入范围，防止非法参数写入设备。比如曝光时间必须在 100~10000μs 之间，输入超出范围时界面显示错误提示。

### 第一步：自定义校验规则

csharp:

```c#
using System.Globalization;
using System.Windows.Controls;

public class ExposureValidationRule : ValidationRule
{
    public double Min { get; set; } = 100;
    public double Max { get; set; } = 10000;

    public override ValidationResult Validate(object value, CultureInfo cultureInfo)
    {
        if (!double.TryParse(value?.ToString(), out double num))
            return new ValidationResult(false, "请输入有效数字");

        if (num < Min || num > Max)
            return new ValidationResult(false, $"取值范围：{Min} ~ {Max} μs");

        return ValidationResult.ValidResult;
    }
}
```

### 第二步：XAML 绑定中加入校验

xaml:

```xaml
<StackPanel Margin="30" Spacing="10">
    <TextBlock Text="相机曝光时间（μs）："/>
    <TextBox Width="200">
        <TextBox.Text>
            <Binding Path="GuideCamera.Exposure" 
                     Mode="TwoWay" 
                     UpdateSourceTrigger="PropertyChanged">
                <Binding.ValidationRules>
                    <local:ExposureValidationRule Min="100" Max="10000"/>
                </Binding.ValidationRules>
            </Binding>
        </TextBox.Text>
    </TextBox>
</StackPanel>
```

### 效果

输入非法值时，输入框自动显示红色边框，鼠标悬停显示错误信息；非法值不会回写到数据源，保证数据安全。

### 核心要点

1. 校验发生在**绑定回写数据源之前**，非法值不会污染业务数据；
2. 可自定义错误模板，实现更美观的错误提示；
3. 工业场景必备：所有设备参数输入都应加范围校验，避免误操作导致设备异常。

## 实例 6：命令绑定（`ICommand` 纯 MVVM）

### 场景

按钮点击、菜单操作不写后台事件，直接绑定 ViewModel 中的命令，彻底解耦 UI 和业务逻辑，是 MVVM 的核心标志。

### ViewModel 实现

csharp:

```c#
public class StationViewModel : ViewModelBase
{
    private bool _isRunning;
    public bool IsRunning
    {
        get => _isRunning;
        set => SetProperty(ref _isRunning, value);
    }

    // 开始检测命令
    public ICommand StartDetectCommand { get; }
    // 停止检测命令
    public ICommand StopDetectCommand { get; }
    // 设置曝光命令（带参数）
    public ICommand SetExposureCommand { get; }

    public StationViewModel()
    {
        StartDetectCommand = new RelayCommand(OnStartDetect, _ => !IsRunning);
        StopDetectCommand = new RelayCommand(OnStopDetect, _ => IsRunning);
        SetExposureCommand = new RelayCommand(OnSetExposure);
    }

    private void OnStartDetect(object obj)
    {
        IsRunning = true;
        // 执行开始检测业务逻辑...
    }

    private void OnStopDetect(object obj)
    {
        IsRunning = false;
        // 执行停止检测业务逻辑...
    }

    private void OnSetExposure(object obj)
    {
        if (double.TryParse(obj?.ToString(), out double val))
        {
            GuideCamera.Exposure = val;
        }
    }
}
```

### XAML 绑定命令

xaml:

```xaml
<StackPanel Margin="30" Spacing="10">
    <!-- 无参数命令 -->
    <Button Content="开始检测" Command="{Binding StartDetectCommand}" Width="120"/>
    <Button Content="停止检测" Command="{Binding StopDetectCommand}" Width="120"/>

    <!-- 带参数命令 -->
    <Button Content="设置曝光为2000" 
            Command="{Binding SetExposureCommand}"
            CommandParameter="2000"
            Width="180"/>
</StackPanel>
```

### 核心要点

1. **零后台代码**：按钮点击完全不依赖 Window 后台事件，UI 和逻辑彻底解耦；
2. **自动可用状态**：`CanExecute` 返回 false 时，按钮自动禁用，不用手动设置 `IsEnabled`；
3. **可单元测试**：直接测试 ViewModel 的命令，无需实例化窗口，大幅提升可测试性。

## 实例 7：`RelativeSource` + 数据触发器 实现列表联动

### 场景

ListBox 选中某条缺陷记录时，画布上对应的缺陷框自动高亮，纯 XAML 实现，不用后台事件。

### XAML 实现

xaml:

```xaml
<ListBox ItemsSource="{Binding DefectList}" Width="200">
    <ListBox.ItemTemplate>
        <DataTemplate>
            <!-- 缺陷框矩形 -->
            <Rectangle Width="{Binding Width}" Height="{Binding Height}"
                       Stroke="Gray" StrokeThickness="1" Fill="#22FFFFFF">
                <Rectangle.Style>
                    <Style TargetType="Rectangle">
                        <Style.Triggers>
                            <!-- 向上找父级 ListBoxItem，监听 IsSelected 属性 -->
                            <DataTrigger 
                                Binding="{Binding IsSelected, 
                                    RelativeSource={RelativeSource AncestorType=ListBoxItem}}" 
                                Value="True">
                                <Setter Property="Stroke" Value="Yellow"/>
                                <Setter Property="StrokeThickness" Value="3"/>
                            </DataTrigger>
                        </Style.Triggers>
                    </Style>
                </Rectangle.Style>
            </Rectangle>
        </DataTemplate>
    </ListBox.ItemTemplate>
</ListBox>
```

### 核心要点

1. `RelativeSource AncestorType` 沿可视化树向上查找指定类型的父元素，不需要给控件起名；
2. 纯 XAML 实现交互，符合 MVVM，不需要后台代码监听选中事件；
3. 工业场景常用：列表与图形联动、选中高亮、详情联动显示。

## 高级绑定选型总结

| 场景                     | 方案              | 核心类 / 关键字                        |
| :----------------------- | :---------------- | :------------------------------------- |
| 嵌套对象深层属性绑定     | 多级路径 + 兜底值 | `.` 路径、`FallbackValue`              |
| 多个数据决定一个 UI 属性 | 多值转换器        | `MultiBinding`、`IMultiValueConverter` |
| 异构集合不同 UI 展示     | 数据模板选择器    | `DataTemplateSelector`                 |
| 列表筛选、排序、分组     | 集合视图          | `ICollectionView`                      |
| 参数输入合法性校验       | 绑定校验规则      | `ValidationRule`                       |
| 按钮操作解耦、纯 MVVM    | 命令绑定          | `ICommand`、`RelayCommand`             |
| 模板内找父级属性         | 相对源绑定        | `RelativeSource AncestorType`          |
