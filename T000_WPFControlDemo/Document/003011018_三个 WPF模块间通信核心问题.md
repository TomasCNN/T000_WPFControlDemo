# 003011018_三个 WPF 模块间通信核心问题

## 问题一：如何在 WPF 中实现模块间的松耦合？

### 核心定义

松耦合 = **模块之间只依赖抽象，不依赖具体实现**。修改一个模块的内部实现，不会影响任何其他模块。这是工业软件能够**5~10 年稳定运行、快速迭代、硬件可插拔**的基础。

### 一、实现松耦合的 5 大核心技术（按重要性排序）

------

#### 1. 依赖倒置原则（DIP）：松耦合的基石

**核心思想**：

- 上层模块不应该依赖下层模块，两者都应该依赖抽象
- 抽象不应该依赖细节，细节应该依赖抽象

**工业场景最经典应用：硬件抽象层**

csharp:

```c#
// ❌ 强耦合：直接依赖具体的埃科相机
public class CameraService
{
    private readonly IkCamera _camera = new IkCamera(); // 硬编码依赖
}

// ✅ 松耦合：依赖抽象接口
public class CameraService
{
    private readonly ICamera _camera; // 只依赖接口，不依赖具体实现

    // 构造函数注入，运行时才决定用哪个相机
    public CameraService(ICamera camera)
    {
        _camera = camera;
    }
}
```

**巨大优势**：换相机品牌时，只需要写一个新的`ICamera`实现，上层代码**一行都不用改**。

------

#### 2. 依赖注入（DI）：松耦合的实现工具

**核心原理**：由一个全局容器负责创建和管理所有对象，模块之间的依赖由容器自动注入，而不是自己 new 对象。

**你的模板中已经在使用的 Prism DI 示例**：

csharp:

```c#
// 1. 在App.xaml.cs中注册抽象和实现
containerRegistry.RegisterSingleton<ICamera, IkCamera>();
containerRegistry.RegisterSingleton<IPlc, SiemensPlc>();
containerRegistry.Register<CameraService>();

// 2. 在需要的地方通过构造函数注入
public class DetectionProcess
{
    // 不需要自己new CameraService和PlcService
    public DetectionProcess(CameraService cameraService, PlcService plcService)
    {
        // 容器自动注入实例
    }
}
```

**关键优势**：

- 彻底消除硬编码依赖
- 轻松实现单例、瞬态等生命周期管理
- 单元测试时可以轻松替换为 Mock 对象

------

#### 3. 接口隔离原则（ISP）：最小化依赖

**核心思想**：一个类不应该依赖它不需要的接口。将大接口拆分成多个小而专一的接口。

**工业场景示例**：

csharp:

```c#
// ❌ 胖接口：面阵相机不需要线扫速度设置
public interface ICamera
{
    bool Initialize();
    Bitmap GetBitmap();
    bool SetLineScanSpeed(int speed); // 面阵相机没有这个功能
}

// ✅ 接口隔离：拆分多个小接口
public interface ICamera : IDisposable
{
    bool Initialize();
    Bitmap GetBitmap(int timeout);
}

public interface ILineScanCamera : ICamera
{
    bool SetLineScanSpeed(int speed);
}

public interface IAreaScanCamera : ICamera
{
    bool SetTriggerDelay(int delay);
}
```

------

#### 4. 事件驱动架构：彻底解耦模块间的调用

**核心原理**：模块之间不直接调用对方的方法，而是通过发布 / 订阅事件进行通信。发布者不知道谁会订阅，订阅者也不知道谁发布了事件。

**Prism 事件聚合器示例（你的模板标准用法）**：

csharp:

```\
// 1. 定义事件（放在Common/Events文件夹）
public class DefectDetectedEvent : PubSubEvent<List<Defect>> { }

// 2. 算法模块发布事件
public class AlgorithmService
{
    public List<Defect> DetectDefects(Bitmap image)
    {
        var defects = new List<Defect>();
        // 算法处理...
        
        // 发布事件，不需要知道谁会接收
        _eventAggregator.GetEvent<DefectDetectedEvent>().Publish(defects);
        return defects;
    }
}

// 3. 监控模块订阅事件
public class MonitorViewModel
{
    public MonitorViewModel(IEventAggregator eventAggregator)
    {
        // 订阅事件，不需要知道谁发布
        eventAggregator.GetEvent<DefectDetectedEvent>()
            .Subscribe(OnDefectDetected, ThreadOption.UIThread);
    }

    private void OnDefectDetected(List<Defect> defects)
    {
        // 更新UI显示缺陷
    }
}
```

------

#### 5. 配置化与动态加载：实现真正的插件化

**核心原理**：将模块的差异部分提取到配置文件中，甚至可以在运行时动态加载模块，不需要重新编译。

**工业场景示例：硬件可插拔**

json

```json
// appsettings.json配置文件
{
  "Hardware": {
    "Camera": {
      "Type": "Ik",
      "ExposureTime": 1000
    },
    "Plc": {
      "Type": "Siemens",
      "IpAddress": "192.168.1.100"
    }
  }
}
```

csharp:

```c#
// 工厂类根据配置动态创建硬件实例
public class HardwareFactory
{
    public ICamera CreateCamera()
    {
        var cameraType = _config.Hardware.Camera.Type;
        return cameraType switch
        {
            "Ik" => new IkCamera(_logger, _config.Hardware.Camera),
            "Hik" => new HikCamera(_logger, _config.Hardware.Camera),
            "Basler" => new BaslerCamera(_logger, _config.Hardware.Camera),
            _ => throw new NotSupportedException($"不支持的相机类型：{cameraType}")
        };
    }
}
```

### 二、必须避免的 7 种强耦合陷阱

1. ❌ **直接 new 对象**：`var camera = new IkCamera();`
2. ❌ **静态类和单例**：`public static class CameraManager { }`
3. ❌ **硬编码魔法字符串**：`_plc.WriteShort("D200", 3);`
4. ❌ **跨层调用**：ViewModel 直接操作硬件
5. ❌ **循环依赖**：A 依赖 B，B 依赖 A
6. ❌ **事件不取消订阅**：导致内存泄漏
7. ❌ **共享全局变量**：`public static Bitmap CurrentImage;`

## 问题二：除了上述提到的方式，还有哪些方式可以实现模块间的通信？

之前已经讲过**Prism 事件聚合器、共享服务、依赖注入、回调委托**，这里补充 6 种工业场景常用的通信方式，覆盖从单进程内到跨设备的所有需求。

### 1. MediatR（请求 / 响应模式）【工业业务层首选】

**核心原理**：基于中介者模式，将请求和处理完全分离，发送者不知道谁处理，处理者也不知道谁发送。

**适用场景**：跨模块的命令调用、查询请求、业务流程触发。

**代码示例**：

csharp:

```c#
// 1. 定义命令
public class StartDetectionCommand : IRequest<bool> { }

// 2. 定义命令处理者
public class StartDetectionCommandHandler : IRequestHandler<StartDetectionCommand, bool>
{
    private readonly DetectionProcess _detectionProcess;

    public StartDetectionCommandHandler(DetectionProcess detectionProcess)
    {
        _detectionProcess = detectionProcess;
    }

    public async Task<bool> Handle(StartDetectionCommand request, CancellationToken cancellationToken)
    {
        return await _detectionProcess.RunAsync();
    }
}

// 3. 发送命令
public class MainViewModel
{
    private readonly IMediator _mediator;

    public MainViewModel(IMediator mediator)
    {
        _mediator = mediator;
    }

    private async void StartProcess()
    {
        // 发送命令，不需要知道谁处理
        var result = await _mediator.Send(new StartDetectionCommand());
    }
}
```

**优势**：比事件聚合器更适合需要返回值的场景，天然支持异步和取消。

------

### 2. 消息队列（MQTT/RabbitMQ）【跨进程 / 跨设备首选】

**核心原理**：通过第三方消息代理进行通信，支持发布 / 订阅、点对点等模式。

**适用场景**：多设备通信、分布式系统、与第三方系统集成。

**工业场景示例：与 MES 系统通信**

csharp:

```c#
// 发布检测结果到MES
public async Task PublishResultAsync(ProductRecord record)
{
    var message = JsonConvert.SerializeObject(record);
    await _mqttClient.PublishAsync("vision/result", message);
}

// 订阅MES的生产指令
public void SubscribeToCommands()
{
    _mqttClient.ApplicationMessageReceivedAsync += async e =>
    {
        if (e.ApplicationMessage.Topic == "mes/command")
        {
            var command = JsonConvert.DeserializeObject<MesCommand>(e.ApplicationMessage.Payload);
            await ProcessMesCommandAsync(command);
        }
    };
}
```

------

### 3. 共享内存【高速大数据传输首选】

**核心原理**：多个进程共享同一块物理内存，数据不需要复制，直接读写。

**适用场景**：高速图像数据传输、大文件共享、与 C++ 算法库交互。

**工业场景示例：与 C++ 算法库共享图像**

csharp:

```c#
// 创建共享内存
using var sharedMemory = MemoryMappedFile.CreateNew("VisionImage", 1920 * 1080 * 3);
using var stream = sharedMemory.CreateViewStream();

// 写入图像数据
var imageData = bitmap.LockBits(...);
stream.Write(imageData.Scan0, 0, imageData.Stride * imageData.Height);
bitmap.UnlockBits(imageData);

// C++算法库直接读取共享内存中的图像
```

**优势**：性能比 TCP/IP 高 10~100 倍，适合线扫相机的大图像传输。

------

### 4. 数据库轮询【简单数据共享首选】

**核心原理**：一个模块写入数据库，另一个模块定时读取数据库。

**适用场景**：非实时数据共享、生产记录、参数配置。

**示例**：参数配置模块写入数据库，检测模块定时读取最新参数。

------

### 5. WebSocket【实时双向通信首选】

**核心原理**：建立持久的 TCP 连接，实现全双工通信。

**适用场景**：Web 端监控、手机 APP 远程控制、实时数据推送。

------

### 6. Prism 区域导航参数【页面间传值首选】

**核心原理**：导航时通过参数传递数据。

**适用场景**：从列表页跳转到详情页、页面间传递简单数据。

**代码示例**：

csharp:

```c#
// 导航并传递参数
_regionManager.RequestNavigate("MainRegion", "DetailView", new NavigationParameters
{
    { "ProductId", productId }
});

// 接收参数
public class DetailViewModel : INavigationAware
{
    public void OnNavigatedTo(NavigationContext navigationContext)
    {
        if (navigationContext.Parameters.TryGetValue("ProductId", out int productId))
        {
            LoadProductDetails(productId);
        }
    }
}
```

## 问题三：如何在实际项目中选择合适的模块间通信方式？

### 一、所有通信方式综合对比表

| 通信方式         | 耦合度 | 性能 | 复杂度 | 线程安全   | 适用范围             | 工业场景推荐度 |
| :--------------- | :----- | :--- | :----- | :--------- | :------------------- | :------------- |
| Prism 事件聚合器 | 极低   | 高   | 低     | 是         | 单进程内通知         | ⭐⭐⭐⭐⭐          |
| 共享服务         | 低     | 极高 | 低     | 需自行保证 | 单进程内全局状态共享 | ⭐⭐⭐⭐⭐          |
| MediatR          | 极低   | 高   | 中     | 是         | 单进程内命令 / 查询  | ⭐⭐⭐⭐           |
| 依赖注入         | 低     | 极高 | 低     | 是         | 单进程内服务依赖     | ⭐⭐⭐⭐⭐          |
| 区域导航参数     | 低     | 极高 | 低     | 是         | 页面间传值           | ⭐⭐⭐⭐           |
| 消息队列         | 极低   | 中   | 中     | 是         | 跨进程 / 跨设备      | ⭐⭐⭐            |
| 共享内存         | 中     | 极高 | 高     | 需自行保证 | 高速大数据传输       | ⭐⭐⭐            |
| 数据库轮询       | 低     | 低   | 低     | 是         | 非实时数据共享       | ⭐⭐             |
| WebSocket        | 低     | 中   | 中     | 是         | Web / 移动端通信     | ⭐⭐             |
| 回调委托         | 高     | 极高 | 低     | 否         | 简单局部通信         | ⭐              |

------

### 二、工业上位机决策流程（按优先级）

#### 第一步：判断通信范围

- **单进程内** → 进入第二步
- **跨进程 / 跨设备** → 优先用**MQTT 消息队列**
- **高速大数据传输** → 用**共享内存**
- **Web / 移动端访问** → 用**WebSocket**

#### 第二步：判断通信类型（单进程内）

1. **通知类（不需要返回值）**

   

   - 状态变化、事件发生 → **Prism 事件聚合器**
   - 示例：缺陷检测完成、设备状态变化、报警触发

   

2. **数据共享类**

   

   - 全局状态、系统配置 → **共享服务**
   - 示例：设备运行状态、当前产品参数、用户信息

   

3. **命令 / 查询类（需要返回值）**

   

   - 触发业务流程、查询数据 → **MediatR**
   - 示例：开始检测、停止检测、查询历史记录

   

4. **页面间传值**

   

   - 导航时传递简单数据 → **Prism 区域导航参数**

   

5. **服务依赖**

   

   - 模块需要调用其他模块的服务 → **依赖注入**

   

------

### 三、工业场景最佳实践

1. **90% 的场景用 Prism 事件聚合器 + 共享服务**就足够了
2. **业务流程用 MediatR**，让代码更清晰、更易测试
3. **绝对不要用回调委托**进行跨模块通信，会导致强耦合
4. **事件必须取消订阅**：在 ViewModel 的`OnNavigatedFrom`或`Dispose`方法中取消订阅
5. **共享服务必须保证线程安全**：使用`lock`或`ConcurrentDictionary`
6. **跨设备通信统一用 MQTT**：工业界标准协议，几乎所有设备都支持

------

## 总结

1. **松耦合的核心**：依赖抽象而非具体实现，通过依赖注入和事件驱动消除直接依赖
2. **通信方式选择**：优先用 Prism 事件聚合器和共享服务，命令用 MediatR，跨设备用 MQTT
3. **工业软件第一原则**：稳定性优先，选择成熟、简单、易维护的方案，而不是最先进的方案
