# 999999009-33_NLog 日志分级完整实现指南

日志分级是工业上位机管控日志量级、平衡性能与追溯能力的核心手段。NLog 原生支持 6 级日志体系，通过配置文件的路由规则即可灵活控制输出级别，还支持模块级粒度管控、不停机动态调整，完美适配「生产环境静默运行、排障时精准开日志」的工控需求。

下面从级别体系、配置实现、代码调用、进阶用法、最佳实践五个维度，结合线扫视觉、PLC 控制等真实场景完整说明。

------

## 一、NLog 内置日志级别体系（6 级，从低到高）

级别从低到高排序：`Trace < Debug < Info < Warn < Error < Fatal`。配置 `minlevel` 时，**等于和高于该级别的日志都会输出**，低于该级别的自动丢弃。

| 级别      | 工业场景定位                                           | 生产环境是否开启         | 典型示例                                         |
| :-------- | :----------------------------------------------------- | :----------------------- | :----------------------------------------------- |
| **Trace** | 最细粒度的追踪信息，逐步骤、逐变量                     | ❌ 完全关闭               | 算法每一步中间计算值、通信原始字节流             |
| **Debug** | 开发调试、现场排障用的细节信息                         | ❌ 默认关闭，排障临时开启 | 逐帧图像宽高、PLC 单次读写值、函数入口出口       |
| **Info**  | 关键运行节点、状态切换、流程里程碑                     | ✅ 生产默认开启           | 相机初始化成功、批次启动、参数下发完成、模式切换 |
| **Warn**  | 单次异常、阈值临近、重试成功，存在隐患但不影响当前运行 | ✅ 必须开启               | 单次取图超时、PLC 重连成功、队列长度接近警戒值   |
| **Error** | 单个功能模块失效，影响当前生产                         | ✅ 必须开启               | 相机断连、PLC 连续读写失败、算法初始化失败       |
| **Fatal** | 程序级崩溃、系统紧急停机，设备无法继续运行             | ✅ 强制开启               | 内存溢出、全局未捕获异常、触发紧急停机           |

> 核心原则：级别越高，发生频率越低、重要性越高；生产环境只保留 Info 及以上，Debug/Trace 仅在排障时按需开启。

## 二、配置实现分级：核心在 `rules` 路由规则

日志分级全部通过 `NLog.config` 里的 `<rules>` 节点配置，无需修改业务代码，支持全局统一、分模块、分级别分流等多种模式。

### 1. 全局分级：所有模块统一输出级别

最简单、最常用的方式，给所有日志设置统一的最低输出级别。

xaml:

```xaml
<rules>
  <!-- 全局默认：Info及以上输出到主日志文件 -->
  <logger name="*" minlevel="Info" writeTo="MainLog" />
  
  <!-- Error及以上单独输出到错误日志 -->
  <logger name="*" minlevel="Error" writeTo="ErrorLog" />
</rules>
```

- `name="*"`：通配符，匹配所有日志器；
- `minlevel="Info"`：只输出 Info、Warn、Error、Fatal 四级，自动丢弃 Debug、Trace；
- `writeTo`：指定输出到哪个 target（日志文件）。

### 2. 分模块分级：不同模块不同级别

工业现场排障最实用的模式：只给出问题的模块开 Debug，其他模块保持 Info，避免无关日志刷屏。

#### 实现方式：按日志器名称匹配

给不同模块创建独立名称的 Logger，配置中按名称匹配规则。

xaml:

```xaml
<rules>
  <!-- 1. PLC通信模块：临时开Debug排障，其他时候改成Info -->
  <logger name="PLC通信" minlevel="Debug" writeTo="PlcDebugLog" final="true" />

  <!-- 2. 线扫相机模块：生产环境Info级别 -->
  <logger name="线扫相机" minlevel="Info" writeTo="MainLog" />

  <!-- 3. 全局兜底：其余模块默认Info -->
  <logger name="*" minlevel="Info" writeTo="MainLog" />

  <!-- 4. 所有模块的Error都进错误日志 -->
  <logger name="*" minlevel="Error" writeTo="ErrorLog" />
</rules>
```

- `final="true"`：匹配到这条规则后，不再继续往下匹配，避免同一条日志重复输出到多个文件；
- 模块名称和代码中 `LogManager.GetLogger("模块名")` 一一对应。

#### 兼容之前的统一 LogHelper：按自定义属性过滤

如果你用的是封装好的 `LogHelper`，通过 `ScopeContext` 传入 `Module` 属性区分模块，可以用条件过滤器实现分级：

xaml:

```xaml
<logger name="*" minlevel="Debug" writeTo="DebugLog">
  <filters>
    <!-- 只有PLC通信模块的Debug才输出，其余模块Debug全部忽略 -->
    <when condition="equals('${event-properties:item=Module}', 'PLC通信')" action="Log"/>
    <when condition="level < LogLevel.Info" action="Ignore"/>
  </filters>
</logger>
```

### 3. 按级别分流：不同级别输出到不同文件

工业场景标配：运行日志和错误日志物理分离，出问题第一时间打开错误文件，不用在百万行运行日志里翻找。

xaml:

```xaml
<rules>
  <!-- Info~Warn 进主运行日志 -->
  <logger name="*" minlevel="Info" maxlevel="Warn" writeTo="MainLog" />
  
  <!-- Error~Fatal 进专属错误日志 -->
  <logger name="*" minlevel="Error" writeTo="ErrorLog" />
</rules>
```

- `maxlevel`：设置最高输出级别，和 `minlevel` 配合可以限定级别区间。

### 4. 精细过滤：只输出 / 排除指定级别

如果需要更精准的控制，可以使用级别过滤器：

xaml:

```xaml
<logger name="*" writeTo="WarnOnlyLog">
  <filter type="log4net.Filter.LevelMatchFilter" level="Warn" />
  <filter type="log4net.Filter.DenyAllFilter" />
</logger>
```

## 三、代码中输出不同级别的日志

### 1. 基础调用方法

NLog 的 `Logger` 对象原生提供 6 个级别的写入方法，直接调用即可：

csharp:

```c#
private static readonly Logger _logger = LogManager.GetLogger("线扫相机");

// 调试信息
_logger.Debug("新一帧采集完成，宽{0} 高{1}", width, height);

// 关键节点
_logger.Info("相机初始化成功，分辨率4096*2048");

// 警告
_logger.Warn("单次取图超时，超时阈值500ms");

// 错误（必须带完整异常）
_logger.Error(ex, "取图回调处理异常");

// 致命错误
_logger.Fatal(ex, "程序全局异常，紧急停机");
```

> 重要规范：`Error` 和 `Fatal` 级别必须传入完整的 `Exception` 对象，NLog 会自动输出完整堆栈，不要只打印 `ex.Message`。

### 2. 对应统一封装的 LogHelper

和你之前封装的日志工具类完全对应，每个级别一个方法，强制传入模块名：

csharp:

```c#
public static class LogHelper
{
    private static readonly Logger _logger = LogManager.GetCurrentClassLogger();

    private static void PushModule(string module)
        => ScopeContext.PushProperty("Module", module);

    public static void Debug(string module, string msg)
    {
        PushModule(module);
        _logger.Debug(msg);
    }

    public static void Info(string module, string msg)
    {
        PushModule(module);
        _logger.Info(msg);
    }

    public static void Warn(string module, string msg)
    {
        PushModule(module);
        _logger.Warn(msg);
    }

    public static void Error(string module, string msg, Exception ex = null)
    {
        PushModule(module);
        if (ex == null) _logger.Error(msg);
        else _logger.Error(ex, msg);
    }

    public static void Fatal(string module, string msg, Exception ex)
    {
        PushModule(module);
        _logger.Fatal(ex, msg);
    }
}
```

### 3. 高频场景性能优化：先判断级别再输出

相机回调、PLC 轮询等高频路径，字符串拼接、插值会产生临时对象和 GC 开销。如果生产环境关闭了 Debug 级别，这些拼接就是纯浪费。

**优化写法：先判断级别是否启用，再做格式化**

csharp:

```c#
// 线扫相机回调中，逐帧日志优化
if (_logger.IsDebugEnabled)
{
    // 只有Debug启用时，才执行字符串插值
    LogHelper.Debug("线扫相机", $"新一帧 宽{img.Width} 高{img.Height}");
}
```

生产环境 Debug 关闭时，里面的代码完全不会执行，零性能开销，是高帧率场景的必做优化。

## 四、工业场景进阶：不停机动态调整日志级别

这是 NLog 对标 Log4Net 的核心优势之一，也是量产线排障的刚需。

### 实现原理

配置根节点开启 `autoReload="true"` 后，NLog 会监听配置文件变化，修改后 10 秒内自动生效，无需重启程序、不中断生产。

### 操作步骤

1. 配置文件开启热重载：

xaml:

```xaml
<nlog autoReload="true">
```

1. 现场需要排查 PLC 通信问题时，打开 `NLog.config`，把 PLC 模块的 `minlevel` 从 `Info` 改成 `Debug`，保存；
2. 等待几秒，PLC 模块的 Debug 日志自动开始输出，抓完问题改回 `Info` 即可；
3. 全程无需重启设备、不影响正常生产，完美适配量产线不能随意停机的要求。

## 五、工业上位机分级最佳实践

1. **生产环境默认 Info 级别**

   只保留关键节点和异常告警，既保证可追溯性，又控制日志量级、降低性能开销。

2. **高频路径严格降级**

   相机采集回调、PLC 周期轮询、算法循环等高频执行路径，**逐次信息只能打 Debug**，绝对禁止打 Info，避免生产环境日志刷屏、磁盘爆满。

3. **错误日志独立归档**

   所有模块的 Error/Fatal 单独输出到错误文件，排查问题第一时间打开该文件，定位效率提升 10 倍。

4. **排障用模块级 Debug，不要全局开**

   全局开 Debug 会产生海量无关日志，既占磁盘又难找重点；只给出问题的模块开 Debug，精准定位，信噪比最高。

5. **异常必须用 Error/Fatal，且传完整异常对象**

   禁止用 Info/Warn 记录异常，禁止只打印异常消息不打堆栈，否则故障排查等于无从下手。

6. **审计操作固定用 Info**

   参数修改、模式切换、人工复位等操作审计日志，统一用 Info 级别，保证生产环境永久留存，满足合规要求。

## 六、常见避坑点

1. ❌ **搞反级别顺序**

   Fatal 是最高级（最严重），Trace 是最低级（最详细）。`minlevel="Debug"` 会输出 Debug 及以上所有级别，不是只输出 Debug。

2. ❌ **高频循环打 Info**

   100fps 相机回调每帧打 Info，一天几百万条日志，既占磁盘又无价值，逐帧细节必须用 Debug。

3. ❌ **异常只打 Message**

   `_logger.Error("出错了：" + ex.Message)` 等于白打，必须传入完整 Exception 对象，自动输出堆栈。

4. ❌ **配置修改不生效**

   检查 `NLog.config` 是否设置了「复制到输出目录」；开启 `autoReload` 才支持热更新。

5. ❌ **忘记判断级别就拼接字符串**

   生产环境 Debug 关闭时，复杂的字符串插值依然会执行，产生不必要的 GC 和 CPU 开销，高频场景必须加 `IsDebugEnabled` 判断。
