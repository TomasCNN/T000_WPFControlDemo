# 999999009-10_.NET 主流日志框架配置完整指南（工业 / WPF 场景适配）

NET 生态日志框架的配置分为**代码式配置**和**配置文件式配置**两类。工业场景推荐采用「核心性能配置硬编码 + 可调级别放配置文件」的混合模式：异步写入、文件滚动、磁盘兜底等关键策略写死在代码中，避免现场误改；日志级别、输出开关等放配置文件，支持热更新排查问题。

以下针对 Serilog、NLog、log4net 三大主流框架，结合工业上位机 / WPF 的性能与可靠性要求，给出可直接复用的标准配置与最佳实践。

------

## 一、Serilog 配置（工业场景首选）

Serilog 以**链式代码 API** 为核心配置方式，也支持 `appsettings.json` 文件配置，原生支持结构化日志与异步写入，语法简洁、低 GC、高性能，是现代 .NET 工业软件的首选框架。

### 1. 必装 NuGet 包

| 包名                                     | 作用                         |
| :--------------------------------------- | :--------------------------- |
| `Serilog`                                | 核心框架                     |
| `Serilog.Sinks.File`                     | 本地文件输出                 |
| `Serilog.Sinks.Async`                    | 异步队列写入（工业场景必装） |
| `Serilog.Extensions.DependencyInjection` | WPF MVVM 依赖注入集成        |

### 2. 核心工业级配置项

| 配置项                   | 作用                   | 工业推荐值                            |
| :----------------------- | :--------------------- | :------------------------------------ |
| `MinimumLevel`           | 全局最低输出级别       | 生产环境 `Information`                |
| `MinimumLevel.Override`  | 按命名空间单独设置级别 | 采集 / 通信模块设为 `Warning`/`Error` |
| `WriteTo.Async`          | 启用内存队列异步写入   | **必须开启**，业务线程零阻塞          |
| `rollingInterval`        | 文件滚动周期           | `Day` 按天滚动                        |
| `retainedFileCountLimit` | 保留文件数量上限       | 30（普通日志保留 30 天）              |
| `fileSizeLimitBytes`     | 单文件大小上限         | 100MB                                 |
| `flushToDiskInterval`    | 批量刷盘间隔           | 1 秒                                  |
| `blockWhenFull`          | 队列满时是否阻塞业务   | `false`，宁可丢日志绝不拖垮主业务     |

### 3. 完整工业级代码配置示例

WPF 上位机标准配置，包含异步写入、分级输出、高频模块提级、自动滚动清理、磁盘兜底，可直接复制到 `App.xaml.cs` 启动入口：

csharp:

```c#
using Serilog;
using Serilog.Events;

protected override void OnStartup(StartupEventArgs e)
{
    base.OnStartup(e);

    Log.Logger = new LoggerConfiguration()
        // 1. 全局级别：生产默认只输出Info及以上
        .MinimumLevel.Information()
        // 2. 高频模块单独提级，稳态运行零日志
        .MinimumLevel.Override("PlcDataCollection", LogEventLevel.Warning)
        .MinimumLevel.Override("DeviceCommunication", LogEventLevel.Warning)
        .MinimumLevel.Override("ImageProcessing", LogEventLevel.Warning)
        // 3. 富集业务上下文：附加工位、设备标识
        .Enrich.FromLogContext()
        .Enrich.WithProperty("StationId", "SMT-LINE01")
        .Enrich.WithProperty("DeviceId", "PLC-A01")

        // 4. 主运行日志：异步写入，按天滚动，自动清理
        .WriteTo.Async(a => a.File(
            path: "logs/app-.log",
            rollingInterval: RollingInterval.Day,
            retainedFileCountLimit: 30,
            fileSizeLimitBytes: 100 * 1024 * 1024, // 单文件最大100MB
            flushToDiskInterval: TimeSpan.FromSeconds(1),
            outputTemplate: "{Timestamp:yyyy-MM-dd HH:mm:ss.fff} [{Level:u3}] {Message:lj}{NewLine}{Exception}"),
            bufferSize: 10000,    // 内存队列最大长度
            blockWhenFull: false) // 队列满直接丢弃低级日志，绝不阻塞业务

        // 5. 错误日志单独归档：只存Error及以上，保留90天
        .WriteTo.Async(a => a.File(
            path: "logs/error-.log",
            rollingInterval: RollingInterval.Day,
            retainedFileCountLimit: 90,
            restrictedToMinimumLevel: LogEventLevel.Error))

        // 6. 开发环境输出到VS调试窗口，生产环境自动移除
#if DEBUG
        .WriteTo.Debug()
#endif
        .CreateLogger();

    // 程序退出时强制刷盘，避免丢日志
    AppDomain.CurrentDomain.ProcessExit += (s, args) => Log.CloseAndFlush();
}
```

### 4. 配置文件方式（appsettings.json）

适合需要动态调整级别的现场场景，需安装 `Serilog.Settings.Configuration`：

json:

```json
{
  "Serilog": {
    "MinimumLevel": {
      "Default": "Information",
      "Override": {
        "PlcDataCollection": "Warning",
        "DeviceCommunication": "Warning"
      }
    },
    "WriteTo": [
      {
        "Name": "Async",
        "Args": {
          "configure": [
            {
              "Name": "File",
              "Args": {
                "path": "logs/app-.log",
                "rollingInterval": "Day",
                "retainedFileCountLimit": 30
              }
            }
          ]
        }
      }
    ]
  }
}
```

### 5. 常见配置坑点

- **忘记开异步**：默认 `File` Sink 是同步写入，UI 线程调用会直接造成界面卡顿，必须用 `WriteTo.Async` 包裹。
- **`blockWhenFull` 设为 true**：队列满时阻塞业务线程，违背工业场景「主业务优先」的核心原则。
- **生产环境保留控制台输出**：WPF 默认无控制台窗口，开启后不仅无作用还会增加额外开销，生产环境务必移除。

## 二、NLog 配置

NLog 以 **XML 配置文件（NLog.config）** 为主要配置方式，路由规则灵活、目标类型丰富，适合需要复杂日志分发、多目标输出的传统工业项目。

### 1. 必装 NuGet 包

| 包名                      | 作用         |
| :------------------------ | :----------- |
| `NLog`                    | 核心框架     |
| `NLog.Extensions.Logging` | 依赖注入集成 |

### 2. 核心工业级配置项

| 配置项                   | 作用             | 工业推荐值                   |
| :----------------------- | :--------------- | :--------------------------- |
| `<targets async="true">` | 全局启用异步目标 | **必须开启**，自动队列化写入 |
| `archiveAboveSize`       | 单文件归档阈值   | 104857600（100MB）           |
| `maxArchiveFiles`        | 最大归档文件数   | 30                           |
| `archiveEvery`           | 按时间归档周期   | `Day` 按天                   |
| `rules` 节点             | 日志路由分流规则 | 按模块、级别分流到不同文件   |
| `autoReload`             | 配置修改自动生效 | `true`，支持现场热更         |

### 3. 完整工业级 NLog.config 示例

xaml:

```xaml
<?xml version="1.0" encoding="utf-8" ?>
<nlog xmlns="http://www.nlog-project.org/schemas/NLog.xsd"
      xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
      autoReload="true"
      throwConfigExceptions="false"
      internalLogLevel="Off">

  <targets async="true"> <!-- 全局异步：所有目标走后台线程队列 -->
    <!-- 1. 主运行日志 -->
    <target xsi:type="File"
            name="MainFile"
            fileName="${basedir}/logs/app-${shortdate}.log"
            archiveFileName="${basedir}/logs/archive/app-{#}.log"
            archiveEvery="Day"
            archiveAboveSize="104857600"
            maxArchiveFiles="30"
            layout="${longdate}|${level:uppercase=true}|${logger}|${message}${newline}${exception:format=ToString}"/>

    <!-- 2. 错误专属日志：只记录Error及以上 -->
    <target xsi:type="File"
            name="ErrorFile"
            fileName="${basedir}/logs/error-${shortdate}.log"
            archiveEvery="Day"
            maxArchiveFiles="90"
            layout="${longdate}|${level}|${logger}|${message}${newline}${exception:format=ToString}"/>

    <!-- 3. 通信模块单独日志：保留7天 -->
    <target xsi:type="File"
            name="CommFile"
            fileName="${basedir}/logs/comm-${shortdate}.log"
            archiveAboveSize="52428800"
            maxArchiveFiles="7"
            layout="${longdate}|${message}"/>
  </targets>

  <rules>
    <!-- 路由规则：从上到下匹配，final表示匹配后不再继续 -->
    <logger name="PlcDataCollection.*" minlevel="Warning" writeTo="CommFile" final="true" />
    <logger name="DeviceCommunication.*" minlevel="Warning" writeTo="CommFile" final="true" />
    
    <!-- 错误级别同步写入错误日志 -->
    <logger name="*" minlevel="Error" writeTo="ErrorFile" />
    
    <!-- 全局主日志兜底 -->
    <logger name="*" minlevel="Info" writeTo="MainFile" />
  </rules>
</nlog>
```

> 注意：NLog.config 文件属性需设置为「复制到输出目录：较新则复制」，否则运行时无法加载配置。

### 4. 代码初始化

csharp:

```c#
// WPF 启动时加载配置
NLog.LogManager.LoadConfiguration("NLog.config");
var logger = NLog.LogManager.GetCurrentClassLogger();
```

### 5. 常见配置坑点

- **遗漏 `async="true"`**：默认 target 是同步写入，多线程并发下全局锁竞争严重，高频场景性能骤降。
- **遗漏 `final="true"`**：路由规则默认向下穿透，不加 final 会导致同一条日志重复写入多个目标。
- **开启内部日志**：`internalLogLevel` 设为 Info/Debug 会产生额外的框架自身日志，生产环境必须关闭。

## 三、log4net 配置（遗产项目兼容）

log4net 是经典老牌框架，纯 XML 配置，原生无异步能力，仅用于 .NET Framework 老项目维护，不推荐新项目使用。

### 1. 核心工业级配置项

- `RollingFileAppender`：滚动文件输出核心
- `rollingStyle="Composite"`：日期 + 大小复合滚动模式
- `BufferingForwardingAppender`：缓冲批量写入，模拟异步效果，是 log4net 性能优化的核心
- `MinimalLock`：最小文件锁，提升并发写入性能

### 2. 完整配置示例（App.config）

xaml:

```xaml
<configSections>
  <section name="log4net" type="log4net.Config.Log4NetConfigurationSectionHandler, log4net"/>
</configSections>

<log4net>
  <!-- 缓冲转发器：批量攒100条再写入，大幅减少IO次数 -->
  <appender name="BufferingAppender" type="log4net.Appender.BufferingForwardingAppender">
    <bufferSize value="100"/>
    <appender-ref ref="RollingFileAppender"/>
  </appender>

  <!-- 主滚动文件输出 -->
  <appender name="RollingFileAppender" type="log4net.Appender.RollingFileAppender">
    <file value="Logs/app.log"/>
    <appendToFile value="true"/>
    <rollingStyle value="Composite"/>
    <datePattern value="yyyyMMdd"/>
    <maxSizeRollBackups value="30"/>
    <maximumFileSize value="100MB"/>
    <staticLogFileName value="true"/>
    <!-- 最小锁定模型，降低多线程锁竞争 -->
    <lockingModel type="log4net.Appender.FileAppender+MinimalLock"/>
    
    <layout type="log4net.Layout.PatternLayout">
      <conversionPattern value="%date{yyyy-MM-dd HH:mm:ss.fff} [%level] %message%newline%exception"/>
    </layout>
  </appender>

  <!-- 错误日志单独输出 -->
  <appender name="ErrorAppender" type="log4net.Appender.RollingFileAppender">
    <file value="Logs/error.log"/>
    <filter type="log4net.Filter.LevelRangeFilter">
      <levelMin value="ERROR"/>
      <levelMax value="FATAL"/>
    </filter>
    <rollingStyle value="Composite"/>
    <maxSizeRollBackups value="90"/>
    <maximumFileSize value="100MB"/>
    <layout type="log4net.Layout.PatternLayout">
      <conversionPattern value="%date{yyyy-MM-dd HH:mm:ss.fff} [%level] %message%newline%exception"/>
    </layout>
  </appender>

  <root>
    <level value="INFO"/>
    <appender-ref ref="BufferingAppender"/>
    <appender-ref ref="ErrorAppender"/>
  </root>
</log4net>
```

### 3. 代码初始化

csharp:

```c#
// 启动时加载配置
log4net.Config.XmlConfigurator.Configure();
var logger = log4net.LogManager.GetLogger(typeof(App));
```

### 4. 常见配置坑点

- **不加缓冲器**：原生同步写入 + 全局独占锁，高并发下性能极差，必须搭配 `BufferingForwardingAppender`。
- **默认独占锁**：多进程写入场景会报错，需改用 `MinimalLock` 锁定模型。

## 四、Microsoft.Extensions.Logging 统一抽象配置

现代 WPF MVVM 项目推荐基于 `Microsoft.Extensions.Logging`（MEL）抽象层开发，业务代码只依赖 `ILogger<T>` 接口，不耦合具体日志框架，未来更换方案无需修改业务代码。

### WPF 集成 Serilog 完整步骤

1. 安装核心依赖包：
   - `Microsoft.Extensions.Hosting`
   - `Serilog.Extensions.Hosting`
2. `App.xaml.cs` 中配置宿主与日志

csharp:

```c#
public partial class App : Application
{
    private IHost _host;

    protected override void OnStartup(StartupEventArgs e)
    {
        base.OnStartup(e);

        // 初始化 Serilog
        Log.Logger = new LoggerConfiguration()
            .MinimumLevel.Information()
            .MinimumLevel.Override("PlcDataCollection", Serilog.Events.LogEventLevel.Warning)
            .WriteTo.Async(a => a.File("logs/app-.log", rollingInterval: RollingInterval.Day))
            .CreateLogger();

        // 构建通用宿主，注册服务与日志
        _host = Host.CreateDefaultBuilder(e.Args)
            .UseSerilog() // 接入 Serilog 实现
            .ConfigureServices((context, services) =>
            {
                // 注册业务服务、ViewModel
                services.AddSingleton<MainViewModel>();
                services.AddSingleton<IPlcService, PlcService>();
            })
            .Build();

        // 启动主窗口
        var mainVm = _host.Services.GetRequiredService<MainViewModel>();
        new MainWindow { DataContext = mainVm }.Show();
    }

    protected override void OnExit(ExitEventArgs e)
    {
        _host.Dispose();
        Log.CloseAndFlush();
        base.OnExit(e);
    }
}
```

1. ViewModel 中通过构造函数注入使用

csharp:

```c#
public class MainViewModel
{
    private readonly ILogger<MainViewModel> _logger;

    public MainViewModel(ILogger<MainViewModel> logger)
    {
        _logger = logger;
        _logger.LogInformation("主界面初始化完成，工位：{Station}", "SMT-01");
    }
}
```

## 五、工业场景配置通用原则

1. **异步必开**：所有文件输出必须走异步队列，绝对不能在 UI 线程、采集线程执行同步日志 IO。
2. **分级分流**：主运行日志、错误日志、通信日志分文件输出，设置不同保留周期，兼顾排障与磁盘成本。
3. **高频提级**：PLC 采集、图像处理等高频率模块，生产环境默认只输出 Warning 及以上，稳态零日志。
4. **磁盘兜底**：设置单文件大小上限、总保留数量；异步队列满时优先丢弃低级日志，绝不阻塞主业务。
5. **动静分离**：异步、滚动、刷盘等性能关键配置硬编码，避免现场误改；日志级别、开关放配置文件，支持热更新排查。

## 六、配置验证方法

配置完成后快速验证是否符合预期：

1. **异步验证**：UI 线程循环写入 1000 条日志，界面无卡顿则异步生效。
2. **滚动验证**：临时调小单文件阈值（如 1MB），验证自动拆分与旧文件清理是否正常。
3. **分级验证**：分别写入 Debug/Info/Error 各一条，检查是否按规则分流到对应文件。
4. **异常验证**：手动抛出异常，确认错误日志完整记录堆栈，且不影响主程序运行。
