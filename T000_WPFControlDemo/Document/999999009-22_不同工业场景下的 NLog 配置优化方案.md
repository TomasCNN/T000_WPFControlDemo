# 999999009-22_不同工业场景下的 NLog 配置优化方案

工业场景优化 NLog 的核心原则是：**先定优先级，再配参数**—— 不存在万能最优配置，只有匹配场景诉求的配置。所有工业场景本质都是在「实时性、可靠性、追溯性」三者之间做平衡，不同工位的优先级天差地别，配置策略完全不同。

下面针对工控最常见的 5 类典型场景，分别给出核心诉求、优化要点和可直接复用的配置片段，贴合你常用的线扫视觉、PLC 控制、量产追溯等真实工况。

------

## 场景一：高速视觉采集场景（线扫 / 面阵相机、高帧率取图）

### 适用场景

线扫相机取图回调、高速面阵抓拍、实时图像传输，帧率几十到上百帧每秒，对应你当前优化取图 CT 的场景。

### 核心优先级

**实时性 > 性能 > 日志完整性**

宁可丢几条日志，绝对不能拉高取图 CT、不能造成相机丢帧。

### 核心痛点

回调内同步写日志会产生毫秒级 IO 阻塞，直接拉高取图 CT；高频逐帧日志容易刷爆内存队列。

### 优化配置要点

1. **强制全局异步写入**，溢出策略设为 `Discard`（丢弃），绝对不能用 `Block`，否则队列满了会直接卡住采集线程。
2. 调大 `batchSize`（100~200），攒够一批再批量写盘，大幅减少磁盘 IO 次数。
3. **高频逐帧日志全部降级为 Debug 级别**，生产环境默认关闭，零性能开销；只保留错误、异常日志。
4. **简化日志布局，禁用 `${callsite}` 等反射类渲染器**：获取调用栈的开销是普通日志的几十倍，高频场景下会显著拉高 CT，生产环境绝对禁用，排障时再临时开启。
5. 开启 `keepFileOpen="true"`，长期持有文件句柄，避免频繁开闭文件的额外开销。
6. 队列容量适中（5000 条左右），防止异常疯狂刷屏撑爆内存。

### 参考配置片段

xaml:

```xaml
<targets async="true"
         queueLimit="5000"
         overflowAction="Discard"
         batchSize="200"
         timeToSleepBetweenBatches="1">

  <target xsi:type="File"
          name="CameraLog"
          fileName="D:/Logs/camera-${shortdate}.log"
          archiveEvery="Day"
          maxArchiveDays="30"
          keepFileOpen="true"
          concurrentWrites="false"
          encoding="utf-8">
    <!-- 极简布局：去掉所有高开销字段，只保留核心信息 -->
    <layout>${longdate} | ${level:uppercase=true} | 线程${threadid} | ${message} ${exception:format=ToString}</layout>
  </target>
</targets>
```

## 场景二：实时控制与 PLC 通信场景（运动控制、IO 交互）

### 适用场景

PLC 轮询读写、运动轴控制、传感器信号采集、实时逻辑控制，对时序稳定性要求高。

### 核心优先级

**控制线程不阻塞 > 错误日志不丢失 > 普通日志完整性**

### 核心痛点

控制线程对延迟敏感，普通通信日志量大但价值低，错误 / 告警日志必须完整留痕，用于故障追责和定位。

### 优化配置要点

1. 控制线程的日志全部走异步，普通单次读写日志降级为 Debug，生产环境不输出。
2. **错误日志单独归档**，保留更长时间（90 天），排查问题直接打开错误文件，不用在百万行运行日志里翻找。
3. 通信日志强制带上下文字段：寄存器地址、写入值、错误码、重试次数，无需抓包就能定位通信问题。
4. 可单独为 PLC 模块配置独立异步队列，和相机日志物理隔离，避免高优先级的控制日志被视觉日志挤压。
5. 日志级别按失败次数升级：单次失败打 Warn，连续 3 次失败打 Error，减少无效告警刷屏。

### 参考配置片段

xaml:

```xaml
<targets async="true" queueLimit="3000" overflowAction="Discard">
  <!-- PLC通信运行日志 -->
  <target xsi:type="File" name="PlcLog"
          fileName="D:/Logs/plc-${shortdate}.log"
          archiveEvery="Day" maxArchiveDays="30"
          keepFileOpen="true" encoding="utf-8">
    <layout>${longdate} | ${level} | ${message}</layout>
  </target>

  <!-- 错误专属日志：所有模块的Error/Fatal都进这里，保留90天 -->
  <target xsi:type="File" name="ErrorLog"
          fileName="D:/Logs/error-${shortdate}.log"
          archiveEvery="Day" maxArchiveDays="90"
          keepFileOpen="true" encoding="utf-8">
    <layout>${longdate} | ${level} | ${event-properties:item=Module} | ${message}
${exception:format=ToString,StackTrace:maxInnerExceptionLevel=5}
=========================================================================</layout>
  </target>
</targets>

<rules>
  <logger name="*" minlevel="Info" writeTo="PlcLog" />
  <logger name="*" minlevel="Error" writeTo="ErrorLog" />
</rules>
```

## 场景三：量产追溯与合规审计场景（批量生产、操作留痕）

### 适用场景

量产线检测工位、医药 / 食品合规工位、参数修改留痕、产品全链路追溯，需要满足审计要求。

### 核心优先级

**日志完整可追溯 > 合规不可篡改 > 性能**

### 核心痛点

需要关联批次号、产品 SN、操作人，日志需要长期保存，历史记录不能被随意修改删除。

### 优化配置要点

1. **单独拆分「操作审计日志」文件**，只记录：参数修改、模式切换、批次启停、人工复位，和运行日志物理隔离，专门用于合规审计。
2. 使用 `ScopeContext` 全局透传业务上下文：批次号、工号、产品型号，不用每条日志手动拼接字符串，自动关联到所有日志。
3. 归档保留周期拉长（180 天 / 1 年，按合规要求），采用**按天 + 按大小双重切割**，防止单日日志过大。
4. 日志文件配合 NTFS 权限设为「仅追加」，禁止修改、删除历史日志，满足防篡改要求。
5. 可输出 CSV/JSON 结构化格式，方便后续导入追溯系统做数据分析。

### 参考配置与代码

#### 配置片段

xaml:

```xaml
<target xsi:type="File" name="AuditLog"
        fileName="D:/Logs/audit/audit-${shortdate}.log"
        archiveEvery="Day"
        maxArchiveDays="180"
        keepFileOpen="true"
        encoding="utf-8">
  <!-- 审计日志固定格式：时间 | 操作人 | 批次 | 操作内容 | 结果 -->
  <layout>${longdate} | ${event-properties:item=Operator} | ${event-properties:item=BatchNo} | ${message}</layout>
</target>
```

#### 业务代码注入上下文

csharp:

```c#
// 批次开始时全局注入，后续所有日志自动带批次号
ScopeContext.PushProperty("BatchNo", "B2026062301");
ScopeContext.PushProperty("Operator", "OP001");

// 审计日志调用
LogHelper.Info("操作审计", "修改检测阈值：旧值0.85 → 新值0.90，修改成功");
```

## 场景四：7×24 小时无人值守场景（黑灯产线、无人工作站）

### 适用场景

无人值守检测站、夜班自动产线、连续运行不关机的设备，现场无运维人员。

### 核心优先级

**磁盘不爆满 > 内存不泄漏 > 稳定运行 > 日志完整**

### 核心痛点

长期运行日志越积越多，极易占满磁盘导致程序崩溃；内存泄漏、句柄泄漏会让程序越跑越慢。

### 优化配置要点

1. **双重切割机制**：按自然天切割 + 单文件超大小强制切割（如 100MB），防止单日异常刷屏写爆单个文件、瞬间占满磁盘。
2. **双重过期清理**：`maxArchiveDays`（按天数删） + `maxArchiveFiles`（按数量删）双保险，自动清理过期日志。
3. 异步队列严格限流，溢出直接丢弃，优先保证主程序不崩溃，绝不本末倒置。
4. NLog 自身内部日志设为 `Warn` 级别，只有自身故障才记录，避免自身日志无限膨胀。
5. 设置 `openFileCacheTimeout`，长时间无日志自动释放文件句柄，适配低流量的夜间运行场景。
6. 可配合业务层磁盘空间监控：剩余空间不足 10% 时自动清理最旧日志，做最后一道兜底。

### 参考配置片段

xaml:

```xaml
<target xsi:type="File"
        name="MainLog"
        fileName="D:/Logs/app-${shortdate}.log"
        archiveEvery="Day"         <!-- 按天切割 -->
        archiveAboveSize="104857600" <!-- 单文件超100MB也切割 -->
        archiveNumbering="DateAndSequence"
        maxArchiveDays="30"        <!-- 超过30天自动删 -->
        maxArchiveFiles="100"      <!-- 最多保留100个文件兜底 -->
        keepFileOpen="true"
        openFileCacheTimeout="3600" <!-- 1小时无日志自动释放句柄 -->
        encoding="utf-8">
  <layout>...</layout>
</target>
```

> 注意：`archiveAboveSize` 的单位是**字节**，100MB = 100 × 1024 × 1024 = 104857600。

## 场景五：现场排障与调试场景（故障排查、临时调试）

### 适用场景

现场出问题，需要开启 Debug 日志定位，但不能重启程序（重启后故障可能消失）。

### 核心优先级

**灵活可控 > 精准过滤 > 不影响生产**

### 核心痛点

全量开启 Debug 日志会疯狂刷屏，找不到重点；很多故障重启程序就无法复现，必须热更新配置。

### 优化配置要点

1. 开启 `autoReload="true"`，修改配置文件后自动生效，无需重启设备，不中断生产。
2. **支持模块级粒度控制**：只给指定模块开 Debug（如只开 PLC 通信，相机模块保持 Info），避免无关日志刷屏。
3. 单独的调试日志文件，不污染主运行日志，排障结束后可直接删除。
4. 可配置条件过滤器：只打印指定批次、指定错误码、指定工位的日志，精准过滤。
5. 排障结束后改回 Info 级别，自动生效，不影响设备正常运行。

### 参考配置片段（仅 PLC 模块开 Debug）

xaml:

```xaml
<rules>
  <!-- 全局默认Info级别 -->
  <logger name="*" minlevel="Info" writeTo="MainLog" />
  
  <!-- 单独给PLC通信模块开Debug，排障专用 -->
  <logger name="*" minlevel="Debug" writeTo="DebugLog">
    <filters>
      <when condition="equals('${event-properties:item=Module}', 'PLC通信')" action="Log"/>
      <when condition="level < LogLevel.Info" action="Ignore"/>
    </filters>
  </logger>
</rules>
```

## 全场景通用优化项（所有工业场景都建议做）

1. **日志路径统一放非系统盘**：比如 `D:/Logs/`，避免系统崩溃重装后日志丢失，也不会被程序更新覆盖。
2. **统一 UTF-8 编码**：防止工控机英文 / 繁体系统下中文乱码。
3. **程序退出强制刷盘**：全局异常、程序退出时调用 `LogManager.Shutdown()`，把内存队列里的日志全部落地，保留完整故障现场。
4. **关闭并发写入**：单进程写日志设 `concurrentWrites="false"`，去掉并发锁开销，提升写入性能。
5. **内部日志级别设为 Warn**：`internalLogLevel="Warn"`，只有 NLog 自身出问题才记录，减少额外开销。

## 工业场景避坑红线（绝对不能做）

1. ❌ **绝对不要为了 “不丢日志” 用同步写入**：实时线程同步写盘，CT 飙升、相机丢帧、控制超时，得不偿失。
2. ❌ **不要在高频循环里打 Info 级日志**：100fps 每秒 100 条，一天几百万条，既占磁盘又没实际价值。
3. ❌ **不要滥用 `${callsite}`**：反射获取调用栈开销极大，生产环境禁用，排障时临时开启即可。
4. ❌ **不要只按数量限制，不按天数清理**：`maxArchiveFiles`只能限制总数，`maxArchiveDays`才能按时间自动过期。
5. ❌ **不要把所有日志塞一个文件**：运行、错误、审计拆分存放，排查效率差十倍。
6. ❌ **不要把日志放 C 盘 / 程序目录**：系统崩溃后日志全丢，程序更新时容易被覆盖。

## 视觉检测工位组合方案推荐

结合你的线扫相机 + PLC 控制的视觉检测场景，推荐最终组合配置：

1. 全局异步写入，队列溢出丢弃，优先保证采集 CT 稳定；
2. 主运行日志：Info 级别，按天切割，保留 30 天；
3. 错误专属日志：单独归档，保留 90 天，快速定位故障；
4. 操作审计日志：单独文件，记录参数修改、批次切换，保留 180 天；
5. 相机逐帧日志：Debug 级别，生产默认关闭，排障时临时开启；
6. 开启 `autoReload="true"`，现场排障无需重启程序。
