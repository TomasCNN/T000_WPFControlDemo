# 999999006-27_C# 特性（Attribute）实现结构化注释全解析

C# 中的**特性（Attribute）** 不是普通的文本注释（`//`、`///`），而是一种**可编译、可反射读取的结构化元数据**。你可以把它理解为「贴在代码上的结构化标签 / 注释」：既能说明代码的用途、属性，还能被框架、工具在运行时自动识别和调用。

你之前代码里的 `[DisplayName]`、`[Station]`、`[AddINotifyPropertyChangedInterface]` 都属于这类「带逻辑的注释」。

------

## 一、核心概念区分

很多人会把特性和普通注释混淆，二者本质不同：

| 维度       | 普通注释（`//`、`///`）  | 特性（Attribute）                    |
| :--------- | :----------------------- | :----------------------------------- |
| 编译后     | 完全消失，不会进入程序集 | 保留在程序集元数据中，永久存在       |
| 运行时读取 | 无法被代码读取           | 可以通过反射动态读取，驱动业务逻辑   |
| 结构化     | 纯文本，无格式约束       | 强类型，可带多个属性、多种数据类型   |
| 核心用途   | 给开发人员看的代码说明   | 给框架、工具、业务逻辑用的结构化标注 |

简单说：**普通注释是写给人看的，特性是写给程序 / 框架看的「结构化注释」**。工业上位机里的工位标注、配置项说明、UI 自动生成都大量依赖特性。

------

## 二、.NET 内置注释类特性（开箱即用）

.NET 基类库自带了一批专门用于「描述、标注」的特性，WPF 属性面板、PropertyGrid 控件、自动生成 UI 的框架都会自动读取这些特性显示，是最常用的 “特性注释”。

### 1. `DisplayNameAttribute`：友好显示名称

**作用**：给类、属性、方法起一个对外展示的中文名 / 友好名，UI 界面、属性编辑器会自动显示这个名称，替代生硬的英文属性名。

**示例（结合你的工位配置类）**：

csharp:

```c#
using System.ComponentModel;

[DisplayName("焊接引导工位参数")]
public class StationWeldingGuideOption
{
    [DisplayName("心跳寄存器地址")]
    public string Heartbeat { get; set; } = "D200";

    [DisplayName("曝光时间默认值")]
    public short DefaultExposure { get; set; } = 1000;
}
```

- 效果：在属性网格、配置界面中，不会显示 `Heartbeat` 这个英文，而是直接显示「心跳寄存器地址」。
- 你之前代码里 `[DisplayName("对位激光引导测量工位")]` 就是这个用法，给工位类加中文名称，UI 工位列表自动读取展示。

### 2. `DescriptionAttribute`：详细描述

**作用**：补充更详细的说明文字，通常用于鼠标悬停提示、属性详情说明，比 `DisplayName` 信息更丰富。

**示例**：

csharp:

```c#
[DisplayName("心跳寄存器地址")]
[Description("与PLC心跳通信的D寄存器地址，上位机周期写入数值，PLC检测判断上位机是否在线")]
public string Heartbeat { get; set; } = "D200";
```

- 效果：属性编辑器中鼠标悬停在属性上，会弹出这段详细说明。

### 3. `CategoryAttribute`：分类分组

**作用**：给属性按业务类别分组，在属性网格中按分类折叠显示，适合配置项很多的场景。

**示例**：

csharp:

```c#
public class StationWeldingGuideOption
{
    [Category("通信参数"), DisplayName("心跳地址")]
    public string Heartbeat { get; set; } = "D200";

    [Category("视觉参数"), DisplayName("引导相机曝光")]
    public short GuideExposure { get; set; } = 1200;

    [Category("视觉参数"), DisplayName("3D相机精度")]
    public double Camera3DPrecision { get; set; } = 0.01;
}
```

- 效果：属性面板里会自动分成「通信参数」「视觉参数」两个分组，结构清晰。

### 4. `BrowsableAttribute`：控制可见性

**作用**：标记某个属性是否在属性浏览器中显示，`false` 表示隐藏，相当于「内部使用，不对外展示」。

**示例**：

csharp:

```c#
// 内部调试用，不在配置界面显示
[Browsable(false)]
public bool DebugMode { get; set; }
```

### 5. `ReadOnlyAttribute`：标记只读

**作用**：标记属性在编辑器中是否只读，防止用户误修改。

**示例**：

csharp:

```c#
// 设备序列号，只读不可修改
[ReadOnly(true), DisplayName("设备序列号")]
public string DeviceSN { get; private set; }
```

### 6. `ObsoleteAttribute`：过时标记

**作用**：标记代码已废弃，编译时自动弹出警告 / 错误，是「带编译检查的注释」，比普通注释靠谱得多。

**示例**：

csharp:

```c#
[Obsolete("该方法已废弃，请使用 WriteBarcodeNew 替代", false)]
public void WriteBarcode(string barcode)
{
    // 旧逻辑
}
```

- 第二个参数 `false` 表示编译警告，`true` 表示编译错误（强制不让用）。
- 效果：其他人调用这个方法时，VS 会直接标波浪线提示，避免误用旧代码。

## 三、自定义特性：实现自己的结构化注释

当内置特性不够用时，你可以自己定义特性类，承载任意自定义的元数据。你代码里的 `[Station]` 就是典型的自定义特性，用来保存工位的模式、视图类型、算法类型等信息。

### 1. 定义自定义特性

规则：

- 类名以 `Attribute` 结尾（约定俗成）；
- 继承 `System.Attribute`；
- 用 `[AttributeUsage]` 限制特性的应用范围（只能贴在类上？还是属性、方法都可以？）。

**示例：模拟你代码里的工位特性**

csharp:

```c#
using System;

/// <summary>
/// 工位元数据特性：标记类为一个工位，自动注册到框架
/// </summary>
[AttributeUsage(AttributeTargets.Class, AllowMultiple = false, Inherited = false)]
public class StationAttribute : Attribute
{
    /// <summary>工位模式：主机/从机</summary>
    public StationMode Mode { get; set; }

    /// <summary>结果视图类型</summary>
    public Type ResultType { get; set; }

    /// <summary>算法参数视图类型</summary>
    public Type AlgType { get; set; }
}

public enum StationMode
{
    Host,   // 主机模式
    Slave   // 从机模式
}
```

- `AttributeTargets.Class`：只能贴在类上面；
- `AllowMultiple = false`：一个类只能贴一次这个特性；
- `Inherited = false`：子类不会继承这个特性。

### 2. 使用自定义特性

和你代码里的用法完全一致，直接贴在目标代码上：

csharp:

```c#
[DisplayName("对位激光引导测量工位")]
[Station(Mode = StationMode.Host, ResultType = typeof(IStationTakeFitView), AlgType = typeof(IStationAlgorithmView))]
public class WeldingGuide : PCHStationBase<StationWeldingGuideOption>, IStationWeldingGuide
{
    // 工位业务逻辑
}
```

### 3. 反射读取特性（框架的核心用法）

特性之所以比普通注释强，就是因为可以在运行时通过反射读出来，驱动业务逻辑。比如你的工位框架，启动时会扫描所有类，找到带 `[Station]` 特性的类，自动注册到系统里。

**读取示例**：

csharp:

```c#
using System.Reflection;

// 扫描当前程序集中所有带 Station 特性的工位类
var stationTypes = Assembly.GetExecutingAssembly().GetTypes()
    .Where(t => t.IsClass && !t.IsAbstract)
    .Where(t => t.GetCustomAttribute<StationAttribute>() != null);

foreach (var type in stationTypes)
{
    var stationAttr = type.GetCustomAttribute<StationAttribute>();
    var displayName = type.GetCustomAttribute<DisplayNameAttribute>()?.DisplayName ?? type.Name;

    Console.WriteLine($"发现工位：{displayName}，模式：{stationAttr.Mode}");
    // 自动实例化、注册工位、关联视图...
}
```

这就是你框架里「写个类贴个特性，工位就自动生效」的底层原理 ——**特性 + 反射自动发现**，不用手动写注册代码。

## 四、工业场景常用的特性注释场景

结合你做的激光焊接上位机，这些是最典型的用法：

1. **配置项标注**

   用 `DisplayName`、`Description`、`Category` 标记所有配置参数，配置界面可以自动生成，不用手写每个控件的绑定。

2. **工位 / 设备自动注册**

   用自定义 `[Station]`、`[Device]` 特性标记工位、设备类，框架启动时自动扫描注册，插件化扩展。

3. **权限控制**

   给方法、功能加 `[RequiresPermission("管理员")]` 特性，AOP 框架自动校验权限。

4. **数据校验**

   给属性加 `[Range(1, 10000)]`、`[Required]` 等数据注解特性，自动校验参数合法性。

5. **日志埋点**

   给方法加 `[LogAction("修改曝光参数")]` 特性，自动记录操作日志。

------

## 五、总结

1. **普通注释**是给人看的，纯文本，编译后消失，适合代码内部说明；
2. **特性**是结构化的元数据，编译后保留，可被反射读取，既能当 “注释” 说明代码，还能驱动框架逻辑；
3. 简单的显示、描述、分类用 .NET 内置的 `DisplayName`、`Description`、`Category` 即可；
4. 业务自定义的标注（比如工位、设备、权限），可以继承 `Attribute` 自定义特性类，配合反射实现自动发现、自动配置。
