# 999999009-16_工业上位机日志：用法规则 + 实现方式 + 实战案例

工业上位机的日志和普通软件日志定位完全不同：它不是 “开发调试工具”，而是**设备故障追溯、生产问题审计、性能瓶颈排查的核心依据**，要求低开销、不影响实时性、可追溯、不占满磁盘。下面结合你常用的相机采集、PLC 通信、生产流程场景，完整讲清规则、用法和可直接复用的案例。

------

## 一、上位机日志的核心作用

1. **故障定位**：设备异常时，通过日志快速区分是相机断连、PLC 通信失败、算法报错还是逻辑 bug，不用现场复现也能排查。
2. **生产追溯**：产品出现质量问题时，回溯对应时刻的设备参数、采集状态、报警记录，满足工业生产的审计要求。
3. **性能分析**：记录取图 CT、算法耗时、通信延迟，定位卡顿瓶颈，对应你之前优化相机取图 CT 的需求。
4. **操作留痕**：参数修改、手动启停、复位报警等操作全部记录，避免误操作后无法追溯。

------

## 二、日志分级规则（工业标准五级）

核心原则：**不同级别各司其职，生产环境关闭低级日志，既保证信息完整，又不刷爆磁盘、不拖慢程序**。

| 级别              | 触发场景                                             | 生产环境是否开启 | 典型例子                                                 |
| :---------------- | :--------------------------------------------------- | :--------------- | :------------------------------------------------------- |
| **Fatal（致命）** | 程序崩溃、硬件紧急停止、系统级故障，设备无法继续运行 | ✅ 必须开         | 程序未处理异常崩溃、相机触发紧急停机                     |
| **Error（错误）** | 功能模块失效，影响正常生产，单功能不可用             | ✅ 必须开         | 相机断连、PLC 读写持续失败、取图连续超时、算法初始化失败 |
| **Warn（警告）**  | 单次异常、参数临近阈值，不影响当前运行，但存在隐患   | ✅ 必须开         | 单次取图超时、温度接近上限、PLC 重连成功、缓存队列积压   |
| **Info（信息）**  | 正常运行的关键节点、状态切换，记录设备运行轨迹       | ✅ 建议开         | 相机打开成功、开始 / 结束生产、批次切换、参数下发完成    |
| **Debug（调试）** | 开发调试用的细节信息，变量值、中间步骤、逐帧数据     | ❌ 生产关闭       | 每帧图像宽高、算法中间结果、PLC 单次读写的原始数据       |

> 工业现场铁律：**高频循环内绝对不能打 Info 及以上日志**。比如相机 100fps 的回调里，不能每帧都打 Info，否则每秒 100 条日志，磁盘 IO 直接拉满，程序必卡。

## 三、日志内容与格式规范

### 1. 标准日志格式（工业通用）

plaintext:

```tex
时间(精确到毫秒) | 日志级别 | 线程ID | 模块名 | 描述信息 | [异常堆栈]
```

示例：

plaintext:

```tex
2026-06-23 14:25:30.125 | INFO  | 线程12 | 线扫相机 | 相机打开成功，分辨率4096*2048
2026-06-23 14:25:31.456 | ERROR | 线程12 | 线扫相机 | 取图异常
   System.OutOfMemoryException: 内存不足
   at ImageHelper.FastCopyOpencvToBmp()
```

### 2. 每条日志的必填要素

- **精确到毫秒的时间戳**：工业设备故障排查需要精确到毫秒级时序，区分先后顺序。
- **模块名称**：区分是相机、PLC、算法、MES 通信哪个模块出的问题，避免一锅粥。
- **具体可定位的描述**：禁止只写 “出错了”，要写 “线扫相机取图超时，超时时间 500ms”。
- **错误必带完整堆栈**：Error/Fatal 级必须输出完整 Exception，只打错误消息等于没打。

### 3. 禁止记录的内容

- 禁止记录敏感生产数据、配方参数（防泄密）；
- 禁止打印整张图像的像素数据、超大字节数组；
- 禁止在日志里输出密码、权限密钥等敏感信息。

## 四、工业上位机日志核心使用规则（红线不能碰）

### 1. 实时线程绝对禁止同步写日志

相机采集回调、PLC 实时控制线程、算法处理线程，都是高优先级实时线程。

- 同步写文件会产生几毫秒到几十毫秒的随机 IO 阻塞，直接导致相机丢帧、控制超时；
- 强制规则：**实时线程只提交日志消息，落地写文件全部交给后台异步线程**。

> 对应你之前的相机回调：回调里打日志必须是异步的，不能同步写文件，否则优化的 CT 全被日志耗没了。

### 2. 自动切割 + 自动过期清理，杜绝磁盘占满

工业设备 7×24 小时运行，日志不清理迟早占满磁盘，导致程序崩溃。

- 按天切割日志文件，每天生成一个新文件；
- 自动删除 30 天前的旧日志（可根据磁盘大小调整）；
- 单文件超过限制大小（比如 100MB）也自动切割。

### 3. 生产环境默认关闭 Debug 日志

Debug 日志量大、细节多，开发时用，生产环境必须可配置关闭，避免刷爆磁盘、拉高 CPU。

### 4. 异常不能静默吞掉

catch 捕获异常后，不能只 return null，必须记录异常日志，否则出了问题完全无从排查。

### 5. 关键操作强制留痕

参数修改、手动复位、切换自动 / 手动、启停设备，必须记录 “谁、什么时候、做了什么操作、修改前 / 后值”，满足可审计要求。

## 五、两种主流实现方式

### 方案 1：工业标配 —— NLog 框架（推荐项目使用）

NLog 是工业上位机最常用的日志框架，原生支持异步、自动切割、自动清理、多目标输出，配置即用，不用自己造轮子。

#### 步骤 1：安装 NuGet 包

plaintext:

```tex
Install-Package NLog
```

#### 步骤 2：配置文件 NLog.config（复制到输出目录）

xaml:

```xaml
<?xml version="1.0" encoding="utf-8" ?>
<nlog xmlns="http://www.nlog-project.org/schemas/NLog.xsd"
      xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
      autoReload="true">

  <targets async="true"> <!-- 全局异步，所有日志不阻塞业务线程 -->
    <!-- 主日志文件：按天切割，保留30天 -->
    <target xsi:type="File" 
            name="mainFile"
            fileName="logs/app-${shortdate}.log"
            layout="${longdate}|${level:uppercase=true}|${threadid}|${logger}|${message} ${exception:format=tostring}"
            archiveEvery="Day"
            maxArchiveFiles="30"
            archiveNumbering="Sequence"/>

    <!-- 错误单独存一个文件，排查问题直接看error日志 -->
    <target xsi:type="File" 
            name="errorFile"
            fileName="logs/error-${shortdate}.log"
            layout="${longdate}|${level:uppercase=true}|${threadid}|${logger}|${message} ${exception:format=tostring}">
      <filters>
        <when condition="level &lt;= Warn" action="Ignore"/>
      </filters>
    </target>
  </targets>

  <rules>
    <!-- 生产环境设为Info，调试设为Debug -->
    <logger name="*" minlevel="Info" writeTo="mainFile" />
    <logger name="*" minlevel="Error" writeTo="errorFile" />
  </rules>
</nlog>
```

#### 步骤 3：封装全局日志工具类

csharp:

```c#
using NLog;

public static class LogHelper
{
    private static readonly Logger _logger = LogManager.GetCurrentClassLogger();

    // 调试信息：开发用，生产关闭
    public static void Debug(string module, string msg) 
        => _logger.Debug($"[{module}] {msg}");

    // 正常节点：设备运行关键状态
    public static void Info(string module, string msg) 
        => _logger.Info($"[{module}] {msg}");

    // 警告：单次异常、隐患
    public static void Warn(string module, string msg) 
        => _logger.Warn($"[{module}] {msg}");

    // 错误：功能失效，带异常堆栈
    public static void Error(string module, string msg, Exception ex = null)
    {
        if (ex == null) _logger.Error($"[{module}] {msg}");
        else _logger.Error(ex, $"[{module}] {msg}");
    }

    // 致命错误：程序级崩溃
    public static void Fatal(string module, string msg, Exception ex)
        => _logger.Fatal(ex, $"[{module}] {msg}");
}
```

### 方案 2：轻量自研 —— 异步队列日志（无第三方依赖）

不想引入 NuGet 依赖、追求极致轻量，可以用`BlockingCollection`实现异步队列日志，回调提交消息微秒级，完全不阻塞实时线程。

核心代码：

csharp:

```c#
using System.Collections.Concurrent;
using System.IO;

public static class AppLog
{
    // 异步队列：回调只往里扔消息，立刻返回
    private static readonly BlockingCollection<string> _logQueue = new BlockingCollection<string>(2000);
    private static readonly Thread _writeThread;
    private static readonly string _logDir = Path.Combine(AppDomain.CurrentDomain.BaseDirectory, "logs");

    static AppLog()
    {
        if (!Directory.Exists(_logDir))
            Directory.CreateDirectory(_logDir);

        // 后台低优先级线程专门写文件，不抢业务CPU
        _writeThread = new Thread(WriteLoop)
        {
            IsBackground = true,
            Priority = ThreadPriority.BelowNormal
        };
        _writeThread.Start();
    }

    // 后台循环写文件
    private static void WriteLoop()
    {
        string todayFile = Path.Combine(_logDir, $"{DateTime.Now:yyyy-MM-dd}.log");
        using var sw = new StreamWriter(todayFile, true);
        sw.AutoFlush = true;

        foreach (var msg in _logQueue.GetConsumingEnumerable())
        {
            try
            {
                // 跨天自动切文件
                if (DateTime.Now.Date != File.GetCreationTime(todayFile).Date)
                {
                    sw.Close();
                    todayFile = Path.Combine(_logDir, $"{DateTime.Now:yyyy-MM-dd}.log");
                    sw.BaseStream.SetLength(0);
                }
                sw.WriteLine(msg);
            }
            catch { /* 写日志失败不影响主程序 */ }
        }
    }

    // 格式化日志
    private static string BuildLog(string level, string module, string msg, Exception ex = null)
    {
        string time = DateTime.Now.ToString("yyyy-MM-dd HH:mm:ss.fff");
        int threadId = Thread.CurrentThread.ManagedThreadId;
        string log = $"{time} | {level,5} | 线程{threadId} | {module} | {msg}";
        if (ex != null) log += $"\n{ex}";
        return log;
    }

    // 对外接口：仅入队，微秒级返回，不阻塞
    public static void Info(string module, string msg)
        => _logQueue.Add(BuildLog("INFO", module, msg));

    public static void Warn(string module, string msg)
        => _logQueue.Add(BuildLog("WARN", module, msg));

    public static void Error(string module, string msg, Exception ex = null)
        => _logQueue.Add(BuildLog("ERROR", module, msg, ex));
}
```

```c#
private static void LineScanCCD_OnResultDataGrab(OpencvImage opencvImage)
{
    try
    {
        if (!LineScanCCD.IsOpen())
        {
            // 错误日志：带模块、带描述
            LogHelper.Error("线扫相机", "取图回调触发但相机未打开");
            return;
        }

        using (Bitmap bitmap = FromOpencvImage(opencvImage))
        {
            lock (_imageLock)
            {
                LineScanImage?.Dispose();
                LineScanImage = (Bitmap)bitmap.Clone();
            }
            _imageReadyEvent.Set();
        }

        // Debug级：开发调试看帧频，生产环境自动关闭，不影响性能
        LogHelper.Debug("线扫相机", $"新一帧采集完成，宽{opencvImage.Width} 高{opencvImage.Height}");
    }
    catch (Exception ex)
    {
        // 异常必带堆栈
        LogHelper.Error("线扫相机", "相机取图异常", ex);
    }
    finally
    {
        DestoryOpencvImage(opencvImage);
    }
}
```

## 七、常见避坑点

1. **不要在高频循环里打 Info**：比如 100fps 的相机回调，每帧打 Info，一天就是几百万条，直接把磁盘写满。
2. **不要大量拼接字符串**：回调里拼复杂字符串会产生 GC，造成 CT 尖刺，简单信息直接打，复杂统计降级到 Debug。
3. **日志不要存 C 盘**：工控机系统崩溃时，C 盘日志可能拿不到，建议存在 D 盘专门的日志目录。
4. **异常不要只打 Message**：只打 “参数无效” 等于没打，必须输出完整堆栈才能定位到具体哪行代码出错。
5. **队列要有上限**：异步队列不能无限增长，程序卡死疯狂打日志时，队列满了直接丢弃，不能把内存撑爆。
