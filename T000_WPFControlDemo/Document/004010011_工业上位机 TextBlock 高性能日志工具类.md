# 004010011_工业上位机 TextBlock 高性能日志工具类

## 问题 1：如何使用这个工具类？

### 问题核心诉求

如果需要**零坑、可直接复制到生产环境的完整落地流程**，包括项目结构集成、初始化规范、多场景使用模式、MVVM 适配以及工业开发中最常见的坑点排查。

### 逐点解析与实战步骤

#### 1. 第一步：项目集成（1 分钟完成）

1. 在你的 WPF 项目中新建`Controls`文件夹（工业项目标准结构，用于存放自定义控件和工具类）

2. 将工具类代码保存为`TextBlockLogExtensions.cs`，复制到`Controls`文件夹

3. 添加命名空间引用：

   xaml:

   ```xaml
   <!-- XAML页面顶部引用 -->
   xmlns:controls="clr-namespace:YourProjectName.Controls"
   ```

   csharp:

   ```c#
   // C#后台代码引用
   using YourProjectName.Controls;
   ```

#### 2. 第二步：基础单页面使用（工业项目最常用）

**XAML 布局（必须严格遵循，否则自动滚动不生效）**：

xaml:

```xaml
<!-- 日志区域标准布局 -->
<Border BorderBrush="#DDDDDD" 
        BorderThickness="1" 
        CornerRadius="4" 
        Background="#F5F5F5" 
        Margin="10">
    <!-- 必须：TextBlock的直接父控件只能是ScrollViewer -->
    <ScrollViewer VerticalScrollBarVisibility="Auto" 
                  HorizontalScrollBarVisibility="Disabled"
                  MaxHeight="400">
        <TextBlock x:Name="txtLog"
                   FontFamily="Consolas"  <!-- 工业日志标准等宽字体 -->
                   FontSize="12"
                   LineHeight="18"       <!-- 1.5倍行高，提升可读性 -->
                   Padding="10"
                   <!-- 工业级渲染优化，必加 -->
                   UseLayoutRounding="True"
                   SnapsToDevicePixels="True"
                   RenderOptions.ClearTypeHint="Enabled"
                   TextOptions.TextFormattingMode="Display"/>
    </ScrollViewer>
</Border>
```

**后台初始化（页面构造函数中调用，且只调用一次）**：

csharp:

```c#
public MainWindow()
{
    InitializeComponent();

    // 工业项目生产环境推荐配置
    txtLog.InitLog(
        maxLines: 1500,          // 最多保留1500行（约50MB内存）
        updateIntervalMs: 150,   // 150ms更新一次UI（平衡实时性和性能）
        autoScroll: true,        // 自动滚动到底部
        showTimestamp: true,     // 显示毫秒级时间戳（工业日志必备）
        showThreadId: false,     // 生产环境关闭，减少日志长度
        logFileBasePath: "Logs", // 日志自动保存到程序目录下的Logs文件夹
        maxFileSizeMB: 100,      // 单个日志文件最大100MB，超过自动分割
        maxRetainDays: 7);       // 自动删除7天前的旧日志
}
```

**添加日志（支持任意后台线程直接调用，无需 Dispatcher）**：

csharp:

```c#
// 模拟PLC后台数据采集线程
private void StartPlcDataCollection()
{
    Task.Run(() =>
    {
        int count = 0;
        while (true)
        {
            count++;
            
            // 不同级别日志，自动显示不同颜色
            txtLog.AddInfo($"设备运行正常，当前计数：{count}");
            
            if (count % 10 == 0)
                txtLog.AddWarning("温度接近上限：78.5℃");
            
            if (count % 50 == 0)
                txtLog.AddError("PLC通信超时，正在重试第1次...");

            Task.Delay(50).Wait(); // 每秒20条日志，工业典型频率
        }
    });
}
```

#### 3. 第三步：多页面全局共享日志

工业项目通常有多个页面需要显示同一个日志流（如主界面日志、调试页面日志），使用全局广播机制：

csharp:

```c#
// App.xaml.cs中设置全局日志级别
public partial class App : Application
{
    protected override void OnStartup(StartupEventArgs e)
    {
        base.OnStartup(e);
        // 生产环境只显示Info及以上级别，过滤Debug日志
        TextBlockLogExtensions.GlobalMinimumLevel = LogLevel.Info;
    }
}

// 页面1：订阅全局日志
public Page1()
{
    InitializeComponent();
    txtLogPage1.InitLog();
    txtLogPage1.SubscribeGlobalLog(); // 订阅所有全局广播的日志
}

// 页面2：订阅全局日志
public Page2()
{
    InitializeComponent();
    txtLogPage2.InitLog();
    txtLogPage2.SubscribeGlobalLog();
}

// 任意地方广播日志（所有订阅页面都会收到）
TextBlockLogExtensions.BroadcastLog(LogLevel.Info, "系统启动成功");
TextBlockLogExtensions.BroadcastLog(LogLevel.Error, "电机过载报警");
```

#### 4. 第四步：MVVM 模式适配（工业项目标准）

不要在 ViewModel 中直接操作 TextBlock 控件，通过事件解耦：

csharp:

```c#
// 1. ViewModel中定义日志请求事件
public class MainViewModel
{
    public event Action<LogLevel, string> LogRequested;

    private void PlcConnectionSuccess()
    {
        // 业务逻辑中只触发事件，不关心UI实现
        LogRequested?.Invoke(LogLevel.Info, "PLC连接成功，IP：192.168.1.100");
    }

    private void TemperatureAlarm(double temp)
    {
        LogRequested?.Invoke(LogLevel.Warning, $"温度超过预警值：{temp:F1}℃");
    }
}

// 2. View中订阅并显示日志
public MainWindow()
{
    InitializeComponent();
    var vm = new MainViewModel();
    DataContext = vm;

    txtLog.InitLog();
    // 订阅ViewModel的日志事件
    vm.LogRequested += txtLog.AddLog;
}
```

#### 5. 常见坑与解决方案

| 问题                 | 根本原因                    | 解决方案                                                     |
| :------------------- | :-------------------------- | :----------------------------------------------------------- |
| 自动滚动不生效       | 工具类找不到父 ScrollViewer | 确保 TextBlock 的**直接父控件**是 ScrollViewer，中间不能有其他容器 |
| 后台线程添加日志报错 | 直接操作 UI 线程控件        | 工具类已内置线程安全，无需额外调用 Dispatcher.Invoke         |
| 页面关闭后内存泄漏   | 未注销事件订阅              | 工具类已内置 TextBlock 卸载事件监听，自动清理资源，无需手动处理 |
| 日志文件乱码         | 编码不统一                  | 工具类已默认使用 UTF-8 编码，无需修改                        |

## 问题 3：这个工具类的适用场景有哪些？

### 问题核心诉求

明确工具类的**边界和定位**，知道什么时候用它，什么时候不能用它，避免用错场景导致性能问题或功能不足。

### 一、核心适用场景（工业上位机 90% 的日志需求）

#### 1. 设备运行实时日志

- **场景描述**：显示 PLC、传感器、电机等设备的实时运行状态、数据采集值
- **特点**：更新频率高（每秒 1-100 条）、数据量大、需要实时显示
- **优势**：高吞吐量、低 CPU 占用、自动滚动、自动持久化

#### 2. 报警与事件日志

- **场景描述**：显示设备报警、故障、状态变化等事件信息
- **特点**：不同级别不同颜色、需要时间戳、需要永久保存
- **优势**：五级日志分级、自动颜色显示、自动文件持久化

#### 3. 操作日志

- **场景描述**：记录用户的所有操作（登录、参数修改、手动控制等）
- **特点**：需要记录操作人、操作时间、操作内容
- **优势**：线程安全、支持后台线程记录、自动保存到文件

#### 4. 调试与诊断日志

- **场景描述**：开发和调试阶段显示详细的调试信息
- **特点**：信息量大、级别多、需要灵活过滤
- **优势**：全局日志级别过滤、支持 Debug 级别、可随时开启关闭

#### 5. 通信日志

- **场景描述**：显示 PLC、串口、以太网等通信接口的收发数据
- **特点**：更新频率极高（每秒几十到上百条）、需要显示原始字节
- **优势**：极高吞吐量、低延迟、不阻塞通信线程

### 二、不适用场景（及替代方案）

#### 1. 需要文本选择和复制功能

- **不适用原因**：TextBlock 原生不支持文本选择
- **替代方案**：使用`RichTextBox`或第三方可选择 TextBlock 控件

#### 2. 超过 5000 行的历史日志查询

- **不适用原因**：TextBlock 没有虚拟化，超过 5000 行后性能急剧下降
- **替代方案**：使用`DataGrid`+ 虚拟化或`FlowDocumentScrollViewer`

#### 3. 需要复杂的富文本格式

- **不适用原因**：TextBlock 只支持简单的内联元素，不支持表格、图片、复杂排版
- **替代方案**：使用`RichTextBox`或`FlowDocument`

#### 4. 需要日志搜索、过滤、导出功能

- **不适用原因**：本工具类专注于实时显示，没有内置搜索过滤功能
- **替代方案**：结合 Log4Net/NLog 等日志框架，使用第三方日志查看控件

### 三、与其他日志方案的对比

| 方案                         | 优点                                   | 缺点                            | 适用场景                 |
| :--------------------------- | :------------------------------------- | :------------------------------ | :----------------------- |
| 本工具类                     | 性能极高、线程安全、自动持久化、零依赖 | 不支持文本选择、无搜索过滤      | 实时日志显示、工业上位机 |
| RichTextBox                  | 支持富文本、文本选择                   | 性能极差，每秒超过 100 条就卡顿 | 历史日志查看、富文本显示 |
| Log4Net/NLog                 | 功能强大、配置灵活                     | 没有内置 UI 显示，需要自己实现  | 后台日志记录、文件持久化 |
| 第三方日志控件（如 MahApps） | 功能全面、支持搜索过滤                 | 依赖多、性能一般                | 桌面应用通用日志         |
| Console.WriteLine            | 最简单                                 | 没有 UI 显示、无法持久化        | 控制台调试               |

### 四、工业项目选型建议

1. **实时日志显示**：优先使用本工具类，性能最好，最稳定
2. **后台日志记录**：结合 Log4Net/NLog，本工具类负责 UI 显示，Log4Net 负责文件持久化
3. **历史日志查询**：使用`DataGrid`+ 虚拟化，从数据库或日志文件中加载
4. **调试日志**：使用本工具类，开发阶段开启 Debug 级别，生产阶段关闭
5. **报警日志**：使用本工具类 + 数据库，重要报警同时写入数据库
