# 999999009-20_NLog 实现工业上位机异步日志完整指南

工业上位机的核心诉求是**日志写盘绝对不能阻塞相机回调、PLC 控制等实时线程，不能拉高 CT、不能造成丢帧**。NLog 原生支持异步写入，配置极简、对业务代码零侵入，是工控场景的最优方案。

下面从原理、配置、参数优化、避坑四个维度，给出适配工业 7×24 小时运行的完整落地方案。

------

## 一、先搞懂：异步写入为什么不阻塞业务线程

### 同步写日志的问题

同步模式下，你调用 `LogHelper.Error()` 时，当前线程会**当场执行打开文件、写磁盘、关闭文件**的完整 IO 操作。

- 机械硬盘单次写入耗时几毫秒到几十毫秒不等；
- 高帧率相机回调里每帧打日志，CT 会直接被拉高十几毫秒，造成相机丢帧、控制超时；
- 这也是我们反复强调「回调里不能同步写日志」的根本原因。

### 异步写日志的核心逻辑

NLog 异步模式本质是**生产者 - 消费者队列模型**：

1. **业务线程（生产者）**：调用日志方法时，只是把日志消息扔进内存队列，立刻返回，耗时微秒级，完全不碰磁盘 IO；
2. **后台专属线程（消费者）**：NLog 自动启动一个低优先级后台线程，批量从队列里取消息，统一写入文件；
3. **全程解耦**：写磁盘的快慢完全不影响业务线程，哪怕磁盘卡一下，也只会积压在队列里，不会卡住相机采集。

> 大白话总结：同步是「你自己跑下楼扔垃圾」，会耽误你干活；异步是「你把垃圾放门口，保洁阿姨统一收走」，你放下就可以继续工作，完全不耽误时间。

------

## 二、最简实现：全局异步（工业首选，一行配置搞定）

这是最推荐、最省事的方式：给所有日志目标统一开启异步，业务代码一行都不用改，自动全部升级为异步写入。

### 核心改动

在 `NLog.config` 里，给 `<targets>` 节点加上 `async="true"` 属性即可：

xaml:

```xaml
<!-- 加上 async="true"，内部所有target自动变成异步写入 -->
<targets async="true">
  <!-- 你的各种日志目标，原封不动放这里 -->
  <target xsi:type="File" name="MainLog" ... />
  <target xsi:type="File" name="ErrorLog" ... />
</targets>
```

**原理**：加上这个属性后，NLog 会自动给每个 target 外面包一层 `AsyncWrapper` 异步包装器，自动创建队列和后台写线程，对上层调用完全透明。

### 单目标异步（灵活按需开启）

如果只想给部分日志开异步、其他保持同步，可以单独给某个 target 包 `AsyncWrapper`：

xaml:

```xaml
<targets>
  <!-- 单独给主日志开异步 -->
  <target xsi:type="AsyncWrapper" name="AsyncMainLog"
          queueLimit="5000" overflowAction="Discard">
    <target xsi:type="File" name="MainLog" ... />
  </target>

  <!-- 错误日志保持同步（极端情况不丢错误，工业不推荐，仅举例） -->
  <target xsi:type="File" name="ErrorLog" ... />
</targets>
```

> 工业场景建议：**直接全局异步**，统一管控，避免遗漏。错误日志也走异步，只要队列容量合理，不会丢失。

## 三、工业场景关键参数详解（必须按场景调优）

异步不是开了就完事，队列容量、溢出策略、批量写入策略，直接决定了「会不会影响主程序」「会不会丢日志」「性能够不够高」。

所有参数都加在 `<targets>` 节点上（全局异步），或 `<target xsi:type="AsyncWrapper">` 节点上（单目标异步）。

| 参数                        | 作用                               | 工业推荐值                  | 说明                                                         |
| :-------------------------- | :--------------------------------- | :-------------------------- | :----------------------------------------------------------- |
| `queueLimit`                | 内存队列最大容纳条数               | `5000`                      | 队列满了之后触发溢出策略。不能设无限大，否则异常疯狂刷屏会把内存撑爆。 |
| `overflowAction`            | 队列满了之后的处理策略             | **`Discard`（丢弃新日志）** | 工业场景铁律：必须设为丢弃，绝对不能设 `Block`。`Block` 会让业务线程卡住等待队列空闲，等于变回同步，白做异步了。 |
| `batchSize`                 | 后台线程一次批量写入的条数         | `100`                       | 攒够 N 条再一次性写盘，减少磁盘 IO 次数，提升性能。数值越大写入效率越高，但实时性略差。 |
| `timeToSleepBetweenBatches` | 两次批量写入之间的休眠时间（毫秒） | `1`                         | 平衡 CPU 占用和日志实时性。设 1ms 既不会空转占 CPU，也能保证日志近乎实时落地。 |
| `autoFlush`                 | 每条日志写完是否立刻刷盘           | `false`                     | 异步模式下关闭，靠批量刷盘提升性能；异常场景由 NLog 兜底。   |

### 推荐配置示例（全局异步 + 工业级参数）

xaml:

```xaml
<targets async="true"
         queueLimit="5000"
         overflowAction="Discard"
         batchSize="100"
         timeToSleepBetweenBatches="1">
  <!-- 日志目标 -->
</targets>
```

> 核心原则：**永远优先保证主程序稳定，其次才是日志完整性**。极端情况下宁可丢几条日志，也绝不能让日志阻塞生产线程。

## 四、完整工业级异步配置文件（可直接复制使用）

这份配置包含：全局异步、按天切割、自动清理 30 天、错误单独归档、工业标准格式，直接替换你的 `NLog.config` 即可。

xaml:

```xaml
<?xml version="1.0" encoding="utf-8" ?>
<nlog xmlns="http://www.nlog-project.org/schemas/NLog.xsd"
      xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
      autoReload="true"
      internalLogLevel="Warn"
      internalLogFile="D:/Logs/nlog-internal.log">

  <!-- ========== 核心：全局异步 + 工业级参数 ========== -->
  <targets async="true"
           queueLimit="5000"
           overflowAction="Discard"
           batchSize="100"
           timeToSleepBetweenBatches="1">

    <!-- 1. 主运行日志 -->
    <target xsi:type="File"
            name="MainLog"
            fileName="D:/Logs/app-${shortdate}.log"
            archiveEvery="Day"
            maxArchiveDays="30"
            keepFileOpen="true"
            concurrentWrites="false"
            encoding="utf-8">
      <layout>${longdate} | ${level:uppercase=true:padding=-5} | 线程${threadid} | ${event-properties:item=Module:padding=-8} | ${message} ${exception:format=ToString,StackTrace:maxInnerExceptionLevel=5}</layout>
    </target>

    <!-- 2. 错误专属日志 -->
    <target xsi:type="File"
            name="ErrorLog"
            fileName="D:/Logs/error-${shortdate}.log"
            archiveEvery="Day"
            maxArchiveDays="90"
            keepFileOpen="true"
            encoding="utf-8">
      <layout>${longdate} | ${level:uppercase=true} | 线程${threadid} | ${event-properties:item=Module} | ${message}
${exception:format=ToString,StackTrace:maxInnerExceptionLevel=5}
----------------------------------------------------------------------</layout>
    </target>

    <!-- 3. 控制台输出（开发调试用） -->
    <target xsi:type="ColoredConsole" name="ConsoleLog"
            layout="${time:format=HH\:mm\:ss.fff} | ${level:uppercase=true:padding=-5} | ${event-properties:item=Module} | ${message}" />
  </targets>

  <!-- 日志规则 -->
  <rules>
    <logger name="*" minlevel="Info" writeTo="MainLog" />
    <logger name="*" minlevel="Error" writeTo="ErrorLog" />
    <logger name="*" minlevel="Debug" writeTo="ConsoleLog" />
  </rules>
</nlog>
```

### 配套性能优化说明

- `keepFileOpen="true"`：长期持有文件句柄，不用每次写都打开 / 关闭文件，高频写入下性能提升非常明显；
- `concurrentWrites="false"`：单进程写日志，关闭并发写入支持，减少额外开销；
- `autoReload="true"`：改配置不用重启程序，生产排查问题临时开 Debug 非常方便。

## 五、业务代码怎么写（对业务完全透明）

开启异步后，**你的日志调用代码一行都不用改**，入队操作由 NLog 自动完成。原来怎么打日志，现在还怎么打。

### 相机回调场景示例（完全不阻塞）

csharp:

```c#
private static void LineScanCCD_OnResultDataGrab(OpencvImage opencvImage)
{
    try
    {
        // ... 图像转换、赋值逻辑 ...

        // 这里只是把消息扔进内存队列，耗时约0.01ms，完全不影响CT
        LogHelper.Debug("线扫相机", $"新一帧 宽{opencvImage.Width} 高{opencvImage.Height}");
    }
    catch (Exception ex)
    {
        // 错误日志同样异步入队，异常时也不会卡住回调
        LogHelper.Error("线扫相机", "取图回调异常", ex);
    }
    finally
    {
        DestoryOpencvImage(opencvImage);
    }
}
```

> 性能对比（4096×2048 线扫图回调）：
>
> - 同步写日志：单条日志增加 CT 3~15ms（磁盘波动大）；
> - 异步写日志：单条日志增加 CT <0.1ms，几乎无感知。

## 六、工业场景进阶必做优化

### 1. 程序退出 / 崩溃时强制刷盘，不丢关键日志

异步日志存在内存队列里，如果程序突然崩溃、强制结束，队列里没来得及写的日志会丢失。

- 正常退出：在程序关闭事件里调用 `LogManager.Shutdown()`，强制把队列里的日志全部刷到磁盘；
- 异常崩溃：在全局未处理异常里先刷日志，再退出。

csharp:

```c#
// 程序退出时调用
public static void ShutdownLog()
{
    LogManager.Shutdown();
}

// 全局异常处理示例
AppDomain.CurrentDomain.UnhandledException += (sender, e) =>
{
    LogHelper.Fatal("主程序", "未捕获异常，程序即将退出", e.ExceptionObject as Exception);
    LogManager.Shutdown(); // 强制刷盘，保留崩溃现场
};
```

### 2. 调用端减少字符串拼接，避免 GC 尖刺

异步只是把「写磁盘」异步了，**字符串拼接、格式化依然在业务线程执行**。

- 高频回调里不要做复杂的字符串插值、大量参数拼接；
- 逐帧细节日志放 Debug 级别，生产环境默认关闭，零开销；
- 复杂统计信息按间隔输出（如每 100 帧打一次统计），不要逐帧打。

### 3. 日志路径放非系统盘

日志统一放在 D 盘等数据分区，避免系统崩溃后日志丢失，同时不占用系统盘空间。

## 七、避坑红线（90% 的人都踩过）

### 1. 绝对不要把溢出策略设为 Block

`overflowAction="Block"` 会导致队列满时，业务线程阻塞等待，等于变回同步日志，异步白做，极端情况直接卡死设备。

- 工业场景强制 `Discard`，宁可丢日志，也不能影响生产。

### 2. 不要以为异步了就可以疯狂刷屏

100fps 回调里每帧打 Info，哪怕是异步，也会持续占用 CPU 做入队、格式化，队列也会快速积压。

- 逐帧细节只能打 Debug，生产环境关闭；
- 正常运行时保持日志输出克制，关键节点才打 Info。

### 3. 不要在异步回调里做复杂日志格式化

比如把整张图像的像素、大数组塞进日志，哪怕是异步，序列化和字符串生成也在调用线程执行，会拉高 CT、制造 GC。

### 4. 不要忘记程序退出刷盘

只开异步不关停，异常退出时最后几条关键日志会丢，故障现场就没了。

### 5. 不要频繁开关日志文件

`keepFileOpen` 一定要开，高频场景下反复开闭文件的开销比写内容还大。

------

## 八、验证异步是否真的生效

1. **耗时验证**：在相机回调里打点计时，打日志前后耗时差在 0.1ms 以内，说明是异步入队；
2. **延迟验证**：打一条日志，日志文件会有几毫秒到几十毫秒的写入延迟，不是立刻出现，说明走了批量写入；
3. **压测验证**：循环打 10000 条日志，看主线程会不会卡住，不卡就是异步生效；
4. **内部日志验证**：把 `internalLogLevel` 改成 Debug，看 NLog 内部日志有没有启动 AsyncWrapper。
