# 999999009-31_NLog 日志输出格式完整配置指南

NLog 日志格式的核心是**布局（Layout）**，通过 `${渲染器名称}` 形式的「布局渲染器」自由拼接字段，支持纯文本、JSON、CSV 等多种格式。工业上位机场景的核心诉求是：**毫秒级时间戳、模块归属清晰、异常堆栈完整、多线程可追溯、格式整齐易读**。

下面从配置方式、常用渲染器、格式化技巧、工业场景模板、进阶结构化日志五个维度完整说明，可直接复用之前的异步配置框架。

------

## 一、格式配置的两种写法

日志格式通过 `layout` 配置，写在每个 `target`（输出目标）内部，有两种常用写法：

### 1. 属性简写（简单格式）

格式简单时直接写为 `target` 的属性，代码量少：

xaml:

```xaml
<target xsi:type="File" 
        name="MainLog"
        fileName="D:/Logs/app-${shortdate}.log"
        layout="${longdate} | ${level:uppercase=true} | ${message} ${exception}" />
```

### 2. 子节点写法（复杂格式推荐）

格式字段多、需要配置参数时，用独立的 `<layout>` 子节点，可读性和可维护性更好，工业场景推荐这种：

xaml:

```xaml
<target xsi:type="File" name="MainLog" ...>
  <layout xsi:type="SimpleLayout">
    <text>${longdate} | ${level:uppercase=true:padding=-5} | 线程${threadid} | ${message} ${exception:format=ToString,StackTrace}</text>
  </layout>
</target>
```

> 说明：默认布局类型就是 `SimpleLayout`（纯文本模板），如果是 JSON、CSV 等特殊格式，需要显式指定 `xsi:type="JsonLayout"`。

## 二、工业场景核心布局渲染器

所有格式都由 `${xxx}` 渲染器拼接而成，下面按用途分类整理工控最常用的渲染器。

### 1. 时间类（故障时序追溯核心）

| 渲染器                          | 输出示例                  | 说明                                                         |
| :------------------------------ | :------------------------ | :----------------------------------------------------------- |
| `${longdate}`                   | `2026-06-23 15:30:15.678` | **工业首选**，精确到毫秒的完整时间，格式固定 `yyyy-MM-dd HH:mm:ss.fff` |
| `${shortdate}`                  | `2026-06-23`              | 仅日期，常用于文件名按天切割                                 |
| `${date:format=HH\:mm\:ss.fff}` | `15:30:15.678`            | 自定义时间格式，控制台调试常用                               |

### 2. 日志级别类

| 渲染器                    | 输出示例         | 说明                                 |
| :------------------------ | :--------------- | :----------------------------------- |
| `${level}`                | `Info` / `Error` | 原始级别名称                         |
| `${level:uppercase=true}` | `INFO` / `ERROR` | 转大写，格式更整齐                   |
| `${level:padding=-5}`     | `INFO `          | 固定宽度对齐，负数左对齐，正数右对齐 |

### 3. 线程与环境类（多线程排障必备）

| 渲染器           | 输出示例  | 说明                                             |
| :--------------- | :-------- | :----------------------------------------------- |
| `${threadid}`    | `12`      | 当前线程编号，排查并发、死锁、时序问题的核心依据 |
| `${processid}`   | `4567`    | 进程 ID，多进程场景用                            |
| `${machinename}` | `PC-ST01` | 机器名，多工位统一采集日志时区分设备             |

### 4. 消息与异常类

| 渲染器         | 说明                                       |
| :------------- | :----------------------------------------- |
| `${message}`   | 日志正文内容，也就是代码里传入的消息字符串 |
| `${exception}` | 异常信息，可配置输出格式和深度             |
| `${newline}`   | 强制换行，用于异常堆栈和正文分隔           |

**异常格式化常用参数**：

plaintext:

```tex
${exception:format=ToString,StackTrace:maxInnerExceptionLevel=5}
```

- `format=ToString`：输出完整异常对象（消息 + 类型 + 堆栈）
- `format=Message`：只输出异常消息，不输出堆栈
- `maxInnerExceptionLevel=5`：最多输出 5 层内部异常，深层嵌套异常也能完整追溯

### 5. 自定义属性类（业务上下文追溯）

通过 `${event-properties:item=属性名}` 读取代码中通过 `ScopeContext` 注入的自定义属性，是工业场景模块划分、批次追溯的核心手段。

比如代码里设置模块名和批次号：

csharp:

```c#
ScopeContext.PushProperty("Module", "线扫相机");
ScopeContext.PushProperty("BatchNo", "B2026062301");
```

配置中对应引用：

plaintext:

```tex
${event-properties:item=Module}
${event-properties:item=BatchNo}
```

> 对应你封装的 `LogHelper`，模块名就是通过这种方式自动注入，无需每条日志手动拼接。

## 三、格式化实用技巧

### 1. 固定宽度对齐，日志整齐易读

用 `padding` 参数设置固定宽度，负数左对齐，正数右对齐，让所有日志列对齐，肉眼排查更高效：

plaintext:

```tex
${level:uppercase=true:padding=-5}    // 左对齐，占5位：INFO  WARN ERROR
${threadid:padding=2}                 // 右对齐，占2位： 3 12
${event-properties:item=Module:padding=-10} // 模块名左对齐占10位
```

### 2. 异常单独换行，堆栈不挤在一行

用 `${newline}` 让异常堆栈单独换行缩进，避免和正文混在一起：

plaintext:

```tex
${message}${onexception:inner=${newline}   ${exception:format=ToString,StackTrace}}
```

效果：正文一行，异常堆栈自动换行并缩进，可读性大幅提升。

### 3. 用变量统一定义格式，多目标复用

如果多个 target 用同一种格式，可以定义变量统一管理，修改时只改一处：

xaml:

```xaml
<nlog>
  <!-- 统一定义格式变量 -->
  <variable name="StandardLayout" 
            value="${longdate} | ${level:uppercase=true:padding=-5} | 线程${threadid} | ${event-properties:item=Module:padding=-10} | ${message} ${exception:format=ToString}" />

  <targets>
    <!-- 直接引用变量 -->
    <target xsi:type="File" name="MainLog" layout="${StandardLayout}" ... />
    <target xsi:type="ColoredConsole" name="ConsoleLog" layout="${StandardLayout}" ... />
  </targets>
</nlog>
```

## 四、工业上位机常用格式模板（可直接复制）

### 1. 主运行日志标准格式（推荐）

包含时间、级别、线程 ID、模块名、消息、异常，兼顾信息密度和可读性：

xaml:

```xaml
<layout>
  <text>${longdate} | ${level:uppercase=true:padding=-5} | 线程${threadid:padding=2} | ${event-properties:item=Module:padding=-10} | ${message} ${onexception:inner=${newline}   ${exception:format=ToString,StackTrace:maxInnerExceptionLevel=3}}</text>
</layout>
```

**输出效果**：

plaintext:

```tex
2026-06-23 15:30:15.678 | INFO  | 线程12 | 线扫相机   | 相机初始化成功，分辨率4096*2048
2026-06-23 15:30:16.123 | ERROR | 线程12 | 线扫相机   | 取图回调异常
   System.NullReferenceException: 未将对象引用设置到对象的实例
   在 ImageHelper.LineScanCCD_OnResultDataGrab() 位置 D:\Project\ImageHelper.cs:第85行
```

### 2. 错误专属日志格式

加重分隔线，异常信息更完整，方便快速定位问题：

xaml:

```xaml
<layout>
  <text>${longdate} | ${level:uppercase=true} | ${event-properties:item=Module} | ${message}
${exception:format=ToString,StackTrace:maxInnerExceptionLevel=5}
------------------------------------------------------------------------</text>
</layout>
```

### 3. 操作审计日志格式

固定字段：时间、操作员、批次号、操作内容，满足合规追溯要求：

xaml:

```xaml
<layout>
  <text>${longdate} | 操作员：${event-properties:item=Operator} | 批次：${event-properties:item=BatchNo} | ${message}</text>
</layout>
```

**输出效果**：

plaintext:

```tex
2026-06-23 15:35:00.001 | 操作员：OP001 | 批次：B2026062301 | 修改缺陷检测阈值：旧值0.85 → 新值0.90，修改成功
```

### 4. 控制台调试格式

精简时间，开发调试用，不占宽度：

xaml:

```xaml
<layout>${time:format=HH\:mm\:ss.fff} | ${level:uppercase=true:padding=-5} | ${event-properties:item=Module} | ${message}</layout>
```

## 五、进阶：JSON 结构化日志格式

如果需要对接日志分析系统、ELK 集中采集，推荐使用 JSON 格式，便于程序解析检索。

### 配置示例

xaml:

```xaml
<target xsi:type="File" name="JsonLog" fileName="D:/Logs/app-json-${shortdate}.log">
  <layout xsi:type="JsonLayout"
          includeAllProperties="true"    <!-- 自动包含所有ScopeContext自定义属性 -->
          escapeUnicode="false"          <!-- 中文不转义，直接可读 -->
          suppressSpaces="true">         <!-- 压缩为单行，减小体积 -->
    <attribute name="time" layout="${longdate}" />
    <attribute name="level" layout="${level:uppercase=true}" />
    <attribute name="threadId" layout="${threadid}" />
    <attribute name="module" layout="${event-properties:item=Module}" />
    <attribute name="message" layout="${message}" />
    <attribute name="exception" layout="${exception:format=ToString}" />
  </layout>
</target>
```

**输出效果**（单行 JSON）：

json:

```json
{"time":"2026-06-23 15:30:15.678","level":"ERROR","threadId":"12","module":"线扫相机","message":"取图异常","exception":"..."}
```

## 六、工业场景注意事项

### 1. 生产环境禁用高开销渲染器

以下渲染器基于反射获取调用信息，性能开销是普通字段的几十倍，高频场景会显著拉高 CT，**仅排障时临时开启**：

- `${callsite}`：获取调用方法名 + 行号
- `${stacktrace}`：完整调用栈
- `${method}`：调用方法名

### 2. 配合编码设置避免中文乱码

日志格式里有中文时，必须在 `target` 上设置 `encoding="utf-8"`，否则工控机英文系统下会出现乱码：

xaml:

```xaml
<target xsi:type="File" name="MainLog" encoding="utf-8" ...>
```

### 3. 异常层数不要设太少

工业场景异常经常多层嵌套（比如 PLC 通信异常→内部异常→底层 Socket 异常），`maxInnerExceptionLevel` 建议设为 3~5，避免深层异常信息丢失。

### 4. 字段并非越多越好

日志字段越多，单条日志体积越大，磁盘占用越快。工业场景保留：时间、级别、线程 ID、模块、消息、异常 这 6 项核心字段即可，其余按需添加。

### 5. 分隔符统一

推荐使用 `|` 作为字段分隔符，既不影响中文阅读，也便于后续脚本、日志工具按列解析检索。
