# 999999009-36_Log4Net 完整指南

Log4Net 是 Apache 基金会旗下的 .NET 平台开源日志框架，脱胎于 Java 生态经典的 Log4j，是 .NET 领域历史最久、兼容性最强的日志组件之一，大量存量 .NET Framework 工业上位机项目均基于它构建日志体系。

------

## 一、核心定位与作用

### 1. 基本定位

Log4Net 专注于日志的分级记录、多目标输出、格式自定义与过滤管控，特点是**稳定、兼容度高、配置灵活**，但迭代速度慢，原生缺少异步写入、按天自动清理等现代日志框架的标配能力，工业实时场景通常需要配合第三方扩展使用。

### 2. 工业场景核心价值

- **故障快速追溯**：留存 PLC 通信异常、相机采集故障、程序崩溃的完整堆栈，出问题无需复现即可定位根因，减少产线停机时间。
- **设备运行监控**：记录设备状态切换、周期耗时、告警事件，通过日志趋势提前发现性能退化、硬件老化隐患，从 “事后救火” 转向 “事前预警”。
- **合规操作审计**：记录参数修改、模式切换、人工复位等操作，满足 GMP、IATF16949 等行业的追溯与审计要求。
- **生产链路关联**：绑定批次号、产品 SN、工位号，实现单产品全生产周期的日志串联，支撑质量问题精准溯源。

------

## 二、实现原理与核心架构

Log4Net 采用分层管道式架构，日志从业务调用到最终落地会经过四层核心组件协同处理。

### 1. 四大核心组件

| 组件                     | 角色       | 职责                                                         |
| :----------------------- | :--------- | :----------------------------------------------------------- |
| **Logger（日志记录器）** | 业务层入口 | 接收日志调用，做级别校验，低于配置级别的日志直接丢弃；支持命名空间层级继承 |
| **Filter（过滤器）**     | 中间筛选   | 按级别、关键词、日志器名称等规则二次过滤，决定日志是否继续向下传递 |
| **Appender（输出器）**   | 落地执行   | 决定日志的输出目的地，如文件、数据库、控制台等，一个 Logger 可绑定多个 Appender |
| **Layout（布局器）**     | 格式编排   | 定义日志的最终输出格式，如时间戳、级别、线程 ID、消息、异常堆栈的排列方式 |

### 2. 日志级别体系

按优先级从低到高分为 5 个正式级别，外加 2 个开关级别：

```
ALL < DEBUG < INFO < WARN < ERROR < FATAL < OFF
```

- 配置级别后，**等于和高于该级别的日志才会被处理**，低于级别的直接丢弃；
- 工业生产环境通常设置为 INFO，仅保留关键节点与异常告警，DEBUG 级仅排障时临时开启。

### 3. 完整处理流程

1. 业务代码调用日志方法，生成日志事件对象；
2. Logger 校验日志级别，低于配置级别直接终止；
3. 日志事件流经 Filter 过滤器，匹配规则的保留，不匹配的丢弃；
4. 分发到所有绑定的 Appender；
5. Appender 调用 Layout 将日志事件格式化为文本；
6. 最终写入文件、数据库等目标介质。

> 关键特性：原生为**同步写入模式**，日志 IO 操作直接在调用线程执行，实时性要求高的工控场景必须借助第三方扩展包实现异步。

### 4. 滚动归档原理

`RollingFileAppender` 是最常用的文件输出器，支持三种滚动切割策略Apache Logging Services：

- `Date`：按时间周期切割（按天、按小时），由 `DatePattern` 决定周期与命名格式；
- `Size`：按文件大小切割，超过阈值生成新文件；
- `Composite`：日期 + 大小双重切割，单日日志过大时自动拆分。

> 原生仅支持 `maxSizeRollBackups` 按文件总数限制备份数量，**不支持按天数自动删除旧日志**，长期运行需要配合外部脚本清理。

## 三、基础使用步骤

### 1. 安装 NuGet 包

- 基础核心包：

  powershell:

  ```powershell
  Install-Package log4net
  ```

- 工业实时场景必备异步扩展包（真后台线程异步，不阻塞业务线程）：

  powershell:

  ```powershell
  Install-Package Log4Net.Async
  ```

### 2. 添加配置文件

在项目根目录新建 `log4net.config`，设置文件属性：**复制到输出目录 → 如果较新则复制**。

基础配置结构如下：

xaml:

```xaml
<?xml version="1.0" encoding="utf-8" ?>
<log4net>
  <!-- 配置各种Appender输出目标 -->
  <appender name="RollingFileAppender" type="log4net.Appender.RollingFileAppender">
    <!-- 输出路径、滚动规则、格式等 -->
  </appender>

  <!-- 根日志器，全局默认配置 -->
  <root>
    <level value="INFO" />
    <appender-ref ref="RollingFileAppender" />
  </root>
</log4net>
```

### 3. 初始化加载配置

程序启动时加载配置，推荐使用 `ConfigureAndWatch` 开启配置热重载，修改配置无需重启程序：

csharp:

```c#
using log4net.Config;
using System.IO;

// 程序入口处执行
FileInfo configFile = new FileInfo("log4net.config");
XmlConfigurator.ConfigureAndWatch(configFile);
```

也可在 `AssemblyInfo.cs` 中通过程序集特性声明：

csharp:

```c#
[assembly: log4net.Config.XmlConfigurator(ConfigFile = "log4net.config", Watch = true)]
```

### 4. 业务代码调用

csharp:

```c#
using log4net;

public class PlcCommunication
{
    // 获取指定名称的日志器，对应配置中的logger节点
    private static readonly ILog log = LogManager.GetLogger("PLC通信");

    public void Demo()
    {
        log.Debug("调试细节，生产默认关闭");
        log.Info("关键节点，生产永久留存");
        log.Warn("单次异常、告警提示");
        log.Error("功能失效，带异常堆栈");
        log.Fatal("致命错误，程序崩溃");
    }
}
```

## 四、工业场景完整实战案例

### 场景背景

PLC 实时控制工位，控制周期 10ms，要求：

1. 控制线程零 IO 阻塞，日志异步写入；
2. 运行日志与错误日志分离，排查高效；
3. 按天 + 按大小双重切割，防止单文件过大；
4. 支持不停机动态调整日志级别。

### 1. 完整配置文件 log4net.config

xaml:

```xaml
<?xml version="1.0" encoding="utf-8" ?>
<log4net>
  <!-- PLC控制专属异步队列 -->
  <appender name="PlcAsyncAppender" type="Log4Net.Async.AsyncForwardingAppender, Log4Net.Async">
    <bufferSize value="3000" />
    <lossy value="true" />
    <!-- ERROR及以上级别强制保留，队列满也不丢弃 -->
    <evaluator type="log4net.Core.LevelEvaluator">
      <threshold value="ERROR" />
    </evaluator>
    <appender-ref ref="PlcRunAppender" />
    <appender-ref ref="ErrorOnlyAppender" />
  </appender>

  <!-- 运行日志：INFO~WARN -->
  <appender name="PlcRunAppender" type="log4net.Appender.RollingFileAppender">
    <file value="D:/DeviceLogs/ST01/plc_run.log" />
    <appendToFile value="true" />
    <!-- 复合滚动：按天+单文件100MB -->
    <rollingStyle value="Composite" />
    <datePattern value="yyyyMMdd'.log'" />
    <maximumFileSize value="100MB" />
    <staticLogFileName value="false" />
    <!-- 兜底：最多保留30个归档文件 -->
    <maxSizeRollBackups value="30" />
    <preserveLogFileNameExtension value="true" />
    <encoding value="utf-8" />
    <!-- 单进程独占锁，提升写入性能 -->
    <lockingModel type="log4net.Appender.FileAppender+ExclusiveLock" />

    <!-- 只输出INFO~WARN级别 -->
    <filter type="log4net.Filter.LevelRangeFilter">
      <levelMin value="INFO" />
      <levelMax value="WARN" />
    </filter>

    <layout type="log4net.Layout.PatternLayout">
      <conversionPattern value="%date{yyyy-MM-dd HH:mm:ss.fff} | %-5level | 线程%thread | 工位%property{StationNo} | %message%newline" />
    </layout>
  </appender>

  <!-- 错误专属日志：ERROR~FATAL -->
  <appender name="ErrorOnlyAppender" type="log4net.Appender.RollingFileAppender">
    <file value="D:/DeviceLogs/ST01/error.log" />
    <appendToFile value="true" />
    <rollingStyle value="Composite" />
    <datePattern value="yyyyMMdd'.log'" />
    <maximumFileSize value="100MB" />
    <staticLogFileName value="false" />
    <maxSizeRollBackups value="90" />
    <encoding value="utf-8" />
    <lockingModel type="log4net.Appender.FileAppender+ExclusiveLock" />

    <filter type="log4net.Filter.LevelRangeFilter">
      <levelMin value="ERROR" />
      <levelMax value="FATAL" />
    </filter>

    <layout type="log4net.Layout.PatternLayout">
      <conversionPattern value="%date{yyyy-MM-dd HH:mm:ss.fff} | %level | %logger | %message%newline%exception
------------------------------------------------------------------------%newline" />
    </layout>
  </appender>

  <!-- 全局规则 -->
  <root>
    <level value="INFO" />
    <appender-ref ref="PlcAsyncAppender" />
  </root>

  <!-- 排障时临时开启：仅PLC通信模块开DEBUG -->
  <!--
  <logger name="PLC通信">
    <level value="DEBUG" />
  </logger>
  -->
</log4net>
```

### 2. 初始化与全局兜底代码

csharp:

```c#
using log4net;
using log4net.Config;
using System.IO;

static class Program
{
    private static readonly ILog fatalLog = LogManager.GetLogger("主程序");

    static void Main()
    {
        // 加载配置并开启热重载
        FileInfo configFile = new FileInfo("log4net.config");
        XmlConfigurator.ConfigureAndWatch(configFile);

        // 注入全局业务上下文
        LogicalThreadContext.Properties["StationNo"] = "ST01";

        // 全局未捕获异常兜底
        AppDomain.CurrentDomain.UnhandledException += (sender, e) =>
        {
            var ex = e.ExceptionObject as Exception;
            fatalLog.Fatal("全局未捕获异常，程序紧急退出", ex);
            LogManager.Shutdown(); // 强制刷盘，落定所有异步日志
        };
    }
}
```

### 3. PLC 通信业务代码示例

csharp:

```c#
public class PlcControlService
{
    private static readonly ILog log = LogManager.GetLogger("PLC通信");
    private int _continuousFailCount = 0;

    public bool WriteRegister(string address, short value)
    {
        try
        {
            // 正常读写仅打DEBUG，生产默认关闭，零开销
            if (log.IsDebugEnabled)
            {
                log.DebugFormat("写入地址{0}，值{1}", address, value);
            }

            bool result = _plcClient.Write(address, value);
            if (!result)
            {
                _continuousFailCount++;
                if (_continuousFailCount >= 3)
                {
                    log.ErrorFormat("地址{0}连续写入失败3次，写入值{1}", address, value);
                }
                else
                {
                    log.WarnFormat("地址{0}单次写入失败，进入重试", address);
                }
                return false;
            }

            _continuousFailCount = 0;
            return true;
        }
        catch (Exception ex)
        {
            log.Error($"写入地址{address}发生通信异常", ex);
            return false;
        }
    }
}
```

## 五、工业场景避坑要点

1. **不要把缓冲当异步**

   原生 `BufferingForwardingAppender` 只是在调用线程批量缓冲，依然阻塞业务线程，不属于真异步；实时场景必须使用 `Log4Net.Async` 包的 `AsyncForwardingAppender`。

2. **按天切割三参数缺一不可**

   要实现按天切割，必须同时配置：

   xaml：

   ```xaml
   <rollingStyle value="Date" />
   <datePattern value="yyyyMMdd'.log'" />
   <staticLogFileName value="false" />
   ```

   缺少 `staticLogFileName="false"` 会导致日志无法正常按天切割。

3. **原生不支持按天数自动清理**

   `maxSizeRollBackups` 限制的是归档文件总数，不是保留天数；7×24 小时运行场景需配合 Windows 定时任务 + 批处理脚本删除过期日志。

4. **生产环境禁用高开销字段**

   `%location`、`%method`、`%stacktrace` 等反射类字段开销是普通字段的几十倍，会显著拉高控制线程耗时，仅排障时临时开启。

5. **单进程优先用独占锁**

   `ExclusiveLock` 比默认的 `MinimalLock` 写入性能高 30% 以上，单进程上位机场景优先使用，减少锁竞争带来的周期抖动。
