# 999999006-2_C# 特性 (Attribute) 的反射读取机制详解

特性 (Attribute) 是 C# 中一种强大的元数据编程机制，它允许你将声明性信息与代码元素（类、方法、属性等）关联起来。**反射 (Reflection)** 则是在运行时读取和操作这些元数据的技术。

## 一、特性的本质与编译时处理

### 1.1 特性的本质

特性本质上是一个**继承自`System.Attribute`的类**，它的实例会被序列化并存储在程序集的元数据中，而不是直接嵌入到 IL 代码里。

csharp:

```c#
// 定义一个自定义特性
[AttributeUsage(AttributeTargets.Class | AttributeTargets.Method)]
public class MyCustomAttribute : Attribute
{
    public string Description { get; }
    public int Version { get; set; }

    public MyCustomAttribute(string description)
    {
        Description = description;
    }
}

// 使用特性
[MyCustom("这是一个测试类", Version = 1)]
public class TestClass
{
    [MyCustom("这是一个测试方法")]
    public void TestMethod() { }
}
```

### 1.2 编译时发生了什么

当你编译上面的代码时，C# 编译器会：

1. 验证特性的使用是否符合`AttributeUsage`的限制
2. 计算特性构造函数的参数和属性初始化器的值
3. 将这些值以**二进制格式**序列化并存储在程序集的元数据表中
4. 在被标记的代码元素的元数据条目中添加一个指向该特性数据的引用

**关键要点**：此时特性类**并没有被实例化**，只是它的构造参数和属性值被保存为数据。

## 二、反射读取特性的完整流程

当你在运行时通过反射读取特性时，会经历以下几个关键步骤：

### 步骤 1：获取表示代码元素的反射对象

首先，你需要获取表示目标代码元素的`Type`、`MethodInfo`、`PropertyInfo`等对象。

csharp:

```c#
Type type = typeof(TestClass);
MethodInfo method = type.GetMethod("TestMethod");
```

### 步骤 2：调用`GetCustomAttributes`方法

这是读取特性的核心方法，它定义在`ICustomAttributeProvider`接口中，由所有反射对象实现。

csharp:

```c#
// 读取类上的所有特性
object[] attributes = type.GetCustomAttributes(true);

// 读取指定类型的特性
MyCustomAttribute classAttr = (MyCustomAttribute)Attribute.GetCustomAttribute(
    type, typeof(MyCustomAttribute));
```

### 步骤 3：CLR 内部执行的详细过程

当`GetCustomAttributes`被调用时，CLR 会执行以下操作：

1. **元数据解析**：CLR 从程序集的元数据表中查找与该代码元素关联的所有特性记录
2. **特性类型加载**：加载特性类的`Type`对象（如果尚未加载）
3. **构造函数参数解析**：从元数据中反序列化构造函数的参数值
4. **实例化特性对象**：使用反射调用特性类的构造函数，传入解析后的参数
5. **属性初始化**：从元数据中反序列化属性初始化器的值，并通过反射设置到新创建的特性对象上
6. **缓存结果**：将创建好的特性对象缓存起来，下次调用时直接返回缓存的实例

### 步骤 4：返回特性实例

最后，方法返回一个包含所有特性实例的数组，或者指定类型的单个实例。

## 三、不同读取方法的区别与性能对比

### 3.1 常用的特性读取方法

| 方法                                           | 描述                   | 返回值      | 是否继承            |
| :--------------------------------------------- | :--------------------- | :---------- | :------------------ |
| `GetCustomAttributes(bool inherit)`            | 获取所有特性           | `object[]`  | 由`inherit`参数决定 |
| `GetCustomAttributes(Type type, bool inherit)` | 获取指定类型的特性     | `object[]`  | 由`inherit`参数决定 |
| `Attribute.GetCustomAttribute(...)`            | 获取单个指定类型的特性 | `Attribute` | 继承                |
| `IsDefined(Type type, bool inherit)`           | 检查是否定义了指定特性 | `bool`      | 由`inherit`参数决定 |

### 3.2 性能差异

- **`IsDefined`**：性能最好，因为它只检查元数据中是否存在该特性的记录，**不需要实例化特性对象**
- **`GetCustomAttributes`**：性能较差，因为它需要实例化所有特性对象
- **`Attribute.GetCustomAttribute`**：性能介于两者之间，只实例化指定类型的特性

**性能测试示例**：

csharp:

```c#
// 最快：只检查是否存在
bool exists = Attribute.IsDefined(type, typeof(MyCustomAttribute));

// 中等：只实例化一个特性
MyCustomAttribute attr = Attribute.GetCustomAttribute(type, typeof(MyCustomAttribute));

// 最慢：实例化所有特性
object[] allAttrs = type.GetCustomAttributes(true);
```

## 四、特性继承与查找规则

### 4.1 `inherit`参数的作用

`GetCustomAttributes`和`IsDefined`方法都有一个`bool inherit`参数，它决定了是否要查找继承自基类的特性。

csharp:

```c#
public class BaseClass
{
    [MyCustom("基类特性")]
    public virtual void VirtualMethod() { }
}

public class DerivedClass : BaseClass
{
    public override void VirtualMethod() { }
}

// 此时：
MethodInfo method = typeof(DerivedClass).GetMethod("VirtualMethod");

// inherit=true：会找到基类上的特性
object[] attrs1 = method.GetCustomAttributes(true); // 长度为1

// inherit=false：不会找到基类上的特性
object[] attrs2 = method.GetCustomAttributes(false); // 长度为0
```

### 4.2 `AttributeUsage.Inherited`属性

特性本身可以通过`AttributeUsage`的`Inherited`属性来控制它是否能被继承：

csharp:

```c#
[AttributeUsage(AttributeTargets.Method, Inherited = false)]
public class NonInheritedAttribute : Attribute { }
```

即使`inherit`参数为`true`，标记了`Inherited = false`的特性也不会被继承查找。

## 五、特性读取的缓存机制

### 5.1 CLR 的内部缓存

CLR 会对通过反射读取的特性实例进行缓存，以提高性能。**同一个代码元素上的同一个特性，只会被实例化一次**。

csharp:

```c#
// 第一次调用：实例化特性并缓存
MyCustomAttribute attr1 = (MyCustomAttribute)Attribute.GetCustomAttribute(
    type, typeof(MyCustomAttribute));

// 第二次调用：直接返回缓存的实例
MyCustomAttribute attr2 = (MyCustomAttribute)Attribute.GetCustomAttribute(
    type, typeof(MyCustomAttribute));

// 验证：两个引用指向同一个对象
Console.WriteLine(object.ReferenceEquals(attr1, attr2)); // 输出：True
```

### 5.2 手动缓存最佳实践

虽然 CLR 有内部缓存，但在性能敏感的场景下，建议你手动缓存特性实例：

csharp:

```c#
private static readonly MyCustomAttribute _cachedAttribute = 
    Attribute.GetCustomAttribute(typeof(TestClass), typeof(MyCustomAttribute)) 
    as MyCustomAttribute;
```

## 六、常见误区与注意事项

### 6.1 误区 1：特性在编译时被实例化

**错误**：很多人以为特性在编译时就被实例化了。

**正确**：特性只在**第一次被反射读取时**才会被实例化。

### 6.2 误区 2：特性构造函数可以包含任意代码

虽然技术上可以，但特性构造函数中的代码会在**反射读取时**执行，这可能导致意外的行为和性能问题。

### 6.3 误区 3：所有特性都可以被继承

只有标记了`[AttributeUsage(Inherited = true)]`（默认值）的特性才会被继承查找。

### 6.4 注意事项

- 特性类应该是**密封的**（`sealed`），以提高性能
- 避免在特性构造函数中执行复杂的逻辑
- 在性能敏感的代码中，优先使用`IsDefined`而不是`GetCustomAttributes`
- 特性参数只能是**编译时常量**（基本类型、字符串、枚举、Type、数组等）

## 七、高级：自定义特性读取

你可以通过实现`ICustomAttributeProvider`接口来自定义特性的读取行为，但这通常只在高级场景中使用。

csharp:

```c#
public class CustomType : TypeDelegator, ICustomAttributeProvider
{
    public CustomType(Type type) : base(type) { }

    public override object[] GetCustomAttributes(bool inherit)
    {
        // 自定义特性读取逻辑
        return base.GetCustomAttributes(inherit);
    }

    public override object[] GetCustomAttributes(Type attributeType, bool inherit)
    {
        // 自定义特性读取逻辑
        return base.GetCustomAttributes(attributeType, inherit);
    }

    public override bool IsDefined(Type attributeType, bool inherit)
    {
        // 自定义特性检查逻辑
        return base.IsDefined(attributeType, inherit);
    }
}
```

## 总结

特性的反射读取是一个从**元数据解析**到**对象实例化**的完整过程：

1. 编译时，特性的参数和属性值被序列化存储在程序集元数据中
2. 运行时，通过反射 API 触发特性的读取
3. CLR 解析元数据，加载特性类型，调用构造函数和设置属性
4. 实例化后的特性对象被缓存，供后续调用使用

理解这个过程对于正确使用特性和优化反射性能至关重要。在实际开发中，应该根据具体场景选择合适的特性读取方法，并注意缓存和性能优化。
