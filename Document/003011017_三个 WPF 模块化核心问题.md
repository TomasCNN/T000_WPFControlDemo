# 003011017_三个 WPF 模块化核心问题

## 问题一：如何在 WPF 中实现模块间的松耦合？

### 核心本质

松耦合的终极目标是：**一个模块的内部变化，不会导致其他模块的修改**。对于生命周期长达 5~10 年的工业软件来说，这是避免代码变成 "屎山" 的唯一途径。

### 一、实现松耦合的 5 层递进体系（从基础到高级）

------

#### 1. 第一层：依赖倒置原则（DIP）—— 松耦合的理论基石

**工业场景最痛的痛点**：换一个相机品牌，要改半个项目的代码。

**解决方案**：让所有上层代码依赖抽象接口，而不是具体的硬件实现。

**你的模板中已经实现的标准范式**：

csharp:

```c#
// 抽象层（稳定不变）
public interface ICamera : IDisposable
{
    Bitmap GetBitmap(int timeoutMs);
    bool SetExposureTime(int exposureUs);
}

// 实现层（易变）
public class IkCamera : ICamera { /* 埃科相机具体实现 */ }
public class HikCamera : ICamera { /* 海康相机具体实现 */ }

// 上层业务（依赖抽象，永远不变）
public class DetectionProcess
{
    // 只依赖ICamera接口，不关心具体是哪个品牌的相机
    private readonly ICamera _camera;
    
    public DetectionProcess(ICamera camera)
    {
        _camera = camera;
    }
}
```

**工业级收益**：换相机时，只需要新增一个`ICamera`的实现类，然后修改配置文件中的一行，**上层业务代码零改动**。

------

#### 2. 第二层：依赖注入（DI）—— 松耦合的实现工具

**解决的问题**：如果不用 DI，你还是需要在某个地方`new IkCamera()`，这依然是硬编码依赖。

**核心原理**：由一个全局容器统一管理所有对象的生命周期和依赖关系，模块需要什么依赖，直接在构造函数里声明，容器会自动注入。

**Prism DI 工业级最佳实践（你的模板可直接升级）**：

csharp:

```c#
// App.xaml.cs 中注册服务
protected override void RegisterTypes(IContainerRegistry containerRegistry)
{
    // 1. 硬件抽象与实现绑定（配置化）
    var cameraType = ConfigService.Instance.CurrentConfig.Hardware.Camera.Type;
    if (cameraType == "Ik")
        containerRegistry.RegisterSingleton<ICamera, IkCamera>();
    else if (cameraType == "Hik")
        containerRegistry.RegisterSingleton<ICamera, HikCamera>();

    // 2. 业务服务注册（自动注入依赖）
    containerRegistry.Register<CameraService>();
    containerRegistry.Register<DetectionProcess>();
}

// 使用时完全不需要new
public class MainViewModel
{
    // 构造函数声明依赖，容器自动注入
    public MainViewModel(DetectionProcess detectionProcess)
    {
        _detectionProcess = detectionProcess;
    }
}
```

**关键优势**：彻底消除代码中的所有`new`关键字，所有依赖关系都在容器中统一管理。

------

#### 3. 第三层：接口隔离原则（ISP）—— 最小化依赖范围

**常见错误**：设计一个 "万能接口"，包含所有可能的功能，导致不需要这些功能的模块也被迫依赖它们。

**解决方案**：将大接口拆分成多个小而专一的接口，每个模块只依赖它真正需要的接口。

**工业场景示例**：

csharp:

```c#
// ❌ 错误：胖接口
public interface ICamera
{
    bool Initialize();
    Bitmap GetBitmap();
    bool SetLineScanSpeed(int speed); // 面阵相机不需要这个功能
    bool SetTriggerDelay(int delay);  // 线扫相机不需要这个功能
}

// ✅ 正确：接口隔离
public interface ICamera : IDisposable
{
    bool Initialize();
    Bitmap GetBitmap(int timeout);
}

public interface ILineScanCamera : ICamera
{
    bool SetLineScanSpeed(int speed);
}

public interface IAreaScanCamera : ICamera
{
    bool SetTriggerDelay(int delay);
}
```

------

#### 4. 第四层：事件驱动架构 —— 彻底消除模块间的直接调用

**解决的问题**：即使依赖了接口，A 模块调用 B 模块的方法，依然是 A 依赖 B。

**核心原理**：模块之间不直接调用对方的方法，而是通过 "发布事件 - 订阅事件" 的方式进行通信。发布者和订阅者完全不知道对方的存在。

**Prism 事件聚合器 工业级完整用法（含防内存泄漏）**：

csharp:

```c#
// 1. 定义强类型事件（放在Common/Events文件夹）
public class DefectDetectedEvent : PubSubEvent<DefectDetectedEventArgs> { }

public class DefectDetectedEventArgs
{
    public string Barcode { get; set; }
    public List<Defect> Defects { get; set; }
    public DateTime DetectTime { get; set; }
}

// 2. 发布事件（算法模块）
public class AlgorithmService
{
    private readonly IEventAggregator _eventAggregator;

    public List<Defect> DetectDefects(Bitmap image)
    {
        var defects = new List<Defect>();
        // 算法处理...
        
        // 发布事件，不需要知道谁会接收
        _eventAggregator.GetEvent<DefectDetectedEvent>()
            .Publish(new DefectDetectedEventArgs
            {
                Barcode = _currentBarcode,
                Defects = defects,
                DetectTime = DateTime.Now
            });
        
        return defects;
    }
}

// 3. 订阅事件（监控模块+数据记录模块）
public class MonitorViewModel : BindableBase, IDisposable
{
    private readonly IEventAggregator _eventAggregator;
    private SubscriptionToken _defectEventToken;

    public MonitorViewModel(IEventAggregator eventAggregator)
    {
        _eventAggregator = eventAggregator;
        
        // 订阅事件并保存订阅令牌
        _defectEventToken = _eventAggregator.GetEvent<DefectDetectedEvent>()
            .Subscribe(OnDefectDetected, ThreadOption.UIThread);
    }

    private void OnDefectDetected(DefectDetectedEventArgs args)
    {
        // 更新UI显示缺陷
        DefectList = new ObservableCollection<Defect>(args.Defects);
    }

    // ✅ 必须取消订阅，防止内存泄漏
    public void Dispose()
    {
        _defectEventToken?.Dispose();
    }
}
```

------

#### 5. 第五层：插件化架构 —— 真正的零耦合

**最高级的松耦合**：模块之间甚至不需要在编译时引用对方，可以在运行时动态加载和卸载模块。

**Prism 模块化插件示例**：

csharp:

```c#
// 单独的算法模块项目
[Module(ModuleName = "AlgorithmModule")]
public class AlgorithmModule : IModule
{
    public void OnInitialized(IContainerProvider containerProvider)
    {
        // 模块初始化
    }

    public void RegisterTypes(IContainerRegistry containerRegistry)
    {
        containerRegistry.Register<IAlgorithmService, AlgorithmService>();
    }
}

// 主项目中动态加载模块
protected override IModuleCatalog CreateModuleCatalog()
{
    return new DirectoryModuleCatalog() { ModulePath = "Modules" };
}
```

**工业级收益**：可以单独更新算法模块，不需要重新编译整个主程序；不同客户可以加载不同的算法模块。

------

### 二、工业场景必须避免的 7 种强耦合反模式

1. ❌ **直接 new 对象**：`var camera = new IkCamera();`
2. ❌ **静态类 / 静态方法**：`public static class CameraManager { }`
3. ❌ **硬编码魔法字符串**：`_plc.WriteShort("D200", 3);`
4. ❌ **跨层调用**：ViewModel 直接操作硬件
5. ❌ **循环依赖**：A 依赖 B，B 依赖 A
6. ❌ **事件不取消订阅**：导致内存泄漏
7. ❌ **共享全局变量**：`public static Bitmap CurrentImage;`

## 问题二：除了上述提到的方式，还有哪些方式可以实现模块间的通信？

上一轮已经讲了**Prism 事件聚合器、共享服务、依赖注入、回调委托、消息总线**，这里补充 6 种工业场景不可或缺的通信方式，覆盖从单进程内到跨工厂的所有需求。

------

### 1. MediatR（请求 / 响应模式）【业务层通信首选】

**核心原理**：基于中介者模式，将 "请求" 和 "处理" 完全分离。发送者发送一个请求，MediatR 会找到对应的处理者执行，并返回结果。

**解决的问题**：事件聚合器没有返回值，不适合需要结果的命令调用。

**工业场景示例：触发检测流程**：

csharp:

```c#
// 1. 定义请求
public class StartDetectionCommand : IRequest<bool>
{
    public string ProductBarcode { get; set; }
}

// 2. 定义请求处理者
public class StartDetectionCommandHandler : IRequestHandler<StartDetectionCommand, bool>
{
    private readonly DetectionProcess _detectionProcess;

    public StartDetectionCommandHandler(DetectionProcess detectionProcess)
    {
        _detectionProcess = detectionProcess;
    }

    public async Task<bool> Handle(StartDetectionCommand request, CancellationToken cancellationToken)
    {
        return await _detectionProcess.RunAsync(request.ProductBarcode);
    }
}

// 3. 发送请求
public class MainViewModel
{
    private readonly IMediator _mediator;

    private async void StartButton_Click()
    {
        // 发送命令，不需要知道谁处理
        var result = await _mediator.Send(new StartDetectionCommand
        {
            ProductBarcode = CurrentBarcode
        });
    }
}
```

**优势**：天然支持异步、取消令牌、管道行为（日志、验证、事务），非常适合业务流程编排。

------

### 2. MQTT 消息队列【跨设备 / 跨系统通信工业标准】

**核心原理**：基于发布 / 订阅模式的轻量级消息协议，是工业 4.0 的事实标准。

**适用场景**：与 MES 系统通信、与 PLC 通信、多设备协同、远程监控。

**工业视觉设备与 MES 通信示例**：

csharp:

```c#
// 发布检测结果到MES
public async Task PublishDetectionResultAsync(ProductRecord record)
{
    var message = new MqttApplicationMessageBuilder()
        .WithTopic("vision/line1/result")
        .WithPayload(JsonConvert.SerializeObject(record))
        .WithQualityOfServiceLevel(2) // 至少一次送达
        .WithRetainFlag(false)
        .Build();

    await _mqttClient.PublishAsync(message);
}

// 订阅MES的生产指令
public void SubscribeToProductionCommands()
{
    _mqttClient.ApplicationMessageReceivedAsync += async e =>
    {
        if (e.ApplicationMessage.Topic == "mes/line1/command")
        {
            var command = JsonConvert.DeserializeObject<MesProductionCommand>(
                e.ApplicationMessage.PayloadSegment);
            
            await ProcessProductionCommandAsync(command);
        }
    };
}
```

------

### 3. 共享内存【高速大数据传输首选】

**核心原理**：多个进程共享同一块物理内存，数据不需要复制，直接读写。

**适用场景**：线扫相机大图像传输、与 C++ 算法库交互、高速数据采集。

**性能对比**：比 TCP/IP 快 10~100 倍，是 GB 级图像传输的唯一可行方案。

**示例：与 C++ 算法库共享图像**：

csharp:

```c#
// 创建1920x1080x3字节的共享内存
using var sharedMemory = MemoryMappedFile.CreateNew("VisionImageBuffer", 1920 * 1080 * 3);
using var stream = sharedMemory.CreateViewStream();

// 写入图像数据
var bitmapData = bitmap.LockBits(
    new Rectangle(0, 0, bitmap.Width, bitmap.Height),
    ImageLockMode.ReadOnly,
    PixelFormat.Format24bppRgb);

stream.Write(bitmapData.Scan0, 0, bitmapData.Stride * bitmapData.Height);
bitmap.UnlockBits(bitmapData);

// C++算法库直接读取共享内存中的图像，不需要复制
```

------

### 4. SQLite 共享数据库【跨进程数据共享首选】

**核心原理**：多个进程访问同一个 SQLite 数据库文件，实现数据共享。

**适用场景**：生产记录共享、参数配置共享、多程序数据交换。

**优势**：不需要额外的服务，部署简单，可靠性高。

------

### 5. WebSocket【Web / 移动端实时通信首选】

**核心原理**：建立持久的 TCP 连接，实现全双工通信。

**适用场景**：Web 端监控界面、手机 APP 远程控制、实时数据推送。

------

### 6. Prism 区域导航参数【页面间传值首选】

**核心原理**：导航时通过参数传递数据。

**适用场景**：从产品列表页跳转到详情页、传递简单的 ID 或参数。

**示例**：

csharp:

```c#
// 导航并传递产品ID
_regionManager.RequestNavigate("MainRegion", "ProductDetailView", 
    new NavigationParameters { { "ProductId", productId } });

// 接收参数
public class ProductDetailViewModel : INavigationAware
{
    public void OnNavigatedTo(NavigationContext navigationContext)
    {
        if (navigationContext.Parameters.TryGetValue("ProductId", out int productId))
        {
            LoadProductDetails(productId);
        }
    }
}
```

## 问题三：如何在实际项目中选择合适的模块间通信方式？

### 一、所有通信方式综合评分表（工业场景专属）

| 通信方式          | 耦合度 | 延迟   | 吞吐量 | 可靠性 | 复杂度 | 适用范围            | 工业推荐度 |
| :---------------- | :----- | :----- | :----- | :----- | :----- | :------------------ | :--------- |
| Prism 事件聚合器  | 极低   | 微秒级 | 高     | 高     | 低     | 单进程内通知        | ⭐⭐⭐⭐⭐      |
| 共享服务          | 低     | 纳秒级 | 极高   | 高     | 低     | 单进程内全局状态    | ⭐⭐⭐⭐⭐      |
| MediatR           | 极低   | 微秒级 | 高     | 高     | 中     | 单进程内命令 / 查询 | ⭐⭐⭐⭐       |
| 依赖注入          | 低     | 纳秒级 | 极高   | 高     | 低     | 单进程内服务依赖    | ⭐⭐⭐⭐⭐      |
| MQTT              | 极低   | 毫秒级 | 中     | 高     | 中     | 跨设备 / 跨系统     | ⭐⭐⭐⭐       |
| 共享内存          | 中     | 微秒级 | 极高   | 中     | 高     | 高速大数据传输      | ⭐⭐⭐        |
| SQLite 共享数据库 | 低     | 毫秒级 | 中     | 高     | 低     | 跨进程数据共享      | ⭐⭐⭐        |
| WebSocket         | 低     | 毫秒级 | 中     | 中     | 中     | Web / 移动端        | ⭐⭐         |
| 区域导航参数      | 低     | 纳秒级 | 高     | 高     | 低     | 页面间传值          | ⭐⭐⭐⭐       |
| 回调委托          | 高     | 纳秒级 | 极高   | 低     | 低     | 简单局部通信        | ⭐          |

------

### 二、工业上位机标准决策流程（按优先级）

#### 第一步：先判断通信范围

- **同一进程内** → 进入第二步
- **同一设备不同进程** → 优先用**SQLite 共享数据库**，大数据用**共享内存**
- **同一车间不同设备** → 必须用**MQTT**
- **跨车间 / 跨工厂** → 用**MQTT + 云平台**
- **Web / 移动端访问** → 用**WebSocket**

#### 第二步：同一进程内，再判断通信类型

1. **通知类（不需要返回值）**

   

   - 状态变化、事件发生 → **Prism 事件聚合器**
   - 示例：缺陷检测完成、设备报警、生产计数更新

   

2. **状态共享类**

   

   - 全局状态、系统配置 → **共享服务**
   - 示例：设备运行状态、当前产品参数、用户权限

   

3. **命令 / 查询类（需要返回值）**

   

   - 触发业务流程、查询数据 → **MediatR**
   - 示例：开始检测、停止检测、查询历史记录

   

4. **页面间导航传值**

   

   - 传递简单 ID 或参数 → **Prism 区域导航参数**

   

5. **服务依赖**

   

   - 模块需要调用其他模块的服务 → **依赖注入**

   

------

### 三、工业场景黄金法则

1. **90% 的场景用 Prism 事件聚合器 + 共享服务**就足够了，不要引入不必要的复杂度
2. **业务流程用 MediatR**，让代码更清晰、更易测试、更容易添加横切关注点（日志、验证、事务）
3. **绝对不要用回调委托进行跨模块通信**，这是强耦合的万恶之源
4. **所有事件必须保存订阅令牌并在适当的时候取消订阅**，否则会导致严重的内存泄漏
5. **跨设备通信统一用 MQTT**，不要自己发明 TCP 协议
6. **线扫相机大图像传输必须用共享内存**，TCP/IP 根本达不到要求的速度

------

## 总结

1. **松耦合是工业软件的生命线**：通过依赖倒置、依赖注入、事件驱动和插件化架构，可以实现真正的硬件可插拔和功能可扩展
2. **通信方式没有最好，只有最合适**：根据通信范围和类型选择最简单、最成熟的方案
3. **工业软件第一原则是稳定性**：优先选择经过工业验证的技术，而不是追求最新的技术潮流
