# 006003002_WPF `Line` 线段类官方类定义深度解析

`Line` 是 WPF 矢量图形体系中 `Shape` 抽象基类的**密封派生类**，用于绘制由两个端点定义的单段直线段。它是 WPF 最轻量化的 Shape 实现之一，仅新增了四个端点坐标依赖属性，其余所有描边、布局、交互、渲染能力全部继承自 `Shape` 与 `FrameworkElement`，是工业上位机中标尺刻度、限位警戒线、尺寸标注、辅助指示线的核心图形元件。

------

## 一、官方基础定义与继承体系

### 1. 基础元信息

- **命名空间**：`System.Windows.Shapes`
- **程序集**：`PresentationFramework.dll`（WPF 核心框架程序集）
- **类修饰符**：`public sealed`（公共密封类，禁止被其他类继承）
- **设计定位**：单一职责的基础直线图形，仅负责形状定义，渲染与布局逻辑完全复用基类

### 2. 完整继承链

plaintext:

```tex
System.Object
  └─ System.Windows.Threading.DispatcherObject
     └─ System.Windows.DependencyObject
        └─ System.Windows.Media.Visual
           └─ System.Windows.UIElement
              └─ System.Windows.FrameworkElement
                 └─ System.Windows.Shapes.Shape
                    └─ System.Windows.Shapes.Line
```

各层能力继承：

- `DispatcherObject`：WPF 线程亲和性，只能在创建它的 UI 线程访问；
- `DependencyObject`：支持依赖属性系统，原生具备数据绑定、样式、动画、属性值继承能力；
- `Visual`：接入 WPF 可视化树，提供 DirectX 硬件加速渲染、命中测试基础；
- `UIElement`：具备路由事件、输入响应、可见性控制、裁剪等基础 UI 能力；
- `FrameworkElement`：完整融入 WPF 布局系统，支持宽高、边距、对齐、数据上下文等标准控件属性；
- `Shape`：提供统一的描边、填充、拉伸、几何渲染等图形通用抽象；
- `Line`：仅实现直线的几何定义，是继承链最末端的具体图形实现。

### 3. 官方类完整声明

以下是 `Line` 类的核心成员精简定义（与官方源码结构一致）：

csharp:

```c#
public sealed class Line : Shape
{
    // 自有依赖属性标识符字段
    public static readonly DependencyProperty X1Property;
    public static readonly DependencyProperty Y1Property;
    public static readonly DependencyProperty X2Property;
    public static readonly DependencyProperty Y2Property;

    // 公共构造函数
    public Line();

    // 端点坐标实例属性
    public double X1 { get; set; }
    public double Y1 { get; set; }
    public double X2 { get; set; }
    public double Y2 { get; set; }

    // 重写 Shape 抽象属性：定义直线的原始几何
    protected override Geometry DefiningGeometry { get; }
}
```

#### 关键结构解读

1. **无新增方法**：`Line` 没有定义任何属于自己的方法，所有功能均通过属性和继承实现；
2. **仅 4 个自有属性**：全部是端点坐标相关，没有额外的外观控制属性；
3. **唯一核心重写**：仅重写了 `Shape` 要求的抽象属性 `DefiningGeometry`，提供直线的几何定义；
4. **密封类约束**：不允许派生继承，如需自定义直线变体（如带箭头直线），需直接继承 `Shape` 基类。

## 二、静态依赖属性字段详解

开头的 4 个 `public static readonly DependencyProperty` 字段，是 WPF 依赖属性系统的**标识符字段**，与下方 4 个实例坐标属性一一对应（命名规则：属性名 + Property）。

### 字段列表

- `X1Property`：对应 `X1` 属性的依赖属性标识符
- `Y1Property`：对应 `Y1` 属性的依赖属性标识符
- `X2Property`：对应 `X2` 属性的依赖属性标识符
- `Y2Property`：对应 `Y2` 属性的依赖属性标识符

### 设计意义

1. **原生支持 WPF 核心特性**：四个坐标全部基于依赖属性注册，天然支持数据绑定、样式复用、动画驱动、属性变更通知，这是 Line 能完美适配 MVVM 模式的根本原因；
2. **属性元数据标记**：注册时均标记了 `FrameworkPropertyMetadataOptions.AffectsMeasure` 和 `AffectsRender`，意味着坐标变化时会自动触发布局重测和渲染重绘，无需开发者手动刷新界面；
3. **内存高效**：静态字段在类静态构造中完成元数据注册，所有 Line 实例共享同一份属性定义，避免每个实例重复存储元数据。

## 三、构造函数

csharp:

```c#
public Line();
```

1. **无参数公共构造**：用于外部实例化 Line 对象；
2. **轻量初始化**：构造函数仅完成继承属性的默认值应用，不会提前创建几何对象，几何计算延迟到布局渲染阶段执行，保证实例化性能；
3. **默认值**：
   - `X1 = Y1 = X2 = Y2 = 0.0`（默认所有坐标为 0，线条不可见）
   - `Stroke = null`（默认无描边，线条不可见）
   - `StrokeThickness = 1.0`
   - `Stretch = Stretch.None`

> 新手常见坑：实例化 Line 后如果只设置坐标，不设置 `Stroke`，线条会完全透明不显示，必须同时赋值 `Stroke` 画刷。

## 四、实例属性逐析

### 1. 自有核心属性：端点坐标（4 个）

这是 Line 形状定义的唯一变量，决定了直线的位置、长度和方向。

| 属性 | 类型     | 默认值 | 官方说明                                                     |
| :--- | :------- | :----- | :----------------------------------------------------------- |
| `X1` | `double` | `0.0`  | 线段**起点**的 X 轴坐标，相对于 Line 元素自身布局区域的左上角 |
| `Y1` | `double` | `0.0`  | 线段**起点**的 Y 轴坐标，相对于 Line 元素自身布局区域的左上角 |
| `X2` | `double` | `0.0`  | 线段**终点**的 X 轴坐标                                      |
| `Y2` | `double` | `0.0`  | 线段**终点**的 Y 轴坐标                                      |

#### 坐标体系说明

- 坐标原点在 Line 元素自身布局区域的左上角，X 轴向右递增，Y 轴向下递增，与 WPF 标准坐标系完全一致；
- 坐标是**相对自身**的，不是相对于父容器的。如果放在 Canvas 中，`Canvas.Left`/`Canvas.Top` 控制 Line 元素整体的位置，`X1/Y1` 是元素内部的相对偏移。

### 2. 继承自 Shape 的有效属性

Line 是纯轮廓开放图形，描边类属性全部生效，是控制外观的核心：

| 属性分类 | 属性名               | 作用与工业场景价值                                           |
| :------- | :------------------- | :----------------------------------------------------------- |
| 描边基础 | `Stroke`             | 线条画刷 / 颜色，为 `null` 时线条完全不显示                  |
| 描边基础 | `StrokeThickness`    | 线条厚度，单位为与设备无关像素，支持小数                     |
| 端点样式 | `StrokeStartLineCap` | 起点端点样式：Flat (平端)、Square (方端)、Round (圆端)、Triangle (三角端)，刻度线常用 Flat，指示线常用 Round |
| 端点样式 | `StrokeEndLineCap`   | 终点端点样式，同起点                                         |
| 虚线样式 | `StrokeDashArray`    | 虚线序列，按「实线长度、空白长度」交替循环，用于警戒线、检测框 |
| 虚线样式 | `StrokeDashOffset`   | 虚线起始偏移量，配合动画可实现流动扫描效果                   |
| 虚线样式 | `StrokeDashCap`      | 虚线段的端点样式                                             |
| 拉伸模式 | `Stretch`            | 控制直线如何适配布局分配的空间：None/Fill/Uniform/UniformToFill |
| 几何只读 | `RenderedGeometry`   | 获取最终渲染后的几何对象，包含线条厚度影响，用于精确命中测试 |

### 3. 无效 / 无意义属性

以下属性继承自 Shape，但对 Line 无实际效果，属于高频踩坑点：

1. **`Fill` 填充属性**

   Line 是开放图形，没有封闭的内部区域，设置 `Fill` 完全不会产生任何填充效果，属于无效属性。

2. **`StrokeLineJoin` 拐角连接属性**

   单段直线没有拐角，该属性无作用，仅对 `Polyline`、``Polygon`等多段图形生效。

3. **`StrokeMiterLimit` 斜接限制属性**

   

   同理，没有拐角就不存在斜接尖角，该属性无意义。

### 4. 布局属性的误区

`Width`、`Height` 是继承自 `FrameworkElement` 的布局属性，**不直接决定线条的长度**：

- 它们控制的是 Line 元素在布局系统中占用的区域大小；
- 线条本身的长度由 `X1/X2`、`Y1/Y2` 的坐标差，结合 `Stretch` 拉伸模式共同决定；
- 这是新手最容易混淆的点：设置 `Width="200"` 不会让线条变成 200 像素长。

## 五、核心重写属性：DefiningGeometry

csharp:

```c#
protected override Geometry DefiningGeometry { get; }
```

这是 `Line` 唯一重写的成员，也是 `Shape` 抽象基类强制所有派生类实现的扩展点。

### 官方内部实现逻辑

csharp:

```c#
protected override Geometry DefiningGeometry
{
    get
    {
        // 以X1Y1为起点、X2Y2为终点，构造直线几何对象
        return new LineGeometry(
            new Point(X1, Y1),
            new Point(X2, Y2));
    }
}
```

### 详细解读

1. **访问级别**：`protected`，外部代码无法直接访问，仅基类和自身内部使用；
2. **职责单一**：只负责返回直线的原始几何定义，不关心描边、拉伸、变换等渲染细节；
3. **设计思想**：**形状定义与渲染执行分离**。所有 Shape 派生类只需要定义 “自己是什么形状”，布局、描边、命中测试、动画等通用逻辑全部由基类统一处理，既保证了所有图形行为一致，也极大减少了重复代码；
4. **与 RenderedGeometry 的区别**：
   - `DefiningGeometry` 是原始设计几何，仅包含坐标信息，不包含线条厚度、拉伸变换；
   - `RenderedGeometry` 是最终渲染几何，包含了描边厚度、变换等全部渲染参数，用于精确命中测试。

## 六、方法实现与布局渲染流程

`Line` 没有重写任何布局、渲染相关的方法，`MeasureOverride`、`ArrangeOverride`、`OnRender` 均直接使用 `Shape` 基类的统一实现，完整流程如下：

1. **测量阶段（Measure）**

   布局系统调用基类 `MeasureOverride`，读取 `DefiningGeometry` 的边界，结合 `StrokeThickness`、`Stretch` 模式，计算 Line 元素期望的布局尺寸。

2. **排列阶段（Arrange）**

   布局系统分配最终渲染区域，基类根据区域大小和 `Stretch` 模式，计算缩放与偏移变换，生成 `GeometryTransform`。

3. **渲染阶段（OnRender）**

   渲染系统回调基类 `OnRender` 方法：

   - 将原始 `LineGeometry` 应用几何变换，得到最终渲染几何；
   - 跳过填充绘制（开放图形无填充）；
   - 根据 `Stroke`、`StrokeThickness`、线帽、虚线等参数构造 `Pen` 对象；
   - 调用 `DrawingContext.DrawGeometry` 绘制线条，通过 DirectX 硬件加速输出到屏幕。

4. **属性变更响应**

   任意坐标或描边属性变化时，依赖属性系统自动触发重测 / 重排 / 重绘，无需手动刷新。

## 七、官方设计的核心特点

1. **极简实现**：整个类仅 4 个属性 + 1 个重写属性，代码高度复用，维护成本极低；
2. **密封类设计**：禁止继承，避免派生类破坏渲染逻辑，也便于运行时做内联性能优化；
3. **开放图形特性**：明确区分闭合 / 开放图形，填充属性对开放图形无效，符合几何绘图的底层逻辑；
4. **完全融入框架**：和标准控件一样支持绑定、样式、动画、路由事件，无需特殊处理即可融入 MVVM 架构；
5. **硬件加速**：底层基于 WPF 可视化层渲染，所有直线绘制均走 DirectX 硬件加速，性能远优于 GDI+ 绘图。

## 补充：Line 与 LineGeometry 的区别

| 对比维度 | `Line`（Shape 派生类）     | `LineGeometry`（几何对象）     |
| :------- | :------------------------- | :----------------------------- |
| 类型     | UI 元素，控件级            | 纯数据，图形原语级             |
| 继承     | `FrameworkElement`         | `Geometry`                     |
| 布局能力 | 参与布局系统，有对齐、边距 | 不参与布局，只有坐标数据       |
| 交互能力 | 支持鼠标事件、命中测试     | 无交互能力，仅描述形状         |
| 重量     | 较重，有依赖属性和布局开销 | 极轻量，纯数据                 |
| 适用场景 | UI 层直接展示、交互、绑定  | 底层绘图、自定义图形、几何组合 |

简单来说：`Line` 是 “可以直接放到界面上用的控件”，`LineGeometry` 是 “用来描述直线形状的底层数据”，`Line` 内部就是通过 `LineGeometry` 来定义自身形状的。
