# 999999009-18_工业上位机 NLog 日志完整落地方案

结合工业上位机**实时性优先、7×24 小时运行、故障可追溯、不影响设备 CT**的核心要求，NLog 是目前最成熟、最适配工控场景的日志框架。下面从部署、配置、封装、场景实战、避坑五个维度，给出可直接落地的完整方案。

------

## 一、前期准备：安装与基础部署

### 1. 安装 NuGet 包

项目中安装两个核心包：

plaintext:

```tex
Install-Package NLog          # 核心运行库
Install-Package NLog.Config   # 配置文件模板（也可手动创建）
```

### 2. 配置文件部署

在项目根目录添加 `NLog.config` 文件，**必须设置文件属性：复制到输出目录 → 如果较新则复制**，否则程序运行时找不到配置，日志不会输出。

> 工业现场建议：日志文件不要存 C 盘 / 程序目录，单独放在 D 盘非系统分区，避免系统崩溃后日志丢失。

------

## 二、核心配置文件 NLog.config（工业场景优化版）

这份配置完全贴合工控需求：**全局异步写入不阻塞实时线程、按天自动切割、自动清理 30 天旧日志、错误单独归档、标准工业日志格式**，可直接复制使用。

xaml:

```xaml
<?xml version="1.0" encoding="utf-8" ?>
<nlog xmlns="http://www.nlog-project.org/schemas/NLog.xsd"
      xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
      autoReload="true"            <!-- 配置自动重载，改级别不用重启程序 -->
      internalLogLevel="Warn"      <!-- NLog自身日志级别，排查问题时改Debug -->
      internalLogFile="D:/Logs/nlog-internal.log"> <!-- NLog自身故障日志 -->

  <!-- 全局异步：所有目标全部异步写入，业务线程只提交消息，不阻塞 -->
  <targets async="true">
    <!-- 1. 主运行日志：记录所有级别，按天切割，保留30天 -->
    <target xsi:type="File"
            name="MainLog"
            fileName="D:/Logs/app-${shortdate}.log"
            archiveFileName="D:/Logs/archive/app-{#}.log"
            archiveEvery="Day"               <!-- 按天切割新文件 -->
            archiveNumbering="Date"
            maxArchiveFiles="30"             <!-- 自动删除30天前的旧日志 -->
            maxArchiveDays="30"
            concurrentWrites="false"         <!-- 单进程写，关闭并发提升性能 -->
            keepFileOpen="true"              <!-- 保持文件打开，减少频繁开闭开销 -->
            encoding="utf-8">

      <!-- 工业标准日志格式：时间(毫秒)|级别|线程ID|模块|消息|异常堆栈 -->
      <layout xsi:type="SimpleLayout">
        <text>${longdate} | ${level:uppercase=true:padding=-5} | 线程${threadid:padding=2} | ${event-properties:item=Module:padding=-8} | ${message} ${exception:format=ToString,StackTrace:maxInnerExceptionLevel=5}"/>
      </layout>
    </target>

    <!-- 2. 错误专属日志：只记录Error/Fatal，排查问题直接看这个文件 -->
    <target xsi:type="File"
            name="ErrorLog"
            fileName="D:/Logs/error-${shortdate}.log"
            archiveEvery="Day"
            maxArchiveFiles="90"
            keepFileOpen="true"
            encoding="utf-8">
      <layout xsi:type="SimpleLayout">
        <text>${longdate} | ${level:uppercase=true} | 线程${threadid} | ${event-properties:item=Module} | ${message}
${exception:format=ToString,StackTrace:maxInnerExceptionLevel=5}
----------------------------------------------------------------------"/>
      </layout>
    </target>

    <!-- 3. 控制台输出：开发调试用，生产环境可注释 -->
    <target xsi:type="ColoredConsole"
            name="ConsoleLog"
            layout="${time:format=HH\:mm\:ss.fff} | ${level:uppercase=true:padding=-5} | ${event-properties:item=Module} | ${message}">
    </target>
  </targets>

  <!-- 日志规则：哪些级别输出到哪些目标 -->
  <rules>
    <!-- 主日志：Info及以上写入主文件，Debug生产环境关闭 -->
    <logger name="*" minlevel="Info" writeTo="MainLog" />
    <!-- 错误日志：Error及以上单独归档 -->
    <logger name="*" minlevel="Error" writeTo="ErrorLog" />
    <!-- 控制台：Debug及以上输出，开发用 -->
    <logger name="*" minlevel="Debug" writeTo="ConsoleLog" />
  </rules>
</nlog>
```

### 工业场景关键配置说明

1. **`targets async="true"`**：全局异步是工控场景的核心。相机回调、PLC 实时线程打日志时，只是把消息放进内存队列，立刻返回，不会产生文件 IO 阻塞，完全不拉高 CT。
2. **`autoReload="true"`**：修改配置文件后自动生效，生产环境排查问题时，临时把`minlevel`改成`Debug`，不用重启设备，不影响生产。
3. **`keepFileOpen="true"`**：保持文件句柄打开，避免每秒上百次开闭文件的开销，高帧率场景性能提升明显。
4. **自动归档 + 过期清理**：7×24 小时运行不会占满磁盘，无需人工定期清理。

## 三、封装统一日志工具类（符合工业模块分级规范）

封装一层静态工具类，强制按模块打印、统一格式，业务调用简洁，同时和 NLog 框架解耦，后续换框架不用改业务代码。

csharp:

```c#
using NLog;
using System;

/// <summary>
/// 工业上位机统一日志工具
/// </summary>
public static class LogHelper
{
    private static readonly Logger _logger = LogManager.GetCurrentClassLogger();

    #region 辅助方法：统一添加模块属性
    private static void SetModule(string module)
    {
        ScopeContext.PushProperty("Module", module);
    }
    #endregion

    /// <summary>
    /// 调试日志：开发排查用，生产环境默认关闭
    /// </summary>
    /// <param name="module">模块名：线扫相机/PLC通信/检测算法/MES交互</param>
    /// <param name="message">日志内容</param>
    public static void Debug(string module, string message)
    {
        SetModule(module);
        _logger.Debug(message);
    }

    /// <summary>
    /// 信息日志：关键运行节点、状态切换
    /// </summary>
    public static void Info(string module, string message)
    {
        SetModule(module);
        _logger.Info(message);
    }

    /// <summary>
    /// 警告日志：单次异常、参数超限、隐患提示
    /// </summary>
    public static void Warn(string module, string message)
    {
        SetModule(module);
        _logger.Warn(message);
    }

    /// <summary>
    /// 错误日志：功能失效，必须带异常堆栈
    /// </summary>
    public static void Error(string module, string message, Exception ex = null)
    {
        SetModule(module);
        if (ex == null)
            _logger.Error(message);
        else
            _logger.Error(ex, message);
    }

    /// <summary>
    /// 致命错误：程序崩溃、紧急停机
    /// </summary>
    public static void Fatal(string module, string message, Exception ex)
    {
        SetModule(module);
        _logger.Fatal(ex, message);
    }
}
```

### 使用示例

csharp:

```c#
// 正常信息
LogHelper.Info("线扫相机", "相机初始化成功，分辨率4096*2048");

// 异常错误（必传Exception，自动打印完整堆栈）
LogHelper.Error("PLC通信", "写入M100地址失败", ex);

// 调试信息（生产环境自动关闭）
LogHelper.Debug("检测算法", $"定位结果 X={x:F3} Y={y:F3}");
```

## 四、工业场景专项进阶优化

### 1. 异步队列限流，防止日志爆炸撑爆内存

高帧率场景如果异常疯狂刷屏，内存队列可能持续增长。在`targets`上添加队列限制，队列满了直接丢弃新日志，**优先保证主程序稳定**：

xaml:

```xaml
<targets async="true" 
         queueLimit="5000"       <!-- 队列最大5000条，满了丢弃 -->
         overflowAction="Discard"> <!-- 溢出策略：丢弃新日志，不阻塞主程序 -->
```

### 2. 动态切换日志级别（无需重启程序）

生产环境默认`Info`级别，排查问题时，直接打开`NLog.config`，把规则里的`minlevel`改成`Debug`，保存后 NLog 自动重载，10 秒内生效，不用重启设备。

xaml:

```xaml
<!-- 排查问题时临时改成Debug -->
<logger name="*" minlevel="Debug" writeTo="MainLog" />
```

排查完改回`Info`即可，完全不影响生产运行。

### 3. 添加业务上下文（批次号、工位号）

生产追溯需要关联批次、产品 SN，用`ScopeContext`统一注入，不用每条日志手动拼接：

csharp:

```c#
// 批次开始时设置全局上下文
ScopeContext.PushProperty("BatchNo", "B2026062301");
ScopeContext.PushProperty("StationNo", "ST01");
```

配置布局里添加对应字段：

plaintext:

```tex
${event-properties:item=BatchNo}
```

后续所有日志自动带批次号，无需每条手动传。

### 4. 按模块单独控制日志级别

只给 PLC 通信模块开 Debug，其他模块保持 Info，精准排查单个模块问题，不刷屏：

xaml:

```xaml
<rules>
  <!-- 单独给PLC模块开Debug -->
  <logger name="*" minlevel="Debug" writeTo="MainLog">
    <filters>
      <when condition="equals('${event-properties:item=Module}', 'PLC通信')" action="Log"/>
      <when condition="level < LogLevel.Info" action="Ignore"/>
    </filters>
  </logger>
</rules>
```

## 六、工业上位机 NLog 避坑红线

1. **绝对不要关闭全局异步**

   实时线程同步写文件会产生几毫秒到几十毫秒的随机 IO 阻塞，直接导致相机丢帧、控制超时，优化的 CT 全被日志耗掉。

2. **高频循环禁止打 Info 及以上日志**

   100fps 的相机回调每帧打 Info，一天就是几百万条，既占磁盘又无价值。逐帧细节用 Debug，生产环境默认关闭。

3. **异常必须传完整 Exception 对象**

   不要只打`ex.Message`，把整个`ex`传给 NLog，它会自动输出完整堆栈、内部异常，这是故障排查的核心依据。

   ❌ 错误：`LogHelper.Error("模块", "出错了" + ex.Message);`

   ✅ 正确：`LogHelper.Error("模块", "出错了", ex);`

4. **不要大量拼接字符串**

   回调里拼复杂字符串会产生 GC，造成 CT 尖刺。简单参数直接打，复杂调试信息降级到 Debug 级别。

5. **日志路径不要放系统盘**

   工控机系统崩溃、重装系统时，C 盘日志会全部丢失，必须放在独立数据分区。

6. **程序退出时手动刷新日志**

   程序正常 / 异常退出时，调用`LogManager.Shutdown()`，把内存队列里的剩余日志全部刷到磁盘，防止最后几条关键日志丢失。

## 七、故障排查技巧

如果发现日志不输出，优先排查：

1. 打开配置里的`internalLogFile`，看 NLog 自身报错，90% 的问题是配置文件没复制到输出目录、路径无权限。
2. 检查日志目录权限，工控机管理员账户运行，确保程序有写入权限。
3. 确认`minlevel`设置正确，生产环境默认 Info，Debug 级日志不会输出。
