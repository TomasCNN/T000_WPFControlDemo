# 999999009-26_不同工业场景下的 Log4Net 配置优化方案

Log4Net 是工业上位机领域的老牌日志框架，优势是稳定、生态成熟、历史项目兼容性强；但和 NLog 相比，**原生异步写入、按天自动清理、全局配置热重载**等能力需要通过扩展或组合配置实现，更考验场景化调优能力。

整体优化逻辑和 NLog 一致：围绕「实时性、完整性、可运维性」三个核心维度做权衡，但具体实现方式差异较大。下面针对工控 5 类典型场景，给出可直接落地的配置方案与优化要点，完全贴合线扫视觉、PLC 控制、量产追溯等真实工况。

------

## 前置说明：Log4Net 核心基础配置差异

和 NLog 相比，工业场景必须先明确 4 个关键差异：

1. **异步实现**：原生无全局异步开关，高速场景需安装 `Log4Net.Async` 包使用 `AsyncForwardingAppender`（真正后台线程异步），或用原生 `BufferingForwardingAppender` 做批量写入减少 IO。
2. **滚动切割**：`RollingFileAppender` 通过 `RollingStyle` 控制切割策略，按天切割必须配合 `DatePattern` + `StaticLogFileName=false` 才能正常生效。
3. **过期清理**：原生仅支持 `MaxSizeRollBackups` 按文件数量兜底，不支持按天数自动删除旧日志，长周期清理需要业务层扩展或脚本辅助。
4. **热重载**：通过 `XmlConfigurator.ConfigureAndWatch()` 监听配置文件变更，实现修改不重启生效。

## 一、高速视觉采集场景（线扫 / 面阵相机、高帧率取图）

### 场景特点

线扫相机 50~100fps 采集回调，CT 要求严苛，日志绝对不能阻塞采集线程；逐帧日志量大，普通信息优先级低，错误信息必须完整留存。

### 核心优先级

**实时性 > 性能 > 普通日志完整性**

### 优化关键要点

1. **强制异步写入**：使用 `AsyncForwardingAppender` 包装文件输出，采集线程仅将消息推入内存队列，耗时微秒级，完全不碰磁盘 IO。
2. **分级丢失策略**：普通 Debug/Info 日志队列满时可丢弃，优先保障主程序；Error/Fatal 级日志强制不丢失。
3. **禁用高开销字段**：生产环境移除 `%location`、`%stacktrace` 等反射类字段，这类字段单条日志开销是普通字段的几十倍，会显著拉高 CT。
4. **批量写入降 IO**：原生场景用 `BufferingForwardingAppender` 攒够一批再写盘，减少磁盘 IO 次数。
5. **独占文件锁**：单进程写入使用 `ExclusiveLock` 锁模型，去掉并发锁开销，写入性能提升 30% 以上。

### 配置示例（异步版，需安装 `Log4Net.Async` NuGet 包）

xaml:

```xaml
<log4net>
  <!-- 高速视觉异步队列：队列满丢弃低级日志，保障采集线程 -->
  <appender name="CameraAsyncAppender" type="Log4Net.Async.AsyncForwardingAppender, Log4Net.Async">
    <bufferSize value="5000" />
    <lossy value="true" />
    <evaluator type="log4net.Core.LevelEvaluator">
      <threshold value="ERROR" />
    </evaluator>
    <appender-ref ref="CameraRollingFile" />
  </appender>

  <!-- 视觉日志文件：按天切割，保留30个文件兜底 -->
  <appender name="CameraRollingFile" type="log4net.Appender.RollingFileAppender">
    <file value="D:/Logs/AOI/camera.log" />
    <appendToFile value="true" />
    <rollingStyle value="Date" />
    <datePattern value="yyyyMMdd'.log'" />
    <staticLogFileName value="false" />
    <maxSizeRollBackups value="30" />
    <encoding value="utf-8" />
    <!-- 单进程独占锁，提升写入性能 -->
    <lockingModel type="log4net.Appender.FileAppender+ExclusiveLock" />
    <!-- 极简布局：移除所有高开销字段 -->
    <layout type="log4net.Layout.PatternLayout">
      <conversionPattern value="%date{yyyy-MM-dd HH:mm:ss.fff} | %-5level | 线程%thread | %message%newline%exception" />
    </layout>
  </appender>

  <!-- 相机模块日志走异步队列 -->
  <logger name="线扫相机">
    <level value="DEBUG" />
    <appender-ref ref="CameraAsyncAppender" />
  </logger>
</log4net>
```

### 业务代码约束

- 逐帧图像信息仅打 `Debug` 级别，生产环境可通过配置关闭，零性能开销；
- 仅异常、连续超时等关键事件打 `Error/Warn`；
- 性能统计按间隔输出（如每 50 帧一次），禁止逐帧打 Info。

## 二、PLC 实时控制场景（运动控制、IO 轮询）

### 场景特点

PLC 周期扫描 10~20ms，控制周期抖动要求严格；普通通信日志量大价值低，通信错误、控制异常必须完整留痕，用于故障追责。

### 核心优先级

**控制线程零阻塞 > 错误日志不丢失 > 普通日志完整性**

### 优化关键要点

1. **独立异步队列隔离**：控制模块单独分配异步队列，和视觉日志物理隔离，避免高优先级控制日志被海量视觉日志挤压。
2. **级别过滤分流**：用 `LevelRangeFilter` 将 Info/Warn 运行日志和 Error/Fatal 错误日志拆分到两个文件，排查问题直接看错误文件。
3. **普通读写降级**：单次寄存器读写仅打 `Debug`，生产环境不输出；单次失败打 `Warn`，连续失败打 `Error`，控制日志量级。
4. **参数化日志**：使用格式化占位符传递参数，避免字符串拼接产生临时对象，减少 GC 加剧周期抖动。

### 配置示例

xaml:

```xaml
<log4net>
  <!-- PLC控制独立异步队列 -->
  <appender name="PlcAsyncAppender" type="Log4Net.Async.AsyncForwardingAppender, Log4Net.Async">
    <bufferSize="3000" />
    <lossy value="false" /> <!-- 控制日志不丢弃 -->
    <appender-ref ref="PlcRunFile" />
    <appender-ref ref="ErrorOnlyFile" />
  </appender>

  <!-- PLC运行日志：Info-Warn级别 -->
  <appender name="PlcRunFile" type="log4net.Appender.RollingFileAppender">
    <file value="D:/Logs/PLC/plc_run.log" />
    <rollingStyle value="Date" />
    <datePattern value="yyyyMMdd'.log'" />
    <staticLogFileName value="false" />
    <maxSizeRollBackups value="30" />
    <encoding value="utf-8" />
    <filter type="log4net.Filter.LevelRangeFilter">
      <levelMin value="INFO" />
      <levelMax value="WARN" />
    </filter>
    <layout type="log4net.Layout.PatternLayout">
      <conversionPattern value="%date{HH:mm:ss.fff} | %-5level | %message%newline" />
    </layout>
  </appender>

  <!-- 全局错误日志：所有模块Error-Fatal都进这里，保留90个文件 -->
  <appender name="ErrorOnlyFile" type="log4net.Appender.RollingFileAppender">
    <file value="D:/Logs/Common/error.log" />
    <rollingStyle value="Date" />
    <datePattern value="yyyyMMdd'.log'" />
    <staticLogFileName value="false" />
    <maxSizeRollBackups value="90" />
    <encoding value="utf-8" />
    <filter type="log4net.Filter.LevelRangeFilter">
      <levelMin value="ERROR" />
      <levelMax value="FATAL" />
    </filter>
    <layout type="log4net.Layout.PatternLayout">
      <conversionPattern value="%date{yyyy-MM-dd HH:mm:ss.fff} | %level | %logger | %message%newline%exception
------------------------------------------------------------------------%newline" />
    </layout>
  </appender>

  <logger name="PLC通信">
    <level value="INFO" />
    <appender-ref ref="PlcAsyncAppender" />
  </logger>
</log4net>
```

## 三、量产追溯与合规审计场景（GMP / 行业合规要求）

### 场景特点

量产检测工位，需满足合规审计要求，参数修改、批次切换、人工操作必须留痕，日志长期保存，不可篡改。

### 核心优先级

**日志完整可追溯 > 防篡改 > 性能**

### 优化关键要点

1. **审计日志物理隔离**：单独配置 Appender，仅记录操作审计类日志，和运行日志完全分离，审计时直接调取。
2. **业务上下文透传**：通过 `LogicalThreadContext.Properties` 注入批次号、操作员、工位号，所有日志自动携带业务上下文，无需每条手动拼接。
3. **双重滚动策略**：`Composite` 模式同时按日期 + 文件大小切割，防止单日日志过大；增大备份数量兜底。
4. **防篡改配套**：日志目录设置 NTFS 「仅追加」权限，禁止修改删除历史文件；定期生成文件哈希校验。

### 配置 + 代码示例

#### 配置片段

xaml:

```xaml
<appender name="AuditFileAppender" type="log4net.Appender.RollingFileAppender">
  <file value="D:/Logs/Audit/audit.log" />
  <rollingStyle value="Composite" />
  <datePattern value="yyyyMMdd'.log'" />
  <maximumFileSize value="100MB" />
  <staticLogFileName value="false" />
  <maxSizeRollBackups value="180" /> <!-- 保留180个文件兜底 -->
  <encoding value="utf-8" />
  <!-- 仅模块名为「操作审计」的日志通过 -->
  <filter type="log4net.Filter.LoggerMatchFilter">
    <loggerToMatch value="操作审计" />
    <acceptOnMatch value="true" />
  </filter>
  <filter type="log4net.Filter.DenyAllFilter" />
  <layout type="log4net.Layout.PatternLayout">
    <conversionPattern value="%date{yyyy-MM-dd HH:mm:ss.fff} | 操作员：%property{Operator} | 批次：%property{BatchNo} | %message%newline" />
  </layout>
</appender>
```

#### 业务代码注入上下文

csharp:

```c#
// 批次开始时全局注入上下文，后续所有日志自动携带
LogicalThreadContext.Properties["BatchNo"] = "B2026062301";
LogicalThreadContext.Properties["Operator"] = "OP001";

// 记录审计日志
ILog auditLog = LogManager.GetLogger("操作审计");
auditLog.Info($"修改缺陷检测阈值：旧值0.85 → 新值0.90，修改成功");
```

## 四、7×24 小时无人值守场景（黑灯产线、无人工作站）

### 场景特点

连续数月不关机，现场无运维人员，核心要求是绝对不能因为日志导致磁盘爆满、程序崩溃。

### 核心优先级

**磁盘不爆满 > 程序稳定 > 日志完整性**

### 优化关键要点

1. **双重滚动切割**：`Composite` 模式同时按自然天 + 文件大小切割，防止单日异常刷屏瞬间写满磁盘。
2. **数量兜底限制**：`MaxSizeRollBackups` 设置最大文件总数，作为磁盘空间的最后一道防线。
3. **崩溃强制刷盘**：全局未捕获异常中调用 `LogManager.Shutdown()`，将异步队列剩余日志全部刷入磁盘，保留故障现场。
4. **业务层兜底监控**：定时检测磁盘剩余空间，低于 10% 触发告警并清理最旧日志，弥补原生不支持按天删除的短板。

> 注意：Log4Net 原生不支持按天数自动删除旧日志，仅支持按文件数量限制。工业场景建议配合简单的定时任务，删除 30 天前的 .log 文件，实现按天过期清理。

### 配置示例

xaml:

```xaml
<appender name="MainRunAppender" type="log4net.Appender.RollingFileAppender">
  <file value="D:/Logs/Unmanned/app.log" />
  <appendToFile value="true" />
  <!-- 双重切割：按天 + 单文件100MB -->
  <rollingStyle value="Composite" />
  <datePattern value="yyyyMMdd" />
  <maximumFileSize value="100MB" />
  <staticLogFileName value="false" />
  <!-- 最多保留100个文件，兜底磁盘空间 -->
  <maxSizeRollBackups value="100" />
  <preserveLogFileNameExtension value="true" />
  <encoding value="utf-8" />
  <lockingModel type="log4net.Appender.FileAppender+ExclusiveLock" />
  <layout type="log4net.Layout.PatternLayout">
    <conversionPattern value="%date{yyyy-MM-dd HH:mm:ss.fff} | %-5level | 线程%thread | %logger | %message%newline%exception" />
  </layout>
</appender>
```

### 崩溃兜底代码

csharp:

```c#
// 程序入口绑定全局未捕获异常
AppDomain.CurrentDomain.UnhandledException += (sender, e) =>
{
    var ex = e.ExceptionObject as Exception;
    ILog fatalLog = LogManager.GetLogger("主程序");
    fatalLog.Fatal("全局未捕获异常，程序紧急退出", ex);
    LogManager.Shutdown(); // 强制刷盘，落定所有异步日志
};
```

## 五、现场免重启排障场景（量产线不停机调试）

### 场景特点

量产线不能随意停机重启，偶发故障复现概率低，需要临时开启 Debug 日志定位问题，不中断生产。

### 核心优先级

**灵活可控 > 精准过滤 > 不影响生产**

### 优化关键要点

1. **开启配置热重载**：初始化时调用 `XmlConfigurator.ConfigureAndWatch()`，监听配置文件变化，修改后几秒内自动生效，无需重启程序。
2. **模块级粒度控制**：通过 `<logger>` 节点单独指定某模块的日志级别，只给出问题的模块开 Debug，其他模块保持 Info，避免刷屏。
3. **属性过滤器精准定位**：可通过 `PropertyFilter` 只打印指定批次、指定工位的日志，进一步缩小排查范围。

### 初始化代码（启用热重载）

csharp:

```c#
// 程序启动时加载配置并开启文件监听
FileInfo configFile = new FileInfo("log4net.config");
XmlConfigurator.ConfigureAndWatch(configFile);
```

### 临时排障配置示例（仅 PLC 模块开 Debug）

xaml:

```xaml
<log4net>
  <!-- 全局默认Info级别 -->
  <root>
    <level value="INFO" />
    <appender-ref ref="MainRunAppender" />
  </root>

  <!-- 排障时临时添加：仅PLC通信模块开启Debug -->
  <logger name="PLC通信">
    <level value="DEBUG" />
  </logger>
</log4net>
```

排障结束后删除该 logger 节点，保存文件自动恢复 Info 级别，全程无需停机。

## 全场景通用优化建议

1. **日志路径统一放非系统盘**：如 `D:/Logs/`，避免系统崩溃重装后日志丢失，也不占用系统盘空间。
2. **统一 UTF-8 编码**：防止工控机多语言环境下中文乱码。
3. **单进程用独占锁**：`ExclusiveLock` 比默认的 `MinimalLock` 写入性能更高，单进程场景优先使用。
4. **生产环境禁用高开销字段**：`%location`、`%stacktrace`、`%method` 等反射类字段开销极大，仅排障时临时开启。
5. **程序退出强制刷盘**：正常关闭、异常退出都调用 `LogManager.Shutdown()`，避免异步队列日志丢失。

## 工业场景避坑红线

1. ❌ **实时线程使用同步写入**：相机回调、控制线程直接写文件，CT 飙升、控制抖动，得不偿失。
2. ❌ **按天切割配置错误**：只设 `RollingStyle=Date` 但不设 `StaticLogFileName=false`，会导致日志无法正常按天切割。
3. ❌ **误以为按天数自动清理**：`MaxSizeRollBackups` 是限制文件总数，不是按天数保留，原生不支持按天过期，需额外补充清理逻辑。
4. ❌ **高频场景滥用 `%location`**：获取调用位置的反射开销是普通日志的几十倍，生产环境必须关闭。
5. ❌ **所有日志塞一个文件**：运行、错误、审计混放，故障排查效率极低。

## 视觉检测工位完整组合配置推荐

结合线扫相机 + PLC 控制的典型视觉检测场景，推荐组合方案：

1. 相机模块走独立异步队列，逐帧 Debug 生产默认关闭，错误不丢失；
2. PLC 控制模块独立异步，运行日志和错误日志物理分离；
3. 操作审计单独归档，满足追溯要求；
4. 开启配置热重载，现场排障无需停机；
5. 复合滚动 + 文件数量兜底，保障 7×24 小时稳定运行。
