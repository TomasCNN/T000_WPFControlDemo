# 999999006-12_C# 自定义特性完整指南：从基础到工业级实战

自定义特性是 C# 元数据编程的核心能力，它允许你创建自己的声明式标签，将自定义元数据与代码元素关联。结合反射和源生成器，自定义特性可以实现从简单的代码标记到复杂的编译时代码生成的各种功能。

本文将从最基础的语法开始，逐步深入到工业级应用的最佳实践，帮助你全面掌握自定义特性的开发和使用。

## 一、特性的本质回顾

在开始自定义特性之前，我们再次明确特性的本质：

- 特性本质上是一个**继承自`System.Attribute`的类**
- 特性实例在**第一次被反射读取时**才会被创建
- 特性的参数和属性值在**编译时**被序列化存储在程序集元数据中
- 特性本身不包含任何执行逻辑，它只是一个**数据容器**

## 二、自定义特性的基本步骤

### 2.1 第一步：定义特性类

所有自定义特性都必须直接或间接继承自`System.Attribute`类。按照惯例，特性类的名称应该以`Attribute`结尾。

csharp:

```c#
// 最简单的自定义特性
public class SimpleAttribute : Attribute
{
}
```

### 2.2 第二步：添加`AttributeUsage`特性

`AttributeUsage`是一个用于描述特性如何使用的特性，它是自定义特性中最重要的部分。

csharp:

```c#
[AttributeUsage(
    AttributeTargets.Class | AttributeTargets.Method, // 可以应用到哪些代码元素
    Inherited = true, // 是否可以被继承
    AllowMultiple = false)] // 是否允许在同一个元素上多次应用
public class MyCustomAttribute : Attribute
{
}
```

#### `AttributeUsage`参数详解

| 参数            | 类型               | 说明                                     | 默认值  |
| :-------------- | :----------------- | :--------------------------------------- | :------ |
| `ValidOn`       | `AttributeTargets` | 指定特性可以应用到哪些代码元素           | `All`   |
| `Inherited`     | `bool`             | 指示特性是否可以被派生类继承             | `true`  |
| `AllowMultiple` | `bool`             | 指示是否允许在同一个元素上多次应用该特性 | `false` |

#### `AttributeTargets`枚举常用值

| 值            | 说明               |
| :------------ | :----------------- |
| `Class`       | 可以应用到类       |
| `Method`      | 可以应用到方法     |
| `Property`    | 可以应用到属性     |
| `Field`       | 可以应用到字段     |
| `Enum`        | 可以应用到枚举     |
| `Constructor` | 可以应用到构造函数 |
| `Parameter`   | 可以应用到参数     |
| `ReturnValue` | 可以应用到返回值   |
| `Assembly`    | 可以应用到程序集   |
| `Module`      | 可以应用到模块     |
| `All`         | 可以应用到任何元素 |

### 2.3 第三步：定义构造函数和属性

特性类可以有构造函数和属性，用于接收和存储元数据。

csharp:

```c#
[AttributeUsage(AttributeTargets.Class | AttributeTargets.Method)]
public class DescriptionAttribute : Attribute
{
    // 构造函数参数：必须在使用特性时提供
    public DescriptionAttribute(string text)
    {
        Text = text;
    }

    // 只读属性：存储构造函数传入的值
    public string Text { get; }

    // 可选的命名参数：使用特性时可以选择性指定
    public int Version { get; set; } = 1;

    public string Author { get; set; } = "Unknown";
}
```

### 2.4 第四步：使用自定义特性

定义好特性后，就可以像使用内置特性一样使用它了。

csharp:

```c#
// 使用特性，传入构造函数参数
[Description("这是一个测试类", Version = 2, Author = "张三")]
public class TestClass
{
    // 在方法上使用特性
    [Description("这是一个测试方法")]
    public void TestMethod()
    {
    }
}
```

## 三、特性参数的限制

特性参数有一个非常重要的限制：**只能是编译时常量**。这意味着你只能使用以下类型作为特性参数：

- 基本数据类型：`bool`, `byte`, `char`, `double`, `float`, `int`, `long`, `sbyte`, `short`, `uint`, `ulong`, `ushort`
- `string`
- `enum`
- `Type`
- `object`
- 以上类型的一维数组

❌ 错误示例：不能使用非编译时常量作为参数

csharp:

```c#
// 编译错误：特性参数必须是编译时常量
[MyAttribute(DateTime.Now)] 
public class TestClass { }

// 编译错误：不能使用自定义类作为参数
[MyAttribute(new MyClass())] 
public class TestClass { }
```

✅ 正确示例：

csharp:

```c#
[MyAttribute("Hello", 123, MyEnum.Value1, typeof(int))]
public class TestClass { }
```

## 四、读取自定义特性

定义和使用特性只是第一步，真正的价值在于在运行时通过反射读取这些特性。

### 4.1 常用的读取方法

#### 1. `Attribute.GetCustomAttribute`

获取单个指定类型的特性，这是最常用的方法。

csharp:

```c#
// 读取类上的特性
var classAttribute = Attribute.GetCustomAttribute(
    typeof(TestClass), 
    typeof(DescriptionAttribute)) as DescriptionAttribute;

if (classAttribute != null)
{
    Console.WriteLine($"类描述：{classAttribute.Text}");
    Console.WriteLine($"版本：{classAttribute.Version}");
    Console.WriteLine($"作者：{classAttribute.Author}");
}

// 读取方法上的特性
var method = typeof(TestClass).GetMethod("TestMethod");
var methodAttribute = Attribute.GetCustomAttribute(
    method, 
    typeof(DescriptionAttribute)) as DescriptionAttribute;

if (methodAttribute != null)
{
    Console.WriteLine($"方法描述：{methodAttribute.Text}");
}
```

#### 2. `GetCustomAttributes`

获取所有特性或指定类型的所有特性。

csharp:

```c#
// 获取类上的所有特性
object[] allAttributes = typeof(TestClass).GetCustomAttributes(true);

// 获取类上指定类型的所有特性
object[] descriptionAttributes = typeof(TestClass).GetCustomAttributes(
    typeof(DescriptionAttribute), true);
```

#### 3. `IsDefined`

检查是否定义了指定类型的特性，性能最好，因为它不需要实例化特性对象。

csharp:

```c#
// 检查类上是否定义了DescriptionAttribute
bool hasDescription = Attribute.IsDefined(
    typeof(TestClass), 
    typeof(DescriptionAttribute));

if (hasDescription)
{
    // 只有在存在特性时才读取
    var attribute = Attribute.GetCustomAttribute(
        typeof(TestClass), 
        typeof(DescriptionAttribute)) as DescriptionAttribute;
}
```

### 4.2 不同代码元素上的特性读取

#### 读取属性上的特性

csharp:

```c#
var property = typeof(TestClass).GetProperty("TestProperty");
var attribute = property.GetCustomAttribute<DescriptionAttribute>();
```

#### 读取枚举值上的特性

csharp:

```c#
public enum MyEnum
{
    [Description("第一个值")]
    Value1,
    
    [Description("第二个值")]
    Value2
}

// 读取枚举值上的特性
var field = typeof(MyEnum).GetField(MyEnum.Value1.ToString());
var attribute = field.GetCustomAttribute<DescriptionAttribute>();
Console.WriteLine(attribute.Text); // 输出：第一个值
```

#### 读取参数上的特性

csharp:

```c#
public void TestMethod([Description("参数描述")] int param)
{
}

var method = typeof(TestClass).GetMethod("TestMethod");
var parameter = method.GetParameters()[0];
var attribute = parameter.GetCustomAttribute<DescriptionAttribute>();
```

## 五、高级特性用法

### 5.1 允许多次应用特性

将`AllowMultiple`设置为`true`，就可以在同一个元素上多次应用同一个特性。

csharp:

```c#
[AttributeUsage(AttributeTargets.Class, AllowMultiple = true)]
public class AuthorAttribute : Attribute
{
    public string Name { get; }
    
    public AuthorAttribute(string name)
    {
        Name = name;
    }
}

// 多次应用特性
[Author("张三")]
[Author("李四")]
public class TestClass
{
}

// 读取所有特性
var authors = typeof(TestClass).GetCustomAttributes<AuthorAttribute>();
foreach (var author in authors)
{
    Console.WriteLine($"作者：{author.Name}");
}
```

### 5.2 特性的继承

`Inherited`参数控制特性是否可以被派生类继承。

csharp:

```c#
[AttributeUsage(AttributeTargets.Class, Inherited = true)]
public class BaseAttribute : Attribute
{
}

[Base]
public class BaseClass
{
}

// DerivedClass会继承BaseClass上的BaseAttribute
public class DerivedClass : BaseClass
{
}

// 检查派生类是否有该特性
bool hasAttribute = Attribute.IsDefined(typeof(DerivedClass), typeof(BaseAttribute));
Console.WriteLine(hasAttribute); // 输出：True
```

如果将`Inherited`设置为`false`，则派生类不会继承基类上的特性。

### 5.3 条件特性

使用`ConditionalAttribute`可以创建条件特性，这些特性只有在定义了指定的编译符号时才会被包含在元数据中。

csharp:

```c#
#define DEBUG

using System.Diagnostics;

[Conditional("DEBUG")]
public class DebugOnlyAttribute : Attribute
{
}

// 只有在定义了DEBUG符号时，这个特性才会被编译
[DebugOnly]
public class TestClass
{
}
```

这在调试和测试代码中非常有用，可以让调试相关的特性只在调试版本中存在。

### 5.4 全局特性

特性不仅可以应用到类、方法等代码元素，还可以应用到整个程序集或模块。

csharp:

```c#
// 在AssemblyInfo.cs文件中
[assembly: AssemblyTitle("我的应用程序")]
[assembly: AssemblyDescription("这是一个测试应用程序")]
[assembly: AssemblyVersion("1.0.0.0")]

// 自定义全局特性
[assembly: MyGlobalAttribute("这是一个全局特性")]
```

读取程序集级别的特性：

csharp:

```c#
var assembly = Assembly.GetExecutingAssembly();
var attribute = assembly.GetCustomAttribute<MyGlobalAttribute>();
```

### 5.5 特性目标显式指定

在某些情况下，需要显式指定特性的应用目标。

csharp:

```c#
// 应用到返回值
[return: Description("方法返回值")]
public int TestMethod()
{
    return 0;
}

// 应用到参数
public void TestMethod([param: Description("方法参数")] int param)
{
}

// 应用到字段
[field: NonSerialized]
public string MyField;
```

## 六、自定义特性的最佳实践

### 6.1 特性类应该是密封的

将特性类声明为`sealed`可以提高性能，因为 CLR 在查找特性时不需要考虑继承链。

csharp

```c#
// 好
public sealed class MyAttribute : Attribute
{
}

// 不好
public class MyAttribute : Attribute
{
}
```

### 6.2 避免在构造函数中执行复杂逻辑

特性构造函数中的代码会在**第一次读取特性时**执行，这可能导致意外的性能问题和行为。

csharp:

```c#
// 不好：在构造函数中执行复杂逻辑
public sealed class BadAttribute : Attribute
{
    public BadAttribute()
    {
        // 复杂的计算或IO操作
        File.ReadAllText("config.txt");
    }
}

// 好：只在构造函数中进行简单的赋值
public sealed class GoodAttribute : Attribute
{
    public GoodAttribute(string value)
    {
        Value = value;
    }
    
    public string Value { get; }
}
```

### 6.3 合理使用`AttributeUsage`

始终为你的特性添加`AttributeUsage`特性，并明确指定它可以应用到哪些元素、是否可继承、是否允许多次应用。这可以防止特性被误用，并提高代码的可读性。

### 6.4 性能考虑

- 优先使用`IsDefined`检查特性是否存在，只有在需要时才读取特性实例
- 缓存特性实例，避免重复反射
- 在性能敏感的场景中，考虑使用源生成器在编译时处理特性，完全避免运行时反射

### 6.5 命名规范

- 特性类名称以`Attribute`结尾
- 使用描述性的名称，清晰表达特性的用途
- 特性的属性使用 PascalCase 命名法

## 七、工业级实战：设备参数验证特性

下面是一个完整的工业自动化场景下的自定义特性示例，实现了一个设备参数验证特性，可以自动验证设备参数的取值范围。

### 7.1 定义验证特性

csharp:

```c#
using System;
using System.Reflection;

namespace IndustrialAutomation.Validation
{
    /// <summary>
    /// 设备参数验证特性
    /// 用于验证设备参数的取值范围
    /// </summary>
    [AttributeUsage(AttributeTargets.Property, AllowMultiple = false)]
    public sealed class ParameterValidationAttribute : Attribute
    {
        /// <summary>
        /// 最小值
        /// </summary>
        public double MinValue { get; }
        
        /// <summary>
        /// 最大值
        /// </summary>
        public double MaxValue { get; }
        
        /// <summary>
        /// 错误消息
        /// </summary>
        public string ErrorMessage { get; set; }
        
        /// <summary>
        /// 是否允许为null
        /// </summary>
        public bool AllowNull { get; set; }

        /// <summary>
        /// 构造函数
        /// </summary>
        /// <param name="minValue">最小值</param>
        /// <param name="maxValue">最大值</param>
        public ParameterValidationAttribute(double minValue, double maxValue)
        {
            MinValue = minValue;
            MaxValue = maxValue;
            ErrorMessage = $"参数值必须在 {minValue} 和 {maxValue} 之间";
        }

        /// <summary>
        /// 验证参数值
        /// </summary>
        /// <param name="value">要验证的值</param>
        /// <returns>验证是否通过</returns>
        public bool Validate(object value)
        {
            if (value == null)
                return AllowNull;

            try
            {
                double numValue = Convert.ToDouble(value);
                return numValue >= MinValue && numValue <= MaxValue;
            }
            catch
            {
                return false;
            }
        }
    }
}
```

### 7.2 定义设备参数类

csharp:

```c#
namespace IndustrialAutomation.Devices
{
    /// <summary>
    /// 温度控制器参数
    /// </summary>
    public class TemperatureControllerParams
    {
        [ParameterValidation(0, 100, 
            ErrorMessage = "设定温度必须在0°C到100°C之间")]
        public double Setpoint { get; set; }

        [ParameterValidation(0.1, 10.0, 
            ErrorMessage = "比例系数必须在0.1到10.0之间")]
        public double Kp { get; set; } = 1.0;

        [ParameterValidation(0.01, 1.0, 
            ErrorMessage = "积分时间必须在0.01到1.0之间")]
        public double Ki { get; set; } = 0.1;

        [ParameterValidation(0.001, 0.1, 
            ErrorMessage = "微分时间必须在0.001到0.1之间")]
        public double Kd { get; set; } = 0.01;
    }
}
```

### 7.3 实现验证器

csharp:

```c#
using System;
using System.Collections.Generic;
using System.Reflection;

namespace IndustrialAutomation.Validation
{
    /// <summary>
    /// 参数验证器
    /// </summary>
    public static class ParameterValidator
    {
        /// <summary>
        /// 验证对象的所有属性
        /// </summary>
        /// <param name="obj">要验证的对象</param>
        /// <returns>验证结果</returns>
        public static ValidationResult Validate(object obj)
        {
            if (obj == null)
                throw new ArgumentNullException(nameof(obj));

            var result = new ValidationResult();
            var properties = obj.GetType().GetProperties(BindingFlags.Public | BindingFlags.Instance);

            foreach (var property in properties)
            {
                var attribute = property.GetCustomAttribute<ParameterValidationAttribute>();
                if (attribute == null)
                    continue;

                var value = property.GetValue(obj);
                if (!attribute.Validate(value))
                {
                    result.AddError(property.Name, attribute.ErrorMessage);
                }
            }

            return result;
        }
    }

    /// <summary>
    /// 验证结果
    /// </summary>
    public class ValidationResult
    {
        private readonly List<ValidationError> _errors = new();

        public bool IsValid => _errors.Count == 0;

        public IReadOnlyList<ValidationError> Errors => _errors.AsReadOnly();

        public void AddError(string propertyName, string errorMessage)
        {
            _errors.Add(new ValidationError(propertyName, errorMessage));
        }
    }

    /// <summary>
    /// 验证错误
    /// </summary>
    public class ValidationError
    {
        public string PropertyName { get; }
        public string ErrorMessage { get; }

        public ValidationError(string propertyName, string errorMessage)
        {
            PropertyName = propertyName;
            ErrorMessage = errorMessage;
        }

        public override string ToString()
        {
            return $"{PropertyName}: {ErrorMessage}";
        }
    }
}
```

### 7.4 使用验证器

csharp:

```c#
using System;
using IndustrialAutomation.Devices;
using IndustrialAutomation.Validation;

namespace IndustrialAutomation
{
    class Program
    {
        static void Main(string[] args)
        {
            var parameters = new TemperatureControllerParams
            {
                Setpoint = 120, // 超出范围
                Kp = 0.05, // 超出范围
                Ki = 0.5,
                Kd = 0.02
            };

            var result = ParameterValidator.Validate(parameters);

            if (!result.IsValid)
            {
                Console.WriteLine("参数验证失败：");
                foreach (var error in result.Errors)
                {
                    Console.WriteLine($"  {error}");
                }
            }
            else
            {
                Console.WriteLine("参数验证成功");
            }
        }
    }
}
```

## 八、自定义特性与源生成器结合

自定义特性最强大的用法是与源生成器结合，在编译时读取特性并自动生成代码。这可以完全避免运行时的反射开销，同时保留特性的声明式编程优势。

例如，我们之前开发的 Modbus 源生成器就是基于自定义特性实现的：

- 定义`ModbusRegisterAttribute`特性标记寄存器映射
- 源生成器在编译时扫描所有标记了该特性的类
- 自动生成高性能的解析代码
- 运行时零反射，性能接近手写代码

这种模式在工业自动化领域非常有用，可以大大提高开发效率和系统性能。

## 总结

自定义特性是 C# 中最强大的元数据编程工具之一，它允许你以声明式的方式将自定义元数据与代码元素关联。掌握自定义特性的开发和使用，可以让你写出更加简洁、灵活和可维护的代码。

### 核心要点回顾

1. 自定义特性必须继承自`System.Attribute`类
2. 使用`AttributeUsage`特性指定特性的使用规则
3. 特性参数只能是编译时常量
4. 通过反射在运行时读取特性
5. 特性类应该是密封的，避免在构造函数中执行复杂逻辑
6. 结合源生成器可以实现编译时代码生成，完全避免运行时反射

### 什么时候应该创建自定义特性

- 当你需要为代码元素添加声明性元数据时
- 当你需要实现横切关注点（如验证、日志、权限）时
- 当你需要减少重复代码和配置时
- 当你需要实现框架级别的扩展能力时
- 当你需要与源生成器结合自动生成代码时
