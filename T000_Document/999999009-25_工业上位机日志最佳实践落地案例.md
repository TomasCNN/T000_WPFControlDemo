# 999999009-25_工业上位机日志最佳实践落地案例

工业上位机日志的核心价值是**运行时零干扰，故障时可追溯**，所有最佳实践都来自真实产线的踩坑沉淀。以下分享 5 个工控领域高频场景的完整落地案例，全部基于 NLog 实现，可直接复用到视觉检测、运动控制、合规追溯等项目中，完全贴合线扫相机、PLC 通信、量产追溯等真实工况。

## 案例一：高速线扫 AOI 视觉检测工位（高帧率、低 CT 要求）

### 场景背景

PCB 板缺陷检测线，12K 线扫相机，帧率 80fps，单帧图像处理耗时要求 <10ms，取图回调绝对不能被日志阻塞，否则会出现相机丢帧、检测漏件，对应你当前优化取图 CT 的核心场景。

### 核心痛点

1. 最初使用同步写日志，单条日志 IO 耗时 3~15ms，直接吃掉一半以上的 CT 余量，偶发丢帧；
2. 逐帧打印图像信息，一天产生几百万条日志，磁盘占用飙升，错误信息被普通日志淹没；
3. 出问题时要在百万行日志里翻找错误，排查效率极低。

### 落地最佳实践

1. **全局异步写入，溢出策略强制丢弃**：采集线程仅将消息推入内存队列，耗时微秒级；队列满时优先保障生产，丢弃非关键日志，绝不阻塞采集线程。
2. **日志分级降级**：逐帧图像信息全部设为 `Debug` 级别，生产环境默认关闭，零性能开销；仅错误、告警强制输出。
3. **错误日志独立归档**：`Error/Fatal` 单独存入专属文件，排查问题第一时间打开错误日志即可。
4. **性能统计间隔输出**：每 50 帧输出一次平均耗时，代替逐帧打印，既监控性能又不刷屏。

### 核心配置片段

xaml:

```xaml
<targets async="true" 
         queueLimit="5000" 
         overflowAction="Discard" 
         batchSize="200"
         timeToSleepBetweenBatches="1">

  <!-- 主运行日志：Info及以上，保留30天 -->
  <target xsi:type="File" name="CameraRunLog"
          fileName="D:/Logs/AOI/camera-${shortdate}.log"
          archiveEvery="Day" maxArchiveDays="30"
          keepFileOpen="true" concurrentWrites="false" encoding="utf-8">
    <layout>${longdate} | ${level:uppercase=true} | 线程${threadid} | ${message} ${exception:format=ToString}</layout>
  </target>

  <!-- 错误专属日志：单独归档，保留90天 -->
  <target xsi:type="File" name="ErrorLog"
          fileName="D:/Logs/AOI/error-${shortdate}.log"
          archiveEvery="Day" maxArchiveDays="90"
          keepFileOpen="true" encoding="utf-8">
    <layout>${longdate} | ${level} | ${event-properties:item=Module} | ${message}
${exception:format=ToString,StackTrace}
------------------------------------------------------------------------</layout>
  </target>
</targets>

<rules>
  <logger name="*" minlevel="Info" writeTo="CameraRunLog" />
  <logger name="*" minlevel="Error" writeTo="ErrorLog" />
</rules>
```

- 日志文件体积减少 80%，故障排查时间从平均 1 小时缩短到 5 分钟；
- 生产环境稳定运行 3 个月，无日志导致的性能卡顿问题。

## 案例二：PLC 精密运动控制装配工位（低抖动、高可靠要求）

### 场景背景

3C 产品精密装配工位，PLC 周期扫描 10ms，六轴机器人联动，要求控制周期抖动 ≤ ±0.5ms，所有参数修改、运动指令必须可追溯。

### 核心痛点

1. 控制线程同步写日志，导致周期抖动最大达 3ms，偶发装配位置偏差；
2. 每周期寄存器读写都打日志，海量普通通信日志淹没了真正的错误告警；
3. 人工操作无留痕，出问题分不清是程序 bug 还是人为误操作。

### 落地最佳实践

1. **控制模块独立异步队列**：和视觉日志物理隔离，避免高优先级的控制日志被大量视觉日志挤压。
2. **普通读写降级，失败分级告警**：单次正常读写仅打 `Debug`，生产环境不输出；单次失败打 `Warn`，连续 3 次失败打 `Error`，兼顾信息完整度和信噪比。
3. **关键操作强制留痕**：运动指令下发、参数修改、模式切换必须打 `Info`，记录操作源和执行结果。
4. **参数化日志减少 GC**：使用占位符传递参数，避免字符串拼接产生临时对象，减少 GC 加剧周期抖动。

### 核心代码示例

csharp:

```c#
private int _continuousFailCount = 0;

public bool WriteRegister(string address, short value)
{
    try
    {
        // 参数化写法：无字符串拼接，无额外GC
        LogHelper.Debug("PLC通信", "写入地址{addr}，值{val}", address, value);
        
        bool result = _plcClient.Write(address, value);
        if (!result)
        {
            _continuousFailCount++;
            if (_continuousFailCount >= 3)
            {
                LogHelper.Error("PLC通信", "地址{addr}连续写入失败3次，写入值{val}", address, value);
            }
            else
            {
                LogHelper.Warn("PLC通信", "地址{addr}单次写入失败，进入重试", address);
            }
            return false;
        }

        _continuousFailCount = 0;
        return true;
    }
    catch (Exception ex)
    {
        LogHelper.Error("PLC通信", "写入地址{addr}发生通信异常", address, ex);
        return false;
    }
}
```

### 落地效果

- 控制周期抖动从 ±2.5ms 降到 ±0.3ms，装配良率提升 0.8%；
- 有效告警信噪比提升 10 倍，通信故障定位时间缩短 80%；
- 所有参数变更可追溯，误操作追责有明确依据。

## 案例三：医药包装检测线（GMP 合规审计场景）

### 场景背景

药盒外观检测线，需满足 GMP 合规要求，所有参数修改、批次切换、人工操作必须留痕，日志保存 180 天，不可篡改，可用于官方审计追溯。

### 核心痛点

1. 参数修改只改不记，出质量问题找不到责任人；
2. 审计日志和运行日志混在一起，审计时提取困难；
3. 日志可被随意删除修改，不符合数据完整性要求。

### 落地最佳实践

1. **审计日志物理隔离**：单独文件存储，只记录操作类事件，和运行日志完全分离，审计时直接调取。
2. **操作三要素强制记录**：操作人、修改前值、修改后值，缺一不可，满足审计追溯要求。
3. **全局上下文自动透传**：使用 `ScopeContext` 注入批次号、工号，所有日志自动关联业务上下文，无需每条手动拼接。
4. **防篡改机制**：日志目录设置 NTFS 只读权限，仅程序可追加写入，禁止修改删除历史记录；定期生成文件哈希校验。
5. **长周期双重归档**：审计日志保留 180 天，按天 + 按大小双重切割，防止单日日志过大。

### 核心配置 + 代码

xaml:

```xaml
<!-- 审计专属日志：单独归档，保留180天 -->
<target xsi:type="File" name="AuditLog"
        fileName="D:/Logs/Pharma/audit-${shortdate}.log"
        archiveEvery="Day"
        archiveAboveSize="104857600"  <!-- 单文件超100MB强制切割 -->
        maxArchiveDays="180"
        encoding="utf-8">
  <layout>${longdate} | 操作员：${event-properties:item=Operator} | 批次：${event-properties:item=BatchNo} | ${message}</layout>
</target>

<rules>
  <!-- 仅模块名为「操作审计」的日志写入审计文件 -->
  <logger name="*" minlevel="Info" writeTo="AuditLog">
    <filters>
      <when condition="not equals('${event-properties:item=Module}','操作审计')" action="Ignore"/>
    </filters>
  </logger>
</rules>
```

csharp:

```c#

```

### 落地效果

- 一次性通过 GMP 审计，操作追溯时间从半天缩短到 1 分钟；
- 日志完整度 100%，无篡改、丢失情况，满足医药行业数据完整性要求；
- 无需额外开发审计模块，基于 NLog 原生能力实现，开发成本极低。

## 案例四：7×24 小时无人值守黑灯产线

### 场景背景

汽车零部件夜班检测站，无人值守，连续运行 30 天不停机，现场无运维人员，核心要求是**设备稳定优先，绝对不能因为日志问题导致停机**。

### 核心痛点

1. 日志持续累积，曾出现磁盘写满导致程序崩溃、整条线停机；
2. 程序异常崩溃时，异步队列里的最后几条关键日志丢失，找不到崩溃根因；
3. 夜间低峰期日志量小，文件句柄长期持有属于不必要的资源占用。

### 落地最佳实践

1. **双重切割 + 双重过期清理**：按自然天切割 + 单文件 100MB 强制切割，按天数 + 文件总数双重兜底，自动清理过期日志。
2. **磁盘空间监控兜底**：业务层定时检测磁盘剩余空间，低于 10% 触发告警并自动清理最旧日志，做最后一道防线。
3. **崩溃强制刷盘机制**：全局未捕获异常处理中，先调用 `LogManager.Shutdown()` 把内存队列日志全部刷盘，再退出程序，保留完整故障现场。
4. **空闲自动释放句柄**：配置 `openFileCacheTimeout`，1 小时无日志自动释放文件句柄，适配低流量夜间场景。

### 核心配置片段

xaml:

```xaml
<target xsi:type="File" name="MainLog"
        fileName="D:/Logs/Unmanned/app-${shortdate}.log"
        archiveEvery="Day"
        archiveAboveSize="104857600"  <!-- 单文件超100MB强制切割，单位字节 -->
        archiveNumbering="DateAndSequence"
        maxArchiveDays="30"
        maxArchiveFiles="100"         <!-- 文件数量兜底，防止极端情况磁盘爆满 -->
        keepFileOpen="true"
        openFileCacheTimeout="3600"   <!-- 1小时无日志自动释放文件句柄 -->
        concurrentWrites="false"
        encoding="utf-8">
  <layout>...</layout>
</target>
```

- 2 次程序异常退出，关键故障日志 100% 留存，均快速定位根因；
- 夜间资源占用降低，设备运行稳定性显著提升。

## 案例五：量产线现场免重启排障场景

### 场景背景

量产线设备不能随意停机重启，偶发故障复现概率低，重启后故障往往消失，排查极其困难。

### 核心痛点

1. 生产环境默认 `Info` 级别，Debug 日志关闭；出问题要改配置重启程序，故障往往就消失了；
2. 全量开启 Debug 日志会疯狂刷屏，无关日志太多，找不到问题重点。

### 落地最佳实践

1. **开启配置热重载**：`autoReload="true"`，修改 `NLog.config` 后 10 秒内自动生效，无需重启程序，不中断生产。
2. **模块级粒度控制**：只给出问题的模块开启 Debug，其他模块保持 Info，避免无关日志刷屏。
3. **条件过滤器精准定位**：可按批次号、错误码、工位过滤日志，只输出关心的内容，进一步缩小排查范围。

### 临时排障配置示例（仅 PLC 模块开 Debug）

xaml:

```xaml
<nlog autoReload="true">
  <rules>
    <!-- 全局默认Info级别 -->
    <logger name="*" minlevel="Info" writeTo="MainLog" />
    
    <!-- 排障时临时添加：仅PLC通信模块输出Debug -->
    <logger name="*" minlevel="Debug" writeTo="DebugLog">
      <filters>
        <when condition="equals('${event-properties:item=Module}', 'PLC通信')" action="Log"/>
        <when condition="level < LogLevel.Info" action="Ignore"/>
      </filters>
    </logger>
  </rules>
</nlog>
```

### 落地效果

- 排障无需停机重启，不影响正常生产，完全适配量产线不能随意停线的要求；
- 模块级 Debug 日志量仅为全量开启的 1/10，排查效率大幅提升；
- 偶发通信故障不用等复现，直接临时开 Debug 抓取，平均排障时间缩短 70%。

## 反面典型：工业上位机日志常见踩坑对照

| 错误做法                                | 实际后果                               | 正确实践                                 |
| :-------------------------------------- | :------------------------------------- | :--------------------------------------- |
| 相机回调同步打 Info，逐帧输出           | CT 飙升、相机丢帧、检测漏件            | 异步写入 + 逐帧降级 Debug，生产默认关闭  |
| catch 只打 `ex.Message`，不输出完整堆栈 | 出问题找不到具体代码行，无法定位根因   | Error/Fatal 必须传入完整 Exception 对象  |
| 日志存 C 盘程序目录，无自动清理         | 系统崩溃日志全丢、磁盘写满程序宕机     | 存 D 盘非系统分区 + 按天自动清理过期文件 |
| 异步溢出策略设为 `Block`                | 队列满时直接卡死业务线程，等于白做异步 | 工业场景强制 `Discard`，优先保障生产稳定 |
| 所有日志塞进同一个文件                  | 排查问题大海捞针，效率极低             | 运行、错误、审计三类文件物理分离         |

## 最终总结

工业上位机日志的最佳实践，始终围绕三个核心原则：

1. **不添乱**：异步写入、分级管控，绝对不能影响设备实时性和稳定性；
2. **真有用**：关键信息必留，错误堆栈完整，故障出现能快速定位根因；
3. **自管理**：自动切割、自动清理、崩溃兜底，7×24 小时运行无需人工干预。
