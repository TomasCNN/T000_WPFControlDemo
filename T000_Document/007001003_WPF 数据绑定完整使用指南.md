# 007001003_WPF 数据绑定完整使用指南

在 WPF 中使用数据绑定，核心是完成「**准备数据源 → 建立数据上下文 → 编写绑定表达式**」三步流程，最终实现「数据变化自动更新 UI，UI 操作自动回写数据」，全程无需手动读写控件属性。

以下结合你熟悉的工业图形控件（`Rectangle`/`Polygon`/`Path`）场景，从基础步骤到实战落地完整讲解。

------

## 一、核心三要素

使用数据绑定前，先明确三个必不可少的组成部分：

1. **数据源（Source）**：提供数据的业务对象，通常是视图模型（ViewModel），数据变化时要能发出通知；
2. **数据上下文（DataContext）**：绑定的「默认数据源容器」，沿着可视化树向下继承，告诉控件「去哪个对象里找绑定的属性」；
3. **绑定表达式（Binding）**：写在 XAML 中，明确「把控件的哪个属性，绑定到数据源的哪个属性」，并可配置绑定方向、转换器等参数。

------

## 二、完整使用步骤

### 第一步：实现可通知的数据源

要让数据源变化时 UI 自动刷新，数据源类必须实现 `INotifyPropertyChanged` 接口，属性值变更时触发 `PropertyChanged` 事件通知 WPF 框架。

#### 标准实现

先封装一个通用的 ViewModel 基类（避免每个类重复写通知逻辑）：

csharp:

```c#
using System.ComponentModel;
using System.Runtime.CompilerServices;

/// <summary>
/// 视图模型基类：封装属性变更通知
/// </summary>
public class ViewModelBase : INotifyPropertyChanged
{
    public event PropertyChangedEventHandler PropertyChanged;

    /// <summary>
    /// 触发属性变更通知
    /// </summary>
    protected void OnPropertyChanged([CallerMemberName] string propertyName = null)
    {
        PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(propertyName));
    }

    /// <summary>
    /// 简化属性赋值：值变化时自动触发通知
    /// </summary>
    protected bool SetProperty<T>(ref T field, T value, [CallerMemberName] string propertyName = null)
    {
        if (EqualityComparer<T>.Default.Equals(field, value))
            return false;
        
        field = value;
        OnPropertyChanged(propertyName);
        return true;
    }
}
```

#### 业务视图模型（以视觉检测场景为例）

继承基类，定义业务属性，对应界面上的图形、数据：

csharp:

```c#
using System.Windows.Media;
using System.Windows.Shapes;

/// <summary>
/// 视觉检测视图模型
/// </summary>
public class DetectViewModel : ViewModelBase
{
    // 1. 设备温度（展示用）
    private double _temperature;
    public double Temperature
    {
        get => _temperature;
        set => SetProperty(ref _temperature, value);
    }

    // 2. 检测 ROI 顶点集合（驱动多边形形状）
    private PointCollection _roiPoints;
    public PointCollection RoiPoints
    {
        get => _roiPoints;
        set => SetProperty(ref _roiPoints, value);
    }

    // 3. 设备状态枚举（控制颜色）
    private DeviceStatus _stationStatus;
    public DeviceStatus StationStatus
    {
        get => _stationStatus;
        set => SetProperty(ref _stationStatus, value);
    }

    // 4. 检测阈值（可编辑，双向绑定）
    private double _detectThreshold;
    public double DetectThreshold
    {
        get => _detectThreshold;
        set => SetProperty(ref _detectThreshold, value);
    }
}

/// <summary>
/// 设备状态枚举
/// </summary>
public enum DeviceStatus
{
    Running,    // 运行中
    Standby,    // 待机
    Alarm       // 告警
}
```

### 第二步：设置 DataContext（数据上下文）

`DataContext` 是绑定的「默认数据源」，**父控件设置后，所有子控件会自动继承**，不需要每个控件单独指定数据源。

#### 最常用方式：窗口构造函数中设置

在窗口的后台代码中，给整个窗口指定数据上下文，窗口内所有控件的绑定默认都从这个 ViewModel 中找属性。

csharp:

```c#
public partial class MainWindow : Window
{
    public MainWindow()
    {
        InitializeComponent();
        
        // 关键：设置窗口的 DataContext
        this.DataContext = new DetectViewModel
        {
            Temperature = 25.6,
            DetectThreshold = 0.85,
            StationStatus = DeviceStatus.Running,
            RoiPoints = new PointCollection
            {
                new Point(100, 100),
                new Point(300, 100),
                new Point(300, 250),
                new Point(100, 250)
            }
        };
    }
}
```

#### 其他常见设置方式

1. **XAML 中声明设置**

xaml:

```xaml
<Window x:Class="Demo.MainWindow"
        xmlns:vm="clr-namespace:Demo.ViewModels">
    <Window.DataContext>
        <vm:DetectViewModel/>
    </Window.DataContext>
</Window>
```

1. **列表控件自动分配**

   `ItemsControl`/`ListBox`等列表控件，会自动把每条数据的 `DataContext`设置为对应的数据项，模板内直接绑定数据项的属性即可（后面批量绑定会详细讲）。

### 第三步：XAML 编写绑定表达式

用 `{Binding 属性名}` 语法，把控件属性和数据源属性关联起来。以下结合你熟悉的图形控件演示：

#### 1. 基础单向绑定（数据 → UI）

xaml:

```xaml
<Grid Margin="20">
    <Grid.RowDefinitions>
        <RowDefinition Height="Auto"/>
        <RowDefinition/>
    </Grid.RowDefinitions>

    <!-- 文本展示：绑定温度，带单位格式化 -->
    <TextBlock FontSize="16"
               Text="{Binding Temperature, StringFormat={}{0} ℃}"/>

    <!-- 画布 + 多边形：ROI 形状完全由数据源驱动 -->
    <Canvas Grid.Row="1" Background="#1E1E1E">
        <Polygon Points="{Binding RoiPoints}"
                 Stroke="Cyan"
                 StrokeThickness="2"
                 Fill="#2200FFFF"
                 StrokeLineJoin="Round"/>
    </Canvas>
</Grid>
```

此时只要后台修改 `RoiPoints` 属性值，界面上的多边形形状会自动刷新，不需要手动操作控件。

#### 2. 双向绑定（UI ↔ 数据）

用户在界面输入 / 操作，值自动回写到数据源：

xaml:

```xaml
<!-- 阈值输入框：修改后立刻回写数据源 -->
<TextBox Text="{Binding DetectThreshold, Mode=TwoWay, UpdateSourceTrigger=PropertyChanged}"/>
```

- `Mode=TwoWay`：开启双向同步；
- `UpdateSourceTrigger=PropertyChanged`：输入内容一变就回写，不用等输入框失焦。

#### 3. 控件间联动（ElementName）

不需要数据源，直接绑定其他控件的属性，适合界面内联动：

xaml:

```xaml
<StackPanel Margin="20">
    <Slider x:Name="opacitySlider" Minimum="0" Maximum="1" Value="0.7"/>
    <!-- 多边形透明度绑定滑块的值，拖动实时变化 -->
    <Polygon Points="150,20 20,180 280,180"
             Stroke="RoyalBlue"
             Fill="#334169E1"
             Opacity="{Binding Value, ElementName=opacitySlider}"/>
</StackPanel>
```

## 三、高频实战场景

### 场景 1：状态驱动图形颜色（值转换器）

工业场景最常用：设备状态是枚举 / 布尔，需要对应显示不同颜色。由于 `StationStatus` 是枚举，`Fill` 是 `Brush` 类型，类型不匹配，需要用 **值转换器（IValueConverter）** 做中间转换。

#### 步骤 1：实现转换器

csharp:

```c#
using System.Globalization;
using System.Windows.Data;
using System.Windows.Media;

/// <summary>
/// 设备状态转背景色转换器
/// </summary>
public class StatusToBrushConverter : IValueConverter
{
    public object Convert(object value, Type targetType, object parameter, CultureInfo culture)
    {
        if (value is not DeviceStatus status) return Brushes.Gray;
        
        return status switch
        {
            DeviceStatus.Running => Brushes.LimeGreen,
            DeviceStatus.Standby => Brushes.Orange,
            DeviceStatus.Alarm => Brushes.Red,
            _ => Brushes.Gray
        };
    }

    // 反向转换（双向绑定时需要，这里单向可以不实现）
    public object ConvertBack(object value, Type targetType, object parameter, CultureInfo culture)
    {
        throw new NotImplementedException();
    }
}
```

#### 步骤 2：在 XAML 中声明为资源

xaml:

```xaml
<Window.Resources>
    <local:StatusToBrushConverter x:Key="StatusToBrushConverter"/>
</Window.Resources>
```

#### 步骤 3：绑定中使用

xaml:

```xaml
<!-- 工位状态矩形：背景色由设备状态自动决定 -->
<Rectangle Width="150" Height="80" RadiusX="8" RadiusY="8"
           Stroke="#333" StrokeThickness="1"
           Fill="{Binding StationStatus, Converter={StaticResource StatusToBrushConverter}}"/>
```

只要 `StationStatus` 属性变化，矩形颜色会自动切换，完全不需要后台写判断逻辑。

### 场景 2：批量渲染缺陷框（列表绑定）

之前用后台循环添加 `Polygon` 的方式，不符合 MVVM 思想。用数据绑定 + `ItemsControl` 可以实现纯数据驱动，算法线程只需要更新集合，UI 自动渲染所有缺陷框。

#### 数据源：缺陷集合

csharp:

```c#
public class DetectViewModel : ViewModelBase
{
    // 缺陷框集合
    public ObservableCollection<DefectInfo> DefectList { get; set; } = new();
}

/// <summary>
/// 单个缺陷信息
/// </summary>
public class DefectInfo : ViewModelBase
{
    private double _x;
    public double X
    {
        get => _x;
        set => SetProperty(ref _x, value);
    }

    private double _y;
    public double Y
    {
        get => _y;
        set => SetProperty(ref _y, value);
    }

    private double _width;
    public double Width
    {
        get => _width;
        set => SetProperty(ref _width, value);
    }

    private double _height;
    public double Height
    {
        get => _height;
        set => SetProperty(ref _height, value);
    }

    private bool _isCritical;
    public bool IsCritical
    {
        get => _isCritical;
        set => SetProperty(ref _isCritical, value);
    }
}
```

#### XAML 批量绑定

xaml:

```xaml
<Canvas Width="800" Height="600" Background="#1E1E1E">
    <ItemsControl ItemsSource="{Binding DefectList}">
        <!-- 用 Canvas 作为布局容器 -->
        <ItemsControl.ItemsPanel>
            <ItemsPanelTemplate>
                <Canvas/>
            </ItemsPanelTemplate>
        </ItemsControl.ItemsPanel>

        <!-- 每个缺陷项的定位 -->
        <ItemsControl.ItemContainerStyle>
            <Style TargetType="ContentPresenter">
                <Setter Property="Canvas.Left" Value="{Binding X}"/>
                <Setter Property="Canvas.Top" Value="{Binding Y}"/>
            </Style>
        </ItemsControl.ItemContainerStyle>

        <!-- 单个缺陷框的数据模板 -->
        <ItemsControl.ItemTemplate>
            <DataTemplate>
                <Rectangle Width="{Binding Width}"
                           Height="{Binding Height}"
                           Stroke="{Binding IsCritical, Converter={StaticResource CriticalToColorConverter}}"
                           StrokeThickness="1.5"
                           Fill="Transparent"/>
            </DataTemplate>
        </ItemsControl.ItemTemplate>
    </ItemsControl>
</Canvas>
```

> 核心优势：后台只需要操作 `DefectList` 集合（添加 / 删除 / 修改），UI 自动同步，彻底告别手动操作 `Canvas.Children`，完美契合 MVVM 架构。

## 四、常见坑与调试技巧

### 1. 绑定失败不报错？看输出窗口

WPF 绑定失败不会抛出异常，但会在 Visual Studio 的「输出」窗口打印错误信息，比如「找不到属性」「DataContext 为 null」，是排查绑定问题的首选方式。

### 2. 数据变了 UI 不更新？

90% 是以下两个原因：

- 数据源类没有实现 `INotifyPropertyChanged` 接口；
- 属性赋值时没有触发 `PropertyChanged` 事件（没调用 `OnPropertyChanged`）。

### 3. 绑定属性找不到？

- 检查 `DataContext` 是否正确设置，是否是预期的对象类型；
- 检查属性名大小写，C# 属性区分大小写，绑定路径必须和类中属性名完全一致。

### 4. 哪些属性可以绑定？

只有 ** 依赖属性（DependencyProperty）** 才能作为绑定目标。WPF 控件的绝大多数属性（如 `Text`、`Fill`、`Width`、`Points`）都是依赖属性，都支持绑定；普通 CLR 属性不能作为绑定目标。

## 五、最佳实践总结

1. **优先 MVVM 模式**：窗口级设置 `DataContext`，所有子控件继承，后台代码不直接操作控件；
2. **属性变更通知**：所有需要动态更新的属性，都要实现变更通知；
3. **类型不匹配用转换器**：枚举转颜色、布尔转可见性、数值转尺寸等场景，统一用 `IValueConverter` 处理，不要在后台写赋值逻辑；
4. **列表用 `ObservableCollection<T>`**：集合元素增删时 UI 自动刷新，普通 `List<T>` 没有变更通知；
5. **简单联动用 `ElementName`**：控件之间的直接联动，不需要绕一圈写数据源。

掌握以上内容，就能覆盖工业上位机、图形可视化场景中 90% 以上的数据绑定需求。
