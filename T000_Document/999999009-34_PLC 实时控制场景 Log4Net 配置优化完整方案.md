# 999999009-34_PLC 实时控制场景 Log4Net 配置优化完整方案

PLC 实时控制的核心诉求是**控制周期零抖动、异常日志不丢失、长期运行不爆盘、排障无需停机**。Log4Net 作为老牌日志框架，原生能力在实时性、自动运维上存在短板，需要针对性配置优化才能适配工控场景。

以下方案完全贴合 PLC 周期轮询、运动控制、IO 交互的真实工况，从异步隔离、分级管控、磁盘兜底、性能优化、热重载五个维度落地优化，可直接复用到 .NET Framework 存量工控项目。

------

## 一、场景核心优先级与痛点

### 核心优先级（从高到低）

控制线程零阻塞 > 错误日志完整可追溯 > 普通日志完整性 > 磁盘占用

### 典型痛点

1. 同步写日志产生毫秒级 IO 阻塞，直接造成控制周期抖动，影响运动控制精度；
2. 周期轮询日志量大，普通读写日志刷屏淹没关键告警信息；
3. 原生不支持按天数自动清理日志，7×24 小时运行极易写满磁盘；
4. 排查问题需重启程序修改配置，无法在线调试，中断生产。

------

## 二、核心优化配置方案

### 1. 真异步写入：彻底隔离磁盘 IO（最关键优化）

#### 为什么必须做

同步模式下，PLC 控制线程调用日志时会当场执行文件打开、写盘、关闭操作，单次耗时 3~15ms 不等，直接导致 10ms 级的控制周期出现剧烈抖动，甚至引发控制超时、动作偏差。

#### 实现方案

安装第三方 NuGet 包 `Log4Net.Async`，使用 `AsyncForwardingAppender` 实现**后台线程异步落盘**：

- 业务线程仅将日志推入内存队列，耗时微秒级，完全不碰磁盘 IO；
- 专属后台线程批量写盘，磁盘耗时完全隔离，不影响控制周期。

#### 关键工业级参数

| 参数             | 推荐值  | 说明                                                       |
| :--------------- | :------ | :--------------------------------------------------------- |
| `bufferSize`     | `3000`  | 内存队列最大容量，防止异常刷屏撑爆内存                     |
| `lossy`          | `true`  | 开启有损模式：队列满时丢弃低级日志，保障控制线程不阻塞     |
| `LevelEvaluator` | `ERROR` | 阈值：ERROR 及以上级别日志强制保留，绝不丢弃；低级日志可丢 |

#### 独立队列隔离

给 PLC 模块单独分配异步队列，和视觉、MES 等大流量模块物理隔离，避免海量视觉日志挤压 PLC 高优先级告警日志。

#### 配置片段示例

xaml:

```xaml
<!-- PLC 控制专属异步队列：独立后台线程，错误不丢失，低级可丢弃 -->
<appender name="PlcAsyncAppender" type="Log4Net.Async.AsyncForwardingAppender, Log4Net.Async">
  <bufferSize value="3000" />
  <lossy value="true" />
  <!-- ERROR 及以上级别强制保留，队列满也不丢 -->
  <evaluator type="log4net.Core.LevelEvaluator">
    <threshold value="ERROR" />
  </evaluator>
  <!-- 同时输出到运行日志和错误日志 -->
  <appender-ref ref="PlcRunAppender" />
  <appender-ref ref="ErrorOnlyAppender" />
</appender>
```

> ❌ 避坑：不要用原生 `BufferingForwardingAppender` 替代，它只是在调用线程批量缓冲，依然会阻塞业务线程，不是真正的异步。

### 2. 分级管控 + 错误独立归档：提升日志信噪比

#### 分级规则（PLC 场景强制）

| 场景                        | 日志级别 | 生产环境   |
| :-------------------------- | :------- | :--------- |
| 单次正常寄存器读写          | DEBUG    | ❌ 默认关闭 |
| 单次读写失败、重试成功      | WARN     | ✅ 开启     |
| 连续 3 次读写失败、通信中断 | ERROR    | ✅ 强制开启 |
| 控制异常、急停触发          | FATAL    | ✅ 强制开启 |

#### 错误日志独立归档

使用 `LevelRangeFilter` 将 ERROR/FATAL 级日志单独输出到专属文件，排查问题直接打开错误日志，无需在百万行轮询日志里翻找。

xaml:

```xaml
<!-- 全局错误专属日志：所有模块 ERROR/FATAL 都进这里，保留更久 -->
<appender name="ErrorOnlyAppender" type="log4net.Appender.RollingFileAppender">
  <file value="D:/Logs/PLC/error.log" />
  <rollingStyle value="Composite" />
  <datePattern value="yyyyMMdd'.log'" />
  <staticLogFileName value="false" />
  <maxSizeRollBackups value="90" />
  <maximumFileSize value="100MB" />
  <encoding value="utf-8" />
  <lockingModel type="log4net.Appender.FileAppender+ExclusiveLock" />
  
  <!-- 只保留 ERROR~FATAL -->
  <filter type="log4net.Filter.LevelRangeFilter">
    <levelMin value="ERROR" />
    <levelMax value="FATAL" />
  </filter>

  <layout type="log4net.Layout.PatternLayout">
    <conversionPattern value="%date{yyyy-MM-dd HH:mm:ss.fff} | %level | %logger | %message%newline%exception
------------------------------------------------------------------------%newline" />
  </layout>
</appender>
```

### 3. 复合滚动 + 磁盘兜底：7×24 小时不爆盘

Log4Net 原生**不支持按天数自动删除旧日志**，仅支持按文件数量限制，需要通过复合切割 + 数量兜底 + 外部脚本三重保障，避免磁盘爆满。

#### 核心配置

xaml:

```xaml
<appender name="PlcRunAppender" type="log4net.Appender.RollingFileAppender">
  <file value="D:/Logs/PLC/plc_run.log" />
  <appendToFile value="true" />
  
  <!-- 复合滚动：按天 + 单文件大小双重切割 -->
  <rollingStyle value="Composite" />
  <datePattern value="yyyyMMdd'.log'" />
  <maximumFileSize value="100MB" />
  <staticLogFileName value="false" /> <!-- 必须设为false，按天切割才生效 -->
  
  <!-- 兜底：最多保留30个归档文件，防止磁盘溢出 -->
  <maxSizeRollBackups value="30" />
  <preserveLogFileNameExtension value="true" />
  
  <encoding value="utf-8" />
  <!-- 单进程独占锁，去掉并发锁开销，写入性能提升30%+ -->
  <lockingModel type="log4net.Appender.FileAppender+ExclusiveLock" />

  <layout type="log4net.Layout.PatternLayout">
    <conversionPattern value="%date{HH:mm:ss.fff} | %-5level | 工位%property{StationNo} | %message%newline" />
  </layout>
</appender>
```

#### 补充：按天自动清理兜底脚本

原生仅支持按数量限制，若需严格按天数保留，可配合 Windows 定时任务执行批处理，每天凌晨删除 30 天前的日志：

bat:

```bat
@echo off
forfiles /p "D:\Logs\PLC" /s /m *.log /d -30 /c "cmd /c del @path"
```

> ❌ 避坑：`maxSizeRollBackups` 是限制**文件总数**，不是按天数保留；设为 30 表示最多留 30 个归档文件，和天数无关。

### 4. 低开销优化：避免 GC 尖刺与周期抖动

PLC 控制对 GC 停顿极其敏感，临时对象触发的垃圾回收会造成周期抖动，必须从日志层面减少 GC 压力。

#### 1. 使用参数化日志，禁止字符串插值

csharp:

```c#
// ✅ 推荐：参数化，无额外字符串拼接GC
log.DebugFormat("写入地址{0}，值{1}", address, value);

// ❌ 禁止：字符串插值，产生临时对象，加剧GC
log.Debug($"写入地址{address}，值{value}");
```

#### 2. 高频路径先判断级别再格式化

生产环境默认关闭 DEBUG，若不做判断，字符串格式化依然会执行，白白产生开销。

csharp:

```c#
// ✅ 正确：级别未开启时，格式化代码完全不执行
if (log.IsDebugEnabled)
{
    log.DebugFormat("读取地址{0}，返回值{1}", address, value);
}
```

#### 3. 禁用高开销反射字段

生产环境移除 `%location`、`%method`、`%stacktrace` 等反射类字段，这类字段单条日志开销是普通字段的几十倍，会显著拉高控制线程耗时。

xaml:

```xaml
<!-- ❌ 生产禁止：反射获取调用位置，开销极大 -->
<conversionPattern value="%date | %level | %location | %message" />
```

### 5. 配置热重载：排障无需停机

量产线 PLC 设备不能随意重启，偶发故障重启后往往消失，必须支持不停机调整日志级别。

#### 开启方式

程序初始化时调用 `ConfigureAndWatch`，监听配置文件变更，修改后几秒自动生效：

csharp:

```c#
// 程序启动时加载配置并开启文件监听
FileInfo configFile = new FileInfo("log4net.config");
XmlConfigurator.ConfigureAndWatch(configFile);
```

#### 模块级粒度排障

配置中单独给 PLC 模块设置级别，排障时临时改成 DEBUG，其他模块保持 INFO，避免无关日志刷屏：

xaml:

```xaml
<!-- 全局默认INFO -->
<root>
  <level value="INFO" />
  <appender-ref ref="PlcAsyncAppender" />
</root>

<!-- 排障时临时添加：仅PLC通信模块开启DEBUG -->
<logger name="PLC通信">
  <level value="DEBUG" />
</logger>
```

排障结束后删除该节点，保存后自动恢复，全程无需停机。

### 6. 业务上下文透传：全链路可追溯

通过 `LogicalThreadContext` 注入工位号、批次号、设备编号等业务属性，所有日志自动携带，无需每条手动拼接，便于故障追溯。

#### 代码注入

csharp:

```c#
// 程序初始化时全局注入，后续所有日志自动携带
LogicalThreadContext.Properties["StationNo"] = "ST01";
LogicalThreadContext.Properties["BatchNo"] = "B2026062301";
```

#### 布局引用

xaml:

```xaml
<conversionPattern value="%date | %level | 工位%property{StationNo} | 批次%property{BatchNo} | %message%newline" />
```

### 7. 崩溃兜底刷盘：保留完整故障现场

异步日志存在内存队列，程序异常崩溃时，未写入磁盘的日志会丢失。必须在全局异常处理中强制刷盘：

csharp:

```c#
AppDomain.CurrentDomain.UnhandledException += (sender, e) =>
{
    var ex = e.ExceptionObject as Exception;
    ILog fatalLog = LogManager.GetLogger("PLC控制");
    fatalLog.Fatal("全局未捕获异常，控制程序紧急退出", ex);
    
    // 强制刷盘，把异步队列所有日志落地
    LogManager.Shutdown();
};
```

## 四、业务代码最佳实践示例

csharp:

```c#
public class PlcCommunication
{
    private static readonly ILog log = LogManager.GetLogger("PLC通信");
    private int _continuousFailCount = 0;

    public bool WriteRegister(string address, short value)
    {
        try
        {
            // 正常读写仅打DEBUG，生产默认关闭，零开销
            if (log.IsDebugEnabled)
            {
                log.DebugFormat("写入地址{0}，值{1}", address, value);
            }

            bool result = _plcClient.Write(address, value);
            if (!result)
            {
                _continuousFailCount++;
                if (_continuousFailCount >= 3)
                {
                    // 连续3次失败打ERROR，触发告警
                    log.ErrorFormat("地址{0}连续写入失败3次，写入值{1}", address, value);
                }
                else
                {
                    // 单次失败打WARN
                    log.WarnFormat("地址{0}单次写入失败，进入重试", address);
                }
                return false;
            }

            _continuousFailCount = 0;
            return true;
        }
        catch (Exception ex)
        {
            // 异常必须带完整堆栈
            log.Error($"写入地址{address}发生通信异常", ex);
            return false;
        }
    }
}
```

## 五、绝对避坑红线

1. ❌ 不要把 `BufferingForwardingAppender` 当真异步，它依然阻塞调用线程，实时控制场景必须用 `AsyncForwardingAppender`；
2. ❌ 不要在周期轮询里打 INFO 级日志，每秒几十次轮询，一天百万条日志，既占磁盘又无价值；
3. ❌ 不要以为 `maxSizeRollBackups` 是按天保留，它是按文件总数限制，长期运行需配合脚本清理；
4. ❌ 不要滥用 `%location` 等高开销反射字段，生产环境必须关闭，避免加剧控制周期抖动；
5. ❌ 不要忘记设 `staticLogFileName="false"`，否则按天切割完全不生效；
6. ❌ 异常不要只打 `ex.Message`，必须传完整 Exception 对象，输出完整堆栈才能定位根因。

- 有效告警信噪比提升 10 倍以上，故障排查时间缩短 80%；

- 日志磁盘占用自动管控，7×24 小时运行无需人工干预。

  

  如果是新项目，优先选型 NLog，原生异步、自动清理、热重载能力更适配工业实时控制场景。
