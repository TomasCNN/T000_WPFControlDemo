# 999999009-28_C# 项目 NLog 异步写入完整实现指南

NLog 实现异步写入**对业务代码零侵入**，核心只需一行配置即可全局开启；针对工业上位机高帧率采集、实时控制的场景，重点在于调优队列参数、设定合理的溢出策略，确保日志绝对不阻塞相机回调、PLC 控制等实时线程。

下面从安装、配置、封装、调用、验证、优化六个维度给出完整可落地方案，全程贴合线扫视觉、工控实时控制的真实工况。

------

## 一、前置准备：安装 NuGet 包

新建或打开 C# 项目后，在 NuGet 包管理器中搜索安装：

powershell:

```powershell
Install-Package NLog
```

无需安装任何额外异步扩展包，**异步写入是 NLog 原生内置能力**，这也是它相比 Log4Net 的核心优势之一。

安装完成后，在项目根目录添加配置文件 `NLog.config`，并设置文件属性：

> **复制到输出目录 → 如果较新则复制**
>
> 否则程序运行时找不到配置，日志不会输出。

## 二、核心实现：两种异步配置方式

### 方式一：全局异步（工业首选，一行配置全量生效）

这是最推荐、最省事的方式：给所有日志目标统一开启异步，业务代码一行都不用改，自动全部升级为后台线程异步写入。

#### 完整配置示例（工业场景优化版，可直接复制）

xaml:

```xaml
<?xml version="1.0" encoding="utf-8" ?>
<nlog xmlns="http://www.nlog-project.org/schemas/NLog.xsd"
      xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
      autoReload="true"            <!-- 配置热重载，改级别不用重启程序 -->
      internalLogLevel="Warn"      <!-- NLog自身日志级别，排查问题时改Debug -->
      internalLogFile="D:/Logs/nlog-internal.log">

  <!-- ========== 核心：全局异步开关 + 工业级参数调优 ========== -->
  <!-- 加上 async="true"，内部所有 target 自动变成异步写入 -->
  <targets async="true"
           queueLimit="5000"          <!-- 内存队列最大容量，防止内存爆掉 -->
           overflowAction="Discard"    <!-- 队列满了丢弃新日志，绝对不能阻塞业务线程 -->
           batchSize="100"             <!-- 攒够100条批量写盘，减少IO次数 -->
           timeToSleepBetweenBatches="1"> <!-- 两次写盘间隔1ms，平衡CPU和实时性 -->

    <!-- 1. 主运行日志：按天切割，保留30天 -->
    <target xsi:type="File"
            name="MainLog"
            fileName="D:/Logs/app-${shortdate}.log"
            archiveEvery="Day"
            maxArchiveDays="30"
            keepFileOpen="true"        <!-- 长期持有文件句柄，减少开闭开销 -->
            concurrentWrites="false"   <!-- 单进程写入，关闭并发锁提升性能 -->
            encoding="utf-8">
      <!-- 标准工业日志格式：时间(毫秒)|级别|线程ID|模块|消息|异常堆栈 -->
      <layout>${longdate} | ${level:uppercase=true:padding=-5} | 线程${threadid} | ${event-properties:item=Module:padding=-8} | ${message} ${exception:format=ToString,StackTrace:maxInnerExceptionLevel=5}</layout>
    </target>

    <!-- 2. 错误专属日志：仅Error/Fatal，排查问题直接看这个文件 -->
    <target xsi:type="File"
            name="ErrorLog"
            fileName="D:/Logs/error-${shortdate}.log"
            archiveEvery="Day"
            maxArchiveDays="90"
            keepFileOpen="true"
            encoding="utf-8">
      <layout>${longdate} | ${level:uppercase=true} | 线程${threadid} | ${event-properties:item=Module} | ${message}
${exception:format=ToString,StackTrace:maxInnerExceptionLevel=5}
----------------------------------------------------------------------</layout>
    </target>

    <!-- 3. 控制台输出（开发调试用，生产可注释） -->
    <target xsi:type="ColoredConsole" name="ConsoleLog"
            layout="${time:format=HH\:mm\:ss.fff} | ${level:uppercase=true:padding=-5} | ${event-properties:item=Module} | ${message}" />
  </targets>

  <!-- 日志路由规则：生产环境默认Info级别 -->
  <rules>
    <logger name="*" minlevel="Info" writeTo="MainLog" />
    <logger name="*" minlevel="Error" writeTo="ErrorLog" />
    <logger name="*" minlevel="Debug" writeTo="ConsoleLog" />
  </rules>
</nlog>
```

#### 异步核心参数详解（工业场景推荐值）

| 参数                        | 作用                           | 工业推荐值                  | 注意事项                                                     |
| :-------------------------- | :----------------------------- | :-------------------------- | :----------------------------------------------------------- |
| `queueLimit`                | 内存队列最大容纳日志条数       | `5000`                      | 不能设无限大，异常疯狂刷屏时会撑爆内存                       |
| `overflowAction`            | 队列满了之后的处理策略         | **`Discard`（丢弃新日志）** | 工业场景铁律：绝对不能设 `Block`，否则会卡住业务线程，异步白做 |
| `batchSize`                 | 后台线程一次批量写入的条数     | `100`                       | 数值越大写盘效率越高，但日志落地延迟略高                     |
| `timeToSleepBetweenBatches` | 两次批量写盘的休眠间隔（毫秒） | `1`                         | 平衡 CPU 占用和日志实时性，1ms 几乎无感知                    |

> 原理：开启全局异步后，NLog 会自动给每个 Target 包一层 `AsyncWrapper`，自动创建后台低优先级线程写盘；业务线程调用日志方法时，只是把消息扔进内存队列，耗时约 0.01ms，完全不碰磁盘 IO。

### 方式二：单目标独立异步（模块隔离场景用）

如果需要给不同模块（比如相机、PLC）分配独立的异步队列，避免高流量的视觉日志挤压高优先级的控制日志，可以单独给某个 Target 包 `AsyncWrapper`。

#### 适用场景

- 线扫相机日志量大，PLC 控制日志优先级高，需要物理隔离队列；
- 部分目标需要同步、部分需要异步混合使用。

#### 配置示例

xaml:

```xaml
<targets>
  <!-- 相机日志：独立异步队列，大流量，溢出丢弃 -->
  <target xsi:type="AsyncWrapper" 
          name="CameraAsync"
          queueLimit="5000"
          overflowAction="Discard"
          batchSize="200">
    <target xsi:type="File" name="CameraLog"
            fileName="D:/Logs/camera-${shortdate}.log"
            ... />
  </target>

  <!-- PLC控制日志：独立异步队列，优先级高，不丢弃 -->
  <target xsi:type="AsyncWrapper"
          name="PlcAsync"
          queueLimit="2000"
          overflowAction="Discard"> <!-- 极端情况仍丢弃，优先保主程序 -->
    <target xsi:type="File" name="PlcLog"
            fileName="D:/Logs/plc-${shortdate}.log"
            ... />
  </target>
</targets>
```

## 三、封装统一日志工具类（C# 代码）

封装一层静态工具类，强制按模块打印，和 NLog 底层解耦，后续换框架不用改业务代码，同时统一上下文注入。

csharp:

```c#
using NLog;
using NLog.ScopeContext;
using System;

/// <summary>
/// 工业上位机统一日志工具
/// </summary>
public static class LogHelper
{
    private static readonly Logger _logger = LogManager.GetCurrentClassLogger();

    #region 业务全局上下文（批次号、操作员，全链路自动携带）
    /// <summary>设置当前生产批次号</summary>
    public static void SetBatchNo(string batchNo)
    {
        ScopeContext.PushProperty("BatchNo", batchNo);
    }

    /// <summary>设置当前操作员工号</summary>
    public static void SetOperator(string operatorNo)
    {
        ScopeContext.PushProperty("Operator", operatorNo);
    }
    #endregion

    #region 内部统一携带模块名
    private static void PushModule(string moduleName)
    {
        ScopeContext.PushProperty("Module", moduleName);
    }
    #endregion

    /// <summary>调试日志：开发排查用，生产默认关闭</summary>
    public static void Debug(string module, string message)
    {
        PushModule(module);
        _logger.Debug(message);
    }

    /// <summary>信息日志：关键节点、状态切换</summary>
    public static void Info(string module, string message)
    {
        PushModule(module);
        _logger.Info(message);
    }

    /// <summary>警告日志：单次异常、阈值临近、重试成功</summary>
    public static void Warn(string module, string message)
    {
        PushModule(module);
        _logger.Warn(message);
    }

    /// <summary>错误日志：功能失效，必须带完整异常堆栈</summary>
    public static void Error(string module, string message, Exception ex = null)
    {
        PushModule(module);
        if (ex == null)
            _logger.Error(message);
        else
            _logger.Error(ex, message);
    }

    /// <summary>致命错误：程序崩溃、紧急停机</summary>
    public static void Fatal(string module, string message, Exception ex)
    {
        PushModule(module);
        _logger.Fatal(ex, message);
    }

    /// <summary>程序退出时调用：强制刷盘，防止异步队列日志丢失</summary>
    public static void Shutdown()
    {
        LogManager.Shutdown();
    }
}
```

## 四、业务代码调用示例（线扫相机回调场景）

开启异步后，**调用方式和同步完全一样**，业务代码零感知，底层自动异步入队。

以你最熟悉的线扫相机采集回调为例：

csharp:

```c#
private static readonly object _imgLock = new object();
private static Bitmap LineScanImage;

private static void LineScanCCD_OnResultDataGrab(OpencvImage opencvImage)
{
    try
    {
        if (!LineScanCCD.IsOpen())
        {
            // 错误日志：异步入队，不阻塞回调
            LogHelper.Error("线扫相机", "取图回调触发，但相机未打开");
            return;
        }

        using (Bitmap bitmap = FromOpencvImage(opencvImage))
        {
            lock (_imgLock)
            {
                LineScanImage?.Dispose();
                LineScanImage = (Bitmap)bitmap.Clone();
            }
        }

        // 逐帧细节仅打Debug，生产环境默认关闭，零性能开销
        LogHelper.Debug("线扫相机", $"新一帧采集完成，宽{opencvImage.Width} 高{opencvImage.Height}");
    }
    catch (Exception ex)
    {
        // 异常必带完整堆栈，异步入队
        LogHelper.Error("线扫相机", "相机取图回调异常", ex);
    }
    finally
    {
        DestoryOpencvImage(opencvImage);
    }
}
```

> 性能对比（4096×2048 线扫图回调）：
>
> - 同步写日志：单条增加 CT 3~15ms（磁盘波动大）
> - 异步写日志：单条增加 CT <0.1ms，几乎无感知

## 五、验证异步是否真的生效

### 方法 1：耗时验证（最直观）

在调用日志前后加 Stopwatch 计时：

csharp:

```c#
var sw = Stopwatch.StartNew();
LogHelper.Info("测试", "测试异步耗时");
sw.Stop();
Console.WriteLine($"日志调用耗时：{sw.ElapsedTicks} 刻");
```

如果耗时在几十微秒级别（几千刻以内），说明只是入队操作，异步生效；如果耗时几毫秒以上，说明是同步写盘。

### 方法 2：批量写入延迟验证

循环打 1000 条日志，观察日志文件：

- 同步：一条一条立刻写入文件；
- 异步：会攒够一批后一次性写入，有轻微延迟，说明走了批量写入。

### 方法 3：压测验证

主线程循环打 10000 条日志，看主线程会不会卡住。

- 同步：主线程明显卡顿；
- 异步：瞬间执行完成，后台线程慢慢写盘。

### 方法 4：查看 NLog 内部日志

把配置里 `internalLogLevel` 改成 `Debug`，运行后查看 `nlog-internal.log`，里面会打印 `AsyncWrapper` 初始化信息，确认异步包装器已启动。

## 六、工业场景进阶必做优化

### 1. 程序退出 / 崩溃强制刷盘，保留故障现场

异步日志存在内存队列里，如果程序突然崩溃、强制结束，队列里没来得及写的日志会丢失。

- 正常退出：窗口关闭时调用 `LogHelper.Shutdown()`；
- 异常崩溃：全局未捕获异常里先刷盘再退出。

csharp:

```c#
// 程序入口绑定全局异常兜底
AppDomain.CurrentDomain.UnhandledException += (sender, e) =>
{
    var ex = e.ExceptionObject as Exception;
    LogHelper.Fatal("主程序", "全局未捕获异常，程序即将退出", ex);
    LogHelper.Shutdown(); // 强制把队列里的日志全部刷到磁盘
};
```

### 2. 高频场景减少字符串拼接，避免 GC 尖刺

异步只是把「写磁盘」异步了，**字符串拼接、格式化依然在业务线程执行**。

- 逐帧细节日志放 Debug 级别，生产默认关闭；
- 复杂统计信息按间隔输出（如每 50 帧打一次），不要逐帧打；
- 优先使用 NLog 原生参数化日志，减少字符串插值产生的临时对象。

### 3. 日志路径统一放非系统盘

比如 `D:/Logs/`，避免系统崩溃重装后日志丢失，也不会占用系统盘空间。

### 4. 利用热重载动态调级别

配置开启 `autoReload="true"` 后，生产环境排查问题时，直接修改 `minlevel` 为 `Debug`，保存后 10 秒内自动生效，不用重启程序，不中断生产。

## 七、避坑红线（工业场景绝对不能做）

1. ❌ **绝对不要把 `overflowAction` 设为 `Block`**

   队列满时会阻塞业务线程等待，等于变回同步日志，极端情况直接卡死设备，工业场景强制 `Discard`。

2. ❌ **不要以为异步了就可以疯狂刷屏**

   100fps 回调里每帧打 Info，哪怕是异步，入队、字符串格式化依然会占用 CPU 和内存，逐帧细节只能打 Debug。

3. ❌ **不要忘记程序退出刷盘**

   只开异步不关停，异常退出时最后几条关键故障日志会丢，故障现场就没了。

4. ❌ **不要在异步日志里打大对象**

   比如整张图像的像素数组、超大报文，序列化和字符串生成依然在调用线程执行，会拉高 CT、制造 GC。

5. ❌ **不要频繁开关日志文件**

   工业高频场景一定要开 `keepFileOpen="true"`，反复开闭文件的开销比写内容还大。
