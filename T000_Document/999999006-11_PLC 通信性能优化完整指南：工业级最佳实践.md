# 999999006-11_PLC 通信性能优化完整指南：工业级最佳实践

PLC 通信是工业自动化系统中最常见的性能瓶颈之一。一个优化良好的通信架构可以将系统响应时间从数百毫秒降低到几十毫秒，同时将 CPU 使用率降低 50% 以上。本文将从**通信协议、数据组织、解析性能、线程模型、硬件配置**五个维度，提供一套完整的工业级 PLC 通信优化方案。

## 一、核心性能瓶颈分析

在开始优化之前，我们需要先了解 PLC 通信的典型性能瓶颈：

| 瓶颈类型             | 影响程度 | 典型表现                 |
| :------------------- | :------- | :----------------------- |
| **过多网络往返**     | ⭐⭐⭐⭐⭐    | 响应时间长，数据更新延迟 |
| **读取不必要的数据** | ⭐⭐⭐⭐     | 网络带宽浪费，解析时间长 |
| **反射式数据解析**   | ⭐⭐⭐⭐     | CPU 使用率高，GC 压力大  |
| **不合理的任务调度** | ⭐⭐⭐      | 任务重叠，实时性差       |
| **频繁的写入操作**   | ⭐⭐⭐      | PLC 负载高，数据不一致   |
| **错误的重试策略**   | ⭐⭐       | 网络拥塞，PLC 死机       |

## 二、通信协议与数据组织优化

这是最基础也是效果最显著的优化方向，可以带来**5-10 倍**的性能提升。

### 2.1 批量读写：减少网络往返次数

**最严重的性能错误**是逐个寄存器读写。Modbus TCP 一次网络往返大约需要 1-5ms，而一次可以读取最多 125 个保持寄存器。

#### ❌ 错误做法

csharp:

```c#
// 逐个读取10个寄存器：10次网络往返，耗时10-50ms
for (int i = 0; i < 10; i++)
{
    var value = modbusMaster.ReadHoldingRegisters(1, (ushort)i, 1)[0];
}
```

#### ✅ 正确做法

csharp:

```c#
// 批量读取10个寄存器：1次网络往返，耗时1-5ms
var values = modbusMaster.ReadHoldingRegisters(1, 0, 10);
```

#### 高级：自动计算最优读取块

自动合并连续的寄存器地址，生成最少数量的读取请求：

csharp:

```c#
public static List<RegisterBlock> CalculateOptimalReadBlocks(IEnumerable<ModbusRegisterInfo> registers)
{
    var sortedRegisters = registers.OrderBy(r => r.Address).ToList();
    var blocks = new List<RegisterBlock>();
    
    if (sortedRegisters.Count == 0)
        return blocks;

    var currentBlock = new RegisterBlock
    {
        StartAddress = sortedRegisters[0].Address,
        Length = sortedRegisters[0].Length
    };

    for (int i = 1; i < sortedRegisters.Count; i++)
    {
        var currentRegister = sortedRegisters[i];
        var gap = currentRegister.Address - (currentBlock.StartAddress + currentBlock.Length);

        // 如果间隙小于8个寄存器，合并读取（宁可多读几个也不多一次网络往返）
        if (gap <= 8 && currentBlock.Length + gap + currentRegister.Length <= 125)
        {
            currentBlock.Length = (ushort)(currentRegister.Address + currentRegister.Length - currentBlock.StartAddress);
        }
        else
        {
            blocks.Add(currentBlock);
            currentBlock = new RegisterBlock
            {
                StartAddress = currentRegister.Address,
                Length = currentRegister.Length
            };
        }
    }

    blocks.Add(currentBlock);
    return blocks;
}

public class RegisterBlock
{
    public ushort StartAddress { get; set; }
    public ushort Length { get; set; }
}
```

**关键原则**：宁可多读几个不相关的寄存器，也不要增加一次网络往返。

### 2.3 写入优化：增量更新与批量写入

#### 增量更新：只写入变化的寄存器

csharp:

```c#
public class IncrementalPlcWriter
{
    private readonly Dictionary<string, object> _lastValues = new();

    public void WriteChanges(ModbusIpMaster master, ProductionLineData newData)
    {
        var changes = new Dictionary<ushort, ushort>();

        // 检查每个属性是否变化
        CheckAndAddChange(changes, "Speed", newData.Speed, old => (ushort)(old * 10));
        CheckAndAddChange(changes, "Status", (ushort)newData.Status, old => (ushort)old);

        if (changes.Count == 0)
            return;

        // 合并连续的地址进行批量写入
        var blocks = MergeChangesIntoBlocks(changes);
        foreach (var block in blocks)
        {
            master.WriteMultipleRegisters(1, block.StartAddress, block.Values);
        }
    }

    private void CheckAndAddChange<T>(Dictionary<ushort, ushort> changes, string propertyName, T newValue, Func<T, ushort> converter)
    {
        var registerInfo = ProductionLineDataMap.GetRegisterInfo(propertyName);
        if (registerInfo == null || registerInfo.AccessMode == DataAccessMode.ReadOnly)
            return;

        if (!_lastValues.TryGetValue(propertyName, out var lastValue) || !Equals(lastValue, newValue))
        {
            changes[registerInfo.Address] = converter(newValue);
            _lastValues[propertyName] = newValue;
        }
    }
}
```

**性能收益**：写入操作减少 90% 以上，PLC 负载显著降低。

## 四、线程与任务调度优化

不合理的线程模型会导致严重的实时性问题和 CPU 使用率飙升。

### 4.1 专用通信线程

使用**单个专用线程**处理所有 PLC 通信，避免多个线程同时访问 Modbus 连接：

csharp:

```c#
public class DedicatedThreadPlcCommunicator
{
    private readonly Thread _communicationThread;
    private readonly BlockingCollection<CommunicationRequest> _requestQueue = new();
    private bool _isRunning;

    public DedicatedThreadPlcCommunicator()
    {
        _communicationThread = new Thread(CommunicationLoop)
        {
            Name = "PLC Communication Thread",
            Priority = ThreadPriority.AboveNormal, // 设置较高优先级
            IsBackground = true
        };
    }

    public void Start()
    {
        _isRunning = true;
        _communicationThread.Start();
    }

    private void CommunicationLoop()
    {
        while (_isRunning)
        {
            try
            {
                // 按优先级处理请求
                var request = _requestQueue.Take();
                
                // 执行通信操作
                var result = ExecuteRequest(request);
                
                // 完成任务
                request.TaskCompletionSource.SetResult(result);
            }
            catch (Exception ex)
            {
                // 处理异常
            }
        }
    }

    // 异步发送请求
    public Task<T> SendRequestAsync<T>(CommunicationRequest request)
    {
        var tcs = new TaskCompletionSource<T>();
        request.TaskCompletionSource = tcs;
        _requestQueue.Add(request);
        return tcs.Task;
    }
}
```

**优势**：

- 避免多线程竞争 Modbus 连接
- 可以按优先级处理请求
- 通信失败不会影响其他线程
- 便于实现统一的错误处理和重试

### 4.2 合理设置任务周期和优先级

| 任务类型     | 推荐周期 | 推荐优先级 | 截止时间 |
| :----------- | :------- | :--------- | :------- |
| 安全监控     | 10ms     | 99         | 8ms      |
| 运动控制     | 20ms     | 90         | 15ms     |
| 过程数据采集 | 100ms    | 80         | 80ms     |
| 状态上报     | 1000ms   | 50         | 500ms    |
| 历史数据存储 | 10000ms  | 20         | 5000ms   |

**关键原则**：

- 不要让任何任务的执行时间超过其周期的 50%
- 高优先级任务应该尽可能短
- 避免在高优先级任务中执行复杂计算

### 4.3 避免在通信线程中执行耗时操作

❌ 错误做法：

## 五、网络与硬件配置优化

### 5.1 网络配置优化

1. **禁用 Nagle 算法**：Modbus 是小数据包协议，Nagle 算法会导致显著延迟

   csharp:

   ```c#
   var tcpClient = new TcpClient();
   tcpClient.Client.NoDelay = true; // 禁用Nagle算法
   tcpClient.Connect(ipAddress, port);
   ```

2. **调整 TCP 缓冲区大小**：

   csharp:

   ```c#
   tcpClient.Client.ReceiveBufferSize = 65536;
   tcpClient.Client.SendBufferSize = 65536;
   ```

3. **使用静态 IP 地址**：避免 DHCP 续租导致的网络中断

4. **使用专用工业交换机**：避免与办公网络共用交换机，减少网络拥塞

### 5.2 PLC 端配置优化

1. **调整通信缓冲区大小**：大多数 PLC 默认的通信缓冲区较小，需要手动增大
2. **优化 OB 块执行周期**：确保通信 OB 块的执行周期小于上位机的读取周期
3. **使用过程映像分区**：将通信数据放在单独的过程映像分区，避免与 PLC 程序竞争
4. **禁用不必要的通信服务**：如 HTTP、FTP、SNMP 等，减少 PLC 负载

### 5.3 操作系统配置优化

1. **设置进程优先级**：

   csharp:

   ```c#
   Process.GetCurrentProcess().PriorityClass = ProcessPriorityClass.High;
   ```

2. **禁用非必要的 Windows 服务**：如 Windows Update、Superfetch 等

3. **调整电源计划**：设置为 "高性能"，禁用 CPU 节能功能

4. **禁用实时调试**：在生产环境中禁用 Visual Studio 调试器

## 六、错误处理与重试策略优化

错误的重试策略会在 PLC 繁忙时雪上加霜，导致系统崩溃。

### 6.1 指数退避重试

csharp:

```c#
public async Task<T> ExecuteWithRetryAsync<T>(Func<Task<T>> operation, int maxRetries = 3)
{
    int retryCount = 0;
    while (true)
    {
        try
        {
            return await operation();
        }
        catch (IOException ex)
        {
            if (retryCount >= maxRetries)
                throw;

            // 指数退避：100ms, 200ms, 400ms, 800ms...
            int delay = (int)Math.Pow(2, retryCount) * 100;
            await Task.Delay(delay);
            
            retryCount++;
        }
    }
}
```

### 6.2 断路器模式

当连续失败次数达到阈值时，暂时停止通信，避免 PLC 过载：

csharp:

```c#
public class CircuitBreaker
{
    private int _failureCount;
    private DateTime _circuitBreakTime;
    private readonly int _failureThreshold = 5;
    private readonly TimeSpan _breakDuration = TimeSpan.FromSeconds(30);

    public bool AllowRequest()
    {
        if (_circuitBreakTime > DateTime.Now)
            return false;

        if (_failureCount >= _failureThreshold)
        {
            _circuitBreakTime = DateTime.Now.Add(_breakDuration);
            _failureCount = 0;
            return false;
        }

        return true;
    }

    public void OnSuccess()
    {
        _failureCount = 0;
    }

    public void OnFailure()
    {
        Interlocked.Increment(ref _failureCount);
    }
}
```

## 七、性能监控与测量

优化必须基于数据，而不是猜测。建立完善的性能监控体系：

csharp:

```c#
public class PlcCommunicationMetrics
{
    private long _totalRequests;
    private long _totalErrors;
    private long _totalBytesSent;
    private long _totalBytesReceived;
    private readonly Stopwatch _stopwatch = new();

    public void RecordRequest(long bytesSent, long bytesReceived, TimeSpan duration, bool success)
    {
        Interlocked.Increment(ref _totalRequests);
        Interlocked.Add(ref _totalBytesSent, bytesSent);
        Interlocked.Add(ref _totalBytesReceived, bytesReceived);
        
        if (!success)
            Interlocked.Increment(ref _totalErrors);
    }

    public void LogMetrics()
    {
        var elapsed = _stopwatch.Elapsed.TotalSeconds;
        Console.WriteLine($"=== PLC通信性能统计 ===");
        Console.WriteLine($"总请求数: {_totalRequests}");
        Console.WriteLine($"错误率: {(double)_totalErrors / _totalRequests:P2}");
        Console.WriteLine($"平均请求时间: {elapsed / _totalRequests:F3}s");
        Console.WriteLine($"吞吐量: {_totalRequests / elapsed:F2} req/s");
        Console.WriteLine($"网络流量: 发送 {_totalBytesSent / 1024:F2} KB, 接收 {_totalBytesReceived / 1024:F2} KB");
    }
}
```

## 总结

PLC 通信性能优化是一个系统性工程，需要从协议、数据、代码、线程、硬件多个维度综合考虑。**批量读写和源生成器解析是两个效果最显著的优化措施**，可以带来一个数量级以上的性能提升。

在优化过程中，一定要遵循 "先测量后优化" 的原则，避免过度优化。同时，要始终牢记工业系统的核心需求是**可靠性和实时性**，不能为了追求极致性能而牺牲系统的稳定性。
