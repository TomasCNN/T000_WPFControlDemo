# 999999009-24_不同工业场景下的 NLog 配置优化方案

工业上位机优化 NLog 的核心原则是**场景匹配、优先级加权**：不存在万能最优配置，所有参数都是在「实时性、日志完整性、磁盘占用、合规性」之间做权衡。不同工位的诉求天差地别：高速视觉工位宁可丢少量日志也不能阻塞采集，合规审计工位宁可增加开销也不能丢失操作记录，无人值守工位第一优先级是绝不能写满磁盘。

以下针对工控最典型的 5 类场景，给出针对性优化思路、关键参数和可直接复用的配置片段，完全贴合线扫视觉、PLC 控制、量产追溯等真实工况。

## 一、高速视觉采集场景（线扫 / 面阵相机、高帧率取图）

### 适用场景

线扫相机采集回调、高速面阵抓拍工位，帧率几十到上百 fps，对应你当前优化取图 CT 的核心场景。

### 核心优先级

**实时性 > 性能 > 日志完整性**

宁可丢弃少量非关键日志，绝对不能拉高取图 CT、造成相机丢帧。

### 核心痛点

- 同步写日志会产生毫秒级 IO 阻塞，直接吃掉你优化出来的 CT 余量；
- 逐帧日志量级极大，容易刷爆内存队列、占用 CPU；
- 高开销的日志渲染器（如调用栈获取）会显著增加单条日志耗时。

### 优化关键配置

1. **精细异步控制**：不使用简化的 `async="true"`，改用 `AsyncWrapper` 显式配置队列参数，溢出策略强制设为 `Discard`（丢弃），绝对禁止 `Block`，否则队列满会直接卡住采集线程。
2. **批量写入降 IO**：调大 `batchSize` 到 100~200，攒够一批再统一写盘，大幅减少磁盘 IO 次数。
3. **日志级别降级**：逐帧图像信息全部设为 `Debug` 级别，生产环境默认关闭，仅保留错误、异常日志。
4. **禁用高开销渲染器**：生产环境禁用 `${callsite}`、`${stacktrace}` 等反射类渲染器，这类字段开销是普通日志的几十倍，仅排障时临时开启。
5. **保持文件句柄常开**：`keepFileOpen="true"`，避免高频开闭文件的额外开销，单进程写入时配合 `concurrentWrites="false"` 进一步提升性能。
6. **队列容量合理限流**：`queueLimit` 设为 5000 左右，防止异常疯狂刷屏撑爆内存。

### 配置示例

xaml:

```xaml
<targets>
  <!-- 高速视觉专用异步队列：精细控制参数，优先保实时性 -->
  <target xsi:type="AsyncWrapper" 
          name="CameraAsync"
          queueLimit="5000"
          overflowAction="Discard"
          batchSize="200"
          timeToSleepBetweenBatches="1">
    <target xsi:type="File"
            name="CameraLog"
            fileName="D:/Logs/camera-${shortdate}.log"
            archiveEvery="Day"
            maxArchiveDays="30"
            keepFileOpen="true"
            concurrentWrites="false"
            encoding="utf-8">
      <!-- 极简布局，去掉所有高开销字段 -->
      <layout>${longdate} | ${level:uppercase=true} | 线程${threadid} | ${message} ${exception:format=ToString}</layout>
    </target>
  </target>
</targets>
```

## 二、实时控制与 PLC 通信场景（运动控制、IO 轮询）

### 适用场景

PLC 周期读写、运动轴控制、传感器信号采集，对时序稳定性、延迟抖动要求极高。

### 核心优先级

**控制线程零阻塞 > 错误日志不丢失 > 普通日志完整性**

### 核心痛点

- 控制线程对延迟敏感，普通轮询日志量大但价值低；
- 通信错误、控制异常必须完整留痕，用于故障追责和定位；
- 普通读写日志刷屏会淹没关键告警信息。

### 优化关键配置

1. **普通读写日志降级**：单次寄存器读写仅打 `Debug`，生产环境不输出，避免日志爆炸。
2. **错误日志独立归档**：所有模块的 `Error/Fatal` 单独进入错误日志文件，保留 90 天，排查问题直接打开该文件，不用在百万行运行日志里翻找。
3. **关键参数强制携带**：通信日志必须包含寄存器地址、写入值、错误码、重试次数，无需抓包就能定位问题。
4. **独立异步队列隔离**：给 PLC 控制模块单独分配异步队列，和视觉日志物理隔离，避免高优先级的控制日志被视觉日志挤压。
5. **失败次数升级告警**：业务层配合逻辑，单次失败打 `Warn`，连续 3 次失败打 `Error`，减少无效告警刷屏。

### 配置示例

xaml:

```xaml
<targets>
  <!-- PLC通信运行日志 -->
  <target xsi:type="AsyncWrapper" name="PlcAsync" queueLimit="3000" overflowAction="Discard">
    <target xsi:type="File" name="PlcLog"
            fileName="D:/Logs/plc-${shortdate}.log"
            archiveEvery="Day" maxArchiveDays="30"
            keepFileOpen="true" encoding="utf-8">
      <layout>${longdate} | ${level} | ${message}</layout>
    </target>
  </target>

  <!-- 全局错误专属日志：所有模块Error/Fatal都进这里，保留90天 -->
  <target xsi:type="AsyncWrapper" name="ErrorAsync" queueLimit="2000" overflowAction="Discard">
    <target xsi:type="File" name="ErrorLog"
            fileName="D:/Logs/error-${shortdate}.log"
            archiveEvery="Day" maxArchiveDays="90"
            keepFileOpen="true" encoding="utf-8">
      <layout>${longdate} | ${level} | ${event-properties:item=Module} | ${message}
${exception:format=ToString,StackTrace:maxInnerExceptionLevel=5}
------------------------------------------------------------------------</layout>
    </target>
  </target>
</targets>

<rules>
  <logger name="*" minlevel="Info" writeTo="PlcLog" />
  <logger name="*" minlevel="Error" writeTo="ErrorLog" />
</rules>
```

## 三、量产追溯与合规审计场景（批量生产、操作留痕）

### 适用场景

量产检测工位、医药 / 食品合规工位、参数修改留痕、产品全链路追溯，需要满足行业审计要求。

### 核心优先级

**日志完整可追溯 > 防篡改 > 性能**

### 核心痛点

- 需要关联批次号、产品 SN、操作人，实现全链路串联；
- 日志需要长期保存，历史记录不能被随意修改删除；
- 审计日志和运行日志混在一起，追溯效率极低。

### 优化关键配置

1. **物理拆分审计日志**：单独拆分「操作审计」日志文件，只记录参数修改、模式切换、批次启停、人工复位，和运行日志完全隔离，专门用于合规审计。
2. **上下文全局透传**：使用 `ScopeContext` 全局注入批次号、工号、产品型号，不用每条日志手动拼接字符串，自动关联到所有同批次日志。
3. **双重切割策略**：按天切割 + 单文件超大小强制切割（如 100MB），防止单日日志过大，单位为**字节**。
4. **长周期归档保留**：审计日志保留 180 天～1 年，按合规要求调整。
5. **配合系统权限防篡改**：日志目录设置 NTFS「仅追加」权限，禁止修改、删除历史日志，满足防篡改要求。

### 配置 + 代码示例

#### 配置片段

xaml:

```xaml
<targets>
  <!-- 操作审计专用日志：单独归档，保留180天 -->
  <target xsi:type="File"
          name="AuditLog"
          fileName="D:/Logs/audit/audit-${shortdate}.log"
          archiveEvery="Day"
          archiveAboveSize="104857600" <!-- 单文件超100MB强制切割 -->
          maxArchiveDays="180"
          keepFileOpen="true"
          encoding="utf-8">
    <!-- 审计固定格式：时间 | 操作人 | 批次号 | 操作内容 -->
    <layout>${longdate} | ${event-properties:item=Operator} | ${event-properties:item=BatchNo} | ${message}</layout>
  </target>
</targets>

<rules>
  <!-- 只有模块名为「操作审计」的日志才写入审计文件 -->
  <logger name="*" minlevel="Info" writeTo="AuditLog">
    <filters>
      <when condition="not equals('${event-properties:item=Module}','操作审计')" action="Ignore"/>
    </filters>
  </logger>
</rules>
```

#### 业务代码注入上下文

csharp:

```c#
// 批次开始时全局注入，后续所有日志自动携带批次号
ScopeContext.PushProperty("BatchNo", "B2026062301");
ScopeContext.PushProperty("Operator", "OP001");

// 记录审计日志
LogHelper.Info("操作审计", "修改缺陷检测阈值：旧值0.85 → 新值0.90，修改成功");
```

## 四、7×24 小时无人值守场景（黑灯产线、无人工作站）

### 适用场景

无人值守检测站、夜班自动产线、连续数月不关机的设备，现场无运维人员。

### 核心优先级

**磁盘不爆满 > 程序不崩溃 > 日志完整性**

### 核心痛点

- 长期运行日志持续累积，极易占满磁盘导致程序崩溃、设备停机；
- 内存、句柄泄漏会让程序越跑越慢，最终异常退出；
- 夜间低峰期日志量小，长期持有句柄属于不必要的资源占用。

### 优化关键配置

1. **双重切割机制**：按自然天切割 + 单文件超大小强制切割，防止单日异常刷屏写爆单个文件、瞬间占满磁盘。
2. **双重过期清理**：`maxArchiveDays`（按天数删除） + `maxArchiveFiles`（按数量兜底）双保险，自动清理过期日志。
3. **异步队列严格限流**：队列满直接丢弃新日志，优先保证主程序不崩溃，绝不本末倒置。
4. **NLog 自身日志降级**：`internalLogLevel="Warn"`，只有框架自身故障才记录，避免自身日志无限膨胀。
5. **空闲自动释放句柄**：设置 `openFileCacheTimeout`，长时间无日志自动释放文件句柄，适配低流量夜间运行场景。
6. **业务层兜底监控**：配合业务代码定时检测磁盘剩余空间，低于 10% 时触发告警。

### 配置示例

xaml:

```xaml
<nlog internalLogLevel="Warn" internalLogFile="D:/Logs/nlog-internal.log">
  <targets async="true" queueLimit="5000" overflowAction="Discard">
    <target xsi:type="File"
            name="MainLog"
            fileName="D:/Logs/app-${shortdate}.log"
            archiveEvery="Day"               <!-- 按天切割 -->
            archiveAboveSize="104857600"     <!-- 单文件超100MB也切割，单位字节 -->
            archiveNumbering="DateAndSequence"
            maxArchiveDays="30"              <!-- 超过30天自动删除 -->
            maxArchiveFiles="100"            <!-- 最多100个文件兜底 -->
            keepFileOpen="true"
            openFileCacheTimeout="3600"      <!-- 1小时无日志自动释放句柄 -->
            concurrentWrites="false"
            encoding="utf-8">
      <layout>${longdate} | ${level:uppercase=true} | 线程${threadid} | ${event-properties:item=Module} | ${message} ${exception:format=ToString}</layout>
    </target>
  </targets>
</nlog>
```

## 五、现场排障与临时调试场景

### 适用场景

现场设备出问题，需要开启 Debug 日志定位，但不能重启程序（重启后故障可能消失）。

### 核心优先级

**灵活可控 > 精准过滤 > 不影响生产**

### 核心痛点

- 全量开启 Debug 日志会疯狂刷屏，找不到重点；
- 很多偶发故障重启程序就无法复现，必须热更新配置。

### 优化关键配置

1. **开启配置热重载**：`autoReload="true"`，修改配置文件后自动生效，无需重启设备，不中断生产。
2. **模块级粒度控制**：只给指定模块开 Debug（如只开 PLC 通信，相机模块保持 Info），避免无关日志刷屏。
3. **单独调试日志文件**：调试日志单独输出，不污染主运行日志，排障结束后可直接删除。
4. **条件过滤器精准过滤**：可配置只打印指定批次、指定错误码、指定工位的日志，进一步缩小范围。

### 配置示例（仅 PLC 模块临时开 Debug）

xaml:

```xaml
<nlog autoReload="true">
  <rules>
    <!-- 全局默认Info级别 -->
    <logger name="*" minlevel="Info" writeTo="MainLog" />
    
    <!-- 排障临时开启：仅PLC通信模块输出Debug -->
    <logger name="*" minlevel="Debug" writeTo="DebugLog">
      <filters>
        <when condition="equals('${event-properties:item=Module}', 'PLC通信')" action="Log"/>
        <when condition="level < LogLevel.Info" action="Ignore"/>
      </filters>
    </logger>
  </rules>
</nlog>
```

## 六、全场景通用优化项（所有工业场景都建议做）

1. **日志路径统一放非系统盘**：比如 `D:/Logs/`，避免系统崩溃重装后日志丢失，也不会被程序更新覆盖。

2. **统一 UTF-8 编码**：防止工控机英文 / 繁体系统下中文乱码。

3. **程序退出强制刷盘**：全局异常、程序退出时调用 `LogManager.Shutdown()`，把内存队列里的日志全部落地，保留完整故障现场。

4. **关闭并发写入**：单进程写日志设 `concurrentWrites="false"`，去掉并发锁开销，提升写入性能。

5. **结构化参数化日志**：使用占位符传递参数，避免字符串拼接产生 GC，也便于后续日志分析工具检索。

   csharp:

   ```c#
   // 推荐：参数化，无GC开销
   LogHelper.Debug("PLC通信", "写入地址{addr}，值{val}", address, value);
   // 不推荐：字符串插值，产生临时对象
   LogHelper.Debug("PLC通信", $"写入地址{address}，值{value}");
   ```

## 七、工业场景避坑红线（绝对不能做）

1. ❌ **实时线程使用同步写入**：相机回调、运动控制线程同步写盘，CT 飙升、丢帧、控制超时，得不偿失。
2. ❌ **高频循环内打 Info 级日志**：100fps 每秒 100 条，一天几百万条，既占磁盘又无实际价值。
3. ❌ **溢出策略设为 Block**：队列满时阻塞业务线程，等于变回同步日志，异步白做，极端情况直接卡死设备。
4. ❌ **滥用 `${callsite}` 等高开销渲染器**：反射获取调用栈开销极大，生产环境禁用，排障时临时开启即可。
5. ❌ **只限制文件数量，不按天数清理**：`maxArchiveFiles` 只能限制总数，`maxArchiveDays` 才能按时间自动过期。
6. ❌ **所有日志塞在一个文件里**：运行、错误、审计混放，排查效率差十倍。
7. ❌ **日志存 C 盘 / 程序目录**：系统崩溃后日志全丢，程序更新时容易被覆盖。
