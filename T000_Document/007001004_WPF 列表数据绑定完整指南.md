# 007001004_WPF 列表数据绑定完整指南

列表数据绑定是 WPF 数据驱动开发的核心场景，核心作用是**用一个集合数据源，自动批量生成一组 UI 元素**，彻底替代后台循环 `Children.Add` 的传统写法，完美契合 MVVM 架构。

结合你熟悉的工业视觉场景：算法输出一批缺陷框，只需要维护一个缺陷集合，界面会自动生成所有矩形 / 多边形标注，增删改全由数据驱动，无需手动操作控件。

------

## 一、核心原理与三要素

列表绑定的本质是「**集合数据源 → 列表控件 → 数据模板**」三者配合：

1. **数据源**：一个实现了 `INotifyCollectionChanged` 的集合（通常是 `ObservableCollection<T>`），元素增删时自动通知 UI；
2. **列表控件**：承载批量元素的容器（`ItemsControl` / `ListBox` / `ListView` 等），负责将集合数据转化为 UI 元素；
3. **数据模板（`ItemTemplate`）**：定义「每个数据项长什么样」，用 XAML 描述单个数据对应的 UI 结构。

### 关键机制

- 列表控件的 `ItemsSource` 属性绑定到集合数据源；
- 控件会自动为集合中的**每一个数据项**，生成一个数据模板的 UI 副本；
- 每个 UI 副本的 `DataContext` 自动设置为对应的数据项，模板内直接绑定单个数据的属性即可。

------

## 二、第一步：准备可观察的数据源

列表绑定的数据源必须支持「集合变更通知」，否则增删元素时 UI 不会自动刷新。

### 1. 集合类型选择

| 集合类型                  | 变更通知   | 适用场景                              |
| :------------------------ | :--------- | :------------------------------------ |
| `ObservableCollection<T>` | ✅ 原生支持 | **列表绑定首选**，元素增删自动刷新 UI |
| `List<T>`                 | ❌ 不支持   | 仅静态不变的列表可用，增删无通知      |

> 工业场景高频坑：用 `List<T>` 绑定后，后台添加元素界面没反应，90% 是这个原因。

### 2. 数据项实现变更通知

集合内的单个数据对象，属性变化时要让 UI 自动更新，必须实现 `INotifyPropertyChanged` 接口。

#### 完整示例：缺陷信息数据模型

csharp:

```c#
using System.ComponentModel;
using System.Runtime.CompilerServices;

/// <summary>
/// 单个缺陷信息（数据项）
/// </summary>
public class DefectInfo : INotifyPropertyChanged
{
    private double _x;
    /// <summary>缺陷框左上角X坐标</summary>
    public double X
    {
        get => _x;
        set { _x = value; OnPropertyChanged(); }
    }

    private double _y;
    /// <summary>缺陷框左上角Y坐标</summary>
    public double Y
    {
        get => _y;
        set { _y = value; OnPropertyChanged(); }
    }

    private double _width;
    public double Width
    {
        get => _width;
        set { _width = value; OnPropertyChanged(); }
    }

    private double _height;
    public double Height
    {
        get => _height;
        set { _height = value; OnPropertyChanged(); }
    }

    private bool _isCritical;
    /// <summary>是否严重缺陷</summary>
    public bool IsCritical
    {
        get => _isCritical;
        set { _isCritical = value; OnPropertyChanged(); }
    }

    // 属性变更通知基础实现
    public event PropertyChangedEventHandler PropertyChanged;
    protected void OnPropertyChanged([CallerMemberName] string propertyName = null)
    {
        PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(propertyName));
    }
}
```

### 3. 视图模型中定义集合

csharp:

```c#
using System.Collections.ObjectModel;

public class DetectViewModel : INotifyPropertyChanged
{
    /// <summary>缺陷集合（列表绑定数据源）</summary>
    public ObservableCollection<DefectInfo> DefectList { get; set; } 
        = new ObservableCollection<DefectInfo>();

    // 模拟算法添加缺陷
    public void AddDefect(double x, double y, double w, double h, bool isCritical)
    {
        DefectList.Add(new DefectInfo
        {
            X = x, Y = y, Width = w, Height = h, IsCritical = isCritical
        });
    }
}
```

> 关键：`ObservableCollection<T>` 自带集合变更通知，调用 `Add/Remove/Clear` 时，UI 会自动同步增删元素。

## 三、第二步：选择合适的列表控件

WPF 提供了多种列表控件，重量和功能不同，按场景选型：

| 控件               | 核心特点                                    | 交互能力           | 适用场景                                     |
| :----------------- | :------------------------------------------ | :----------------- | :------------------------------------------- |
| **`ItemsControl`** | 最轻量，仅做批量渲染                        | 无默认选中、滚动   | 纯展示场景，如批量缺陷框、图形标注、图标阵列 |
| **`ListBox`**      | 继承自 ItemsControl，支持单选 / 多选        | 选中、键盘导航     | 需要选中交互的列表，如缺陷列表、工位列表     |
| **`ListView`**     | 继承自 ListBox，支持视图模式（如 GridView） | 选中、多列布局     | 多列数据列表，如设备参数表                   |
| **`DataGrid`**     | 表格控件，支持编辑、排序、筛选              | 强交互、单元格编辑 | 结构化数据表格，如生产记录、参数配置表       |

> 工业图形渲染场景，绝大多数用 `ItemsControl` 即可，它最轻量化，没有选中、滚动等额外开销，最适合批量绘制 ROI、缺陷框、标记点。

## 四、第三步：核心配置（四大关键属性）

列表绑定的核心是四个属性的配置，决定了「数据从哪来、每项长什么样、用什么布局、怎么定位」。

### 1. `ItemsSource`：绑定数据源

列表控件的核心属性，绑定到集合数据源，是所有列表绑定的入口。

xaml:

```xaml
<!-- 把控件的数据源绑定到 ViewModel 的 DefectList 集合 -->
<ItemsControl ItemsSource="{Binding DefectList}">
</ItemsControl>
```

### 2. `ItemTemplate`：数据模板（每项长什么样）

定义「一个数据项对应什么样的 UI」，是列表绑定的灵魂。模板内部的 `DataContext` 自动指向单个数据项，直接绑定属性即可。

#### 示例：每个缺陷对应一个矩形框

xaml:

```xaml
<ItemsControl ItemsSource="{Binding DefectList}">
    <ItemsControl.ItemTemplate>
        <DataTemplate>
            <!-- 单个缺陷的 UI：矩形框
                 这里的绑定，都是绑定 DefectInfo 类的属性 -->
            <Rectangle Width="{Binding Width}"
                       Height="{Binding Height}"
                       Stroke="{Binding IsCritical, Converter={StaticResource CriticalToColorConverter}}"
                       StrokeThickness="1.5"
                       Fill="Transparent"/>
        </DataTemplate>
    </ItemsControl.ItemTemplate>
</ItemsControl>
```

### 3. `ItemsPanel`：布局面板（项怎么排列）

指定所有列表项用什么布局容器排列，默认是垂直的 `StackPanel`。

- 普通列表：默认 `StackPanel` 即可；
- 图形标注场景：必须改成 `Canvas`，才能支持绝对定位。

xaml:

```xaml
<ItemsControl ItemsSource="{Binding DefectList}">
    <!-- 指定用 Canvas 作为布局容器，支持绝对坐标 -->
    <ItemsControl.ItemsPanel>
        <ItemsPanelTemplate>
            <Canvas Width="800" Height="600" Background="#1E1E1E"/>
        </ItemsPanelTemplate>
    </ItemsControl.ItemsPanel>
</ItemsControl>
```

### 4. `ItemContainerStyle`：项容器样式（怎么定位）

每个列表项都会被包裹在一个「容器」里（`ItemsControl` 对应 `ContentPresenter`），定位、对齐等容器级属性，需要通过 `ItemContainerStyle` 设置。

#### 示例：Canvas 绝对定位

在 Canvas 布局下，通过 `Canvas.Left` / `Canvas.Top` 附加属性定位每个缺陷框：

xaml:

```xaml
<ItemsControl ItemsSource="{Binding DefectList}">
    <ItemsControl.ItemsPanel>
        <ItemsPanelTemplate>
            <Canvas Width="800" Height="600" Background="#1E1E1E"/>
        </ItemsPanelTemplate>
    </ItemsPanelTemplate>

    <!-- 项容器样式：设置每个元素在 Canvas 中的位置 -->
    <ItemsControl.ItemContainerStyle>
        <Style TargetType="ContentPresenter">
            <Setter Property="Canvas.Left" Value="{Binding X}"/>
            <Setter Property="Canvas.Top" Value="{Binding Y}"/>
        </Style>
    </ItemsControl.ItemContainerStyle>

    <ItemsControl.ItemTemplate>
        <DataTemplate>
            <Rectangle Width="{Binding Width}"
                       Height="{Binding Height}"
                       Stroke="{Binding IsCritical, Converter={StaticResource CriticalToColorConverter}}"
                       StrokeThickness="1.5"
                       Fill="Transparent"/>
        </DataTemplate>
    </ItemsControl.ItemTemplate>
</ItemsControl>
```

> 关键注意：`Canvas.Left/Top` 是附加属性，必须写在**项容器**上，不能写在 `DataTemplate` 内部的元素上，否则定位不生效。

## 五、完整实战案例：批量渲染缺陷框

这是工业视觉场景最经典的列表绑定用法，完整可运行。

### 1. 准备数据源（前面已定义）

- `DefectInfo` 单个缺陷类，实现 `INotifyPropertyChanged`
- `DetectViewModel` 视图模型，包含 `ObservableCollection<DefectInfo> DefectList`

### 2. 窗口设置 DataContext

csharp:

```c#
public partial class MainWindow : Window
{
    public DetectViewModel ViewModel { get; } = new DetectViewModel();

    public MainWindow()
    {
        InitializeComponent();
        this.DataContext = ViewModel;

        // 模拟初始化3个缺陷
        ViewModel.AddDefect(100, 100, 80, 50, false);
        ViewModel.AddDefect(250, 180, 120, 90, true);
        ViewModel.AddDefect(400, 120, 60, 70, false);
    }
}
```

### 3. XAML 完整绑定代码

xaml:

```xaml
<Window x:Class="Demo.MainWindow"
        xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
        xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
        xmlns:local="clr-namespace:Demo"
        Title="缺陷检测列表绑定" Height="700" Width="900">
    <Window.Resources>
        <!-- 严重程度转颜色转换器 -->
        <local:CriticalToColorConverter x:Key="CriticalToColorConverter"/>
    </Window.Resources>

    <Grid Margin="20">
        <!-- 批量缺陷标注画布 -->
        <ItemsControl ItemsSource="{Binding DefectList}">
            <!-- 1. 布局容器：Canvas 绝对定位 -->
            <ItemsControl.ItemsPanel>
                <ItemsPanelTemplate>
                    <Canvas Width="800" Height="600" Background="#1E1E1E" SnapsToDevicePixels="True"/>
                </ItemsPanelTemplate>
            </ItemsControl.ItemsPanel>

            <!-- 2. 项容器：定位每个缺陷框的位置 -->
            <ItemsControl.ItemContainerStyle>
                <Style TargetType="ContentPresenter">
                    <Setter Property="Canvas.Left" Value="{Binding X}"/>
                    <Setter Property="Canvas.Top" Value="{Binding Y}"/>
                </Style>
            </ItemsControl.ItemContainerStyle>

            <!-- 3. 数据模板：单个缺陷框的外观 -->
            <ItemsControl.ItemTemplate>
                <DataTemplate>
                    <Rectangle Width="{Binding Width}"
                               Height="{Binding Height}"
                               Stroke="{Binding IsCritical, Converter={StaticResource CriticalToColorConverter}}"
                               StrokeThickness="1.5"
                               Fill="#22FFFFFF"
                               StrokeDashArray="{Binding IsCritical, Converter={StaticResource CriticalToDashConverter}}"/>
                </DataTemplate>
            </ItemsControl.ItemTemplate>
        </ItemsControl>
    </Grid>
</Window>
```

### 效果

- 后台只需要操作 `DefectList` 集合：`Add` 添加缺陷、`Remove` 移除缺陷、修改元素属性；
- UI 会自动同步所有变化，不需要写一行操作 `Canvas.Children` 的代码，完全符合 MVVM 架构。

## 六、进阶：带选中交互的列表（ListBox）

如果需要点击选中某个缺陷、高亮显示，改用 `ListBox` 即可，绑定逻辑完全一致，额外支持 `SelectedItem` 绑定。

### 示例：可选中的缺陷列表

xaml:

```xaml
<ListBox ItemsSource="{Binding DefectList}"
         SelectedItem="{Binding SelectedDefect, Mode=TwoWay}">
    <ListBox.ItemsPanel>
        <ItemsPanelTemplate>
            <Canvas Width="800" Height="600" Background="#1E1E1E"/>
        </ItemsPanelTemplate>
    </ListBox.ItemsPanel>

    <ListBox.ItemContainerStyle>
        <Style TargetType="ListBoxItem">
            <Setter Property="Canvas.Left" Value="{Binding X}"/>
            <Setter Property="Canvas.Top" Value="{Binding Y}"/>
            <!-- 去掉默认选中背景 -->
            <Setter Property="Background" Value="Transparent"/>
            <Setter Property="Template">
                <Setter.Value>
                    <ControlTemplate TargetType="ListBoxItem">
                        <ContentPresenter/>
                    </ControlTemplate>
                </Setter.Value>
            </Setter>
        </Style>
    </ListBox.ItemContainerStyle>

    <ListBox.ItemTemplate>
        <DataTemplate>
            <!-- 选中时边框加粗，通过样式触发器实现 -->
            <Rectangle Width="{Binding Width}" Height="{Binding Height}"
                       Stroke="Cyan" StrokeThickness="1.5" Fill="Transparent">
                <Rectangle.Style>
                    <Style TargetType="Rectangle">
                        <Style.Triggers>
                            <DataTrigger Binding="{Binding IsSelected, RelativeSource={RelativeSource AncestorType=ListBoxItem}}" Value="True">
                                <Setter Property="StrokeThickness" Value="3"/>
                                <Setter Property="Stroke" Value="Yellow"/>
                            </DataTrigger>
                        </Style.Triggers>
                    </Style>
                </Rectangle.Style>
            </Rectangle>
        </DataTemplate>
    </ListBox.ItemTemplate>
</ListBox>
```

ViewModel 中新增选中项属性：

csharp:

```c#
private DefectInfo _selectedDefect;
public DefectInfo SelectedDefect
{
    get => _selectedDefect;
    set { _selectedDefect = value; OnPropertyChanged(); }
}
```

点击界面上的缺陷框，`SelectedDefect` 会自动更新；后台修改 `SelectedDefect`，界面也会自动切换选中态，双向同步。

## 七、常见坑与最佳实践

### 1. 集合增删 UI 不刷新？

- 检查是否用了 `ObservableCollection<T>`，`List<T>` 没有集合变更通知；

- 如果是替换整个集合实例，需要触发属性变更通知：

  csharp:

  ```c#
  private ObservableCollection<DefectInfo> _defectList;
  public ObservableCollection<DefectInfo> DefectList
  {
      get => _defectList;
      set { _defectList = value; OnPropertyChanged(); }
  }
  ```

### 2. 修改单个项属性 UI 不更新？

- 检查数据项类是否实现了 `INotifyPropertyChanged`，属性 setter 是否触发了通知。

### 3. Canvas 定位不生效？

- `Canvas.Left/Top` 必须写在 **ItemContainerStyle** 里，作用于项容器；
- 写在 `DataTemplate` 内部的元素上是无效的，因为容器本身还在原点。

### 4. 大量数据卡顿？

- 开启 UI 虚拟化：`VirtualizingStackPanel.IsVirtualizing="True"`，仅渲染可视区域的项；
- 图形场景下，超大量元素（>500）建议改用 `DrawingVisual` 低层绘制。

### 5. 最佳实践总结

1. 纯展示、无交互的批量渲染，优先用 `ItemsControl`，最轻量；
2. 需要选中、键盘交互，用 `ListBox`；
3. 集合统一用 `ObservableCollection<T>`；
4. 数据项实现 `INotifyPropertyChanged`；
5. 布局用 `ItemsPanel` 控制，定位用 `ItemContainerStyle` 控制，外观用 `ItemTemplate` 控制，职责分离；
6. 列表绑定彻底替代后台循环添加控件，坚持数据驱动，符合 MVVM 架构。
