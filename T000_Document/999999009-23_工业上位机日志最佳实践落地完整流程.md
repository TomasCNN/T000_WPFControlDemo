# 999999009-23_工业上位机日志最佳实践落地完整流程

整套落地分为 6 大阶段：前期框架选型与配置规范、统一日志工具封装、业务分层埋点规范、运行环境优化、上线生产管控、故障追溯运维，完全贴合你线扫相机 + PLC+MES 视觉项目场景。

## 一、阶段 1：项目初始化 —— 统一 NLog 标准配置（从源头锁死规范）

### 1. 强制固定文件部署规则

1. 项目根目录添加 `NLog.config`，属性：**复制到输出目录 = 如果较新则复制**；
2. 日志根目录固定在**非系统盘** `D:\DeviceLogs\工位编号\`，禁止 C 盘、程序运行目录；
3. 编码统一 `UTF-8`，解决工控机多国语言系统中文乱码。

### 2. 全局异步标准模板（强制所有项目统一）

核心约束：

- 全局异步 `async="true"`，实时线程零阻塞；
- 队列限流 + 溢出丢弃，绝不阻塞产线；
- 按天切割 + 自动过期清理，防止磁盘占满；
- 日志分流：主运行日志、错误日志、审计日志三类分离。

xaml：

```xaml
<?xml version="1.0" encoding="utf-8" ?>
<nlog xmlns="http://www.nlog-project.org/schemas/NLog.xsd"
      xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
      autoReload="true"
      internalLogLevel="Warn"
      internalLogFile="D:\DeviceLogs\ST01\nlog-internal.log">

  <!-- 全局异步配置：工业硬性标准 -->
  <targets async="true"
           queueLimit="5000"
           overflowAction="Discard"
           batchSize="100"
           timeToSleepBetweenBatches="1">

    <!-- 1. 主运行日志：设备正常流程、状态切换，保存30天 -->
    <target xsi:type="File"
            name="MainTarget"
            fileName="D:\DeviceLogs\ST01\run-${shortdate}.log"
            encoding="utf-8"
            keepFileOpen="true"
            concurrentWrites="false"
            archiveEvery="Day"
            maxArchiveDays="30"
            archiveNumbering="Date">
      <layout>${longdate} | ${level:uppercase=true:padding=-5} | 线程${threadid:padding=2} | ${event-properties:item=Module:padding=-10} | ${message} ${exception:format=ToString,StackTrace:maxInnerExceptionLevel=3}</layout>
    </target>

    <!-- 2. 错误专属日志：Error/Fatal单独归档，保存90天，故障优先查看 -->
    <target xsi:type="File"
            name="ErrorTarget"
            fileName="D:\DeviceLogs\ST01\error-${shortdate}.log"
            encoding="utf-8"
            keepFileOpen="true"
            archiveEvery="Day"
            maxArchiveDays="90">
      <layout>${longdate} | ${level} | ${event-properties:item=Module} | ${message}
${exception:format=ToString,StackTrace}
------------------------------------------------------------------------</layout>
    </target>

    <!-- 3. 审计日志：参数修改、人工操作、批次切换，合规追溯180天 -->
    <target xsi:type="File"
            name="AuditTarget"
            fileName="D:\DeviceLogs\ST01\audit-${shortdate}.log"
            encoding="utf-8"
            archiveEvery="Day"
            maxArchiveDays="180">
      <layout>${longdate} | ${event-properties:item=Operator} | ${event-properties:item=BatchNo} | ${message}</layout>
    </target>

    <!-- 4. 开发调试控制台，生产环境可注释 -->
    <target xsi:type="ColoredConsole" name="ConsoleTarget" layout="${time:format=HH\:mm\:ss.fff} | ${event-properties:item=Module} | ${message}"/>
  </targets>

  <!-- 日志输出规则：生产环境默认Info -->
  <rules>
    <logger name="*" minlevel="Info" writeTo="MainTarget"/>
    <logger name="*" minlevel="Error" writeTo="ErrorTarget"/>
    <logger name="*" minlevel="Info" writeTo="AuditTarget">
      <filters>
        <when condition="not equals('${event-properties:item=Module}','操作审计')" action="Ignore"/>
      </filters>
    </logger>
    <logger name="*" minlevel="Debug" writeTo="ConsoleTarget"/>
  </rules>
</nlog>
```

### 3. 配置落地约束（团队统一规范）

1. 禁止单独给某个 Target 关闭异步；
2. 禁止修改 `overflowAction="Block"`；
3. 生产环境 `minlevel="Info"`，Debug 仅调试临时开启；
4. 禁止删除自动清理 `maxArchiveDays`，杜绝磁盘爆满风险。

## 二、阶段 2：封装统一静态日志工具类（业务代码零混乱）

### 目标

1. 强制传入模块名，每条日志自带模块标识；
2. 分层 Debug/Info/Warn/Error/Fatal，统一异常堆栈输出；
3. 封装业务上下文（批次、操作员）快速注入方法；
4. 隔离 NLog 底层，后续更换日志框架无需改全业务代码。

csharp:

```c#
using NLog;
using NLog.Scope;
using System;

public static class LogHelper
{
    private static readonly Logger _logger = LogManager.GetCurrentClassLogger();

    #region 业务全局上下文注入（批次、工位、操作员，全链路自动携带）
    /// <summary>设置当前生产批次</summary>
    public static void SetBatch(string batchNo)
    {
        ScopeContext.PushProperty("BatchNo", batchNo);
    }

    /// <summary>设置当前操作员工号</summary>
    public static void SetOperator(string opNo)
    {
        ScopeContext.PushProperty("Operator", opNo);
    }
    #endregion

    #region 内部统一携带模块名
    private static void PushModule(string moduleName)
    {
        ScopeContext.PushProperty("Module", moduleName);
    }
    #endregion

    /// <summary>调试日志：开发排查，生产默认关闭</summary>
    public static void Debug(string module, string msg)
    {
        PushModule(module);
        _logger.Debug(msg);
    }

    /// <summary>普通信息：流程节点、状态切换</summary>
    public static void Info(string module, string msg)
    {
        PushModule(module);
        _logger.Info(msg);
    }

    /// <summary>警告：单次异常、阈值临近、重试成功</summary>
    public static void Warn(string module, string msg)
    {
        PushModule(module);
        _logger.Warn(msg);
    }

    /// <summary>错误：功能失效，必须携带完整异常堆栈</summary>
    public static void Error(string module, string msg, Exception ex = null)
    {
        PushModule(module);
        if (ex == null)
            _logger.Error(msg);
        else
            _logger.Error(ex, msg);
    }

    /// <summary>致命错误：紧急停机、程序崩溃</summary>
    public static void Fatal(string module, string msg, Exception ex)
    {
        PushModule(module);
        _logger.Fatal(ex, msg);
    }

    /// <summary>程序正常退出，刷新异步队列，防止日志丢失</summary>
    public static void FlushAndShutdown()
    {
        LogManager.Shutdown();
    }
}
```

### 强制编码规范

1. 所有模块名称统一命名：`线扫相机`、`PLC通信`、`检测算法`、`MES交互`、`操作审计`；
2. Error/Fatal 必须传入完整 Exception，禁止只打印 ex.Message；
3. 禁止业务代码直接引用 NLog 的 Logger，只能调用 LogHelper。

## 三、阶段 3：业务分层埋点规范（核心落地，区分不同工业模块）

按照项目五大核心模块，规定**哪些场景必须打日志、哪些禁止高频打印**，直接约束开发人员编码习惯。

### 模块 1：高速相机采集（线扫 / 面阵回调，最高实时性要求）

#### 必须打印

1. 相机初始化成功 / 失败；
2. 取图连续超时、内存不足、图像转换异常（Error）；
3. 相机断开、重连告警（Warn）。

#### 限制规则

1. **每一帧图像信息只允许打 Debug**，生产环境关闭，禁止 Info 刷屏；
2. 回调内禁止复杂字符串拼接、大数组打印；
3. 帧耗时统计每 50 帧打印一次 Info，禁止逐帧输出。

示例标准写法：

csharp:

```c#
private static void LineScanCCD_OnResultDataGrab(OpencvImage opencvImage)
{
    try
    {
        if (!LineScanCCD.IsOpen())
        {
            LogHelper.Error("线扫相机", "取图回调触发，但相机未初始化");
            return;
        }
        using var bmp = FromOpencvImage(opencvImage);
        lock (_imgLock)
        {
            LineScanImage?.Dispose();
            LineScanImage = (Bitmap)bmp.Clone();
        }
        _imageReadyEvent.Set();
        // 逐帧细节Debug，生产无开销
        LogHelper.Debug("线扫相机", $"图像宽{opencvImage.Width} 高{opencvImage.Height}");
    }
    catch (Exception ex)
    {
        LogHelper.Error("线扫相机", "图像采集回调异常", ex);
    }
}
```

### 模块 2：PLC / 运动控制实时线程

#### 必须打印

1. PLC 连接断开、重连、读写失败；
2. 寄存器读写错误码、超时、多次重试；
3. 急停、安全门、限位报警。

#### 限制规则

单次轮询读写仅 Debug 打印，正常读写不输出 Info，避免日志爆炸。

### 模块 3：生产流程 & 追溯（审计强制埋点）

所有流程节点必须 Info，自动携带批次、操作员上下文：

1. 批次启动、批次结束、计划产量完成；
2. 产品 SN 检测 OK/NG、缺陷类型、检测耗时；
3. 模式切换：自动 / 手动 / 待机；
4. 参数修改（审计模块，单独进入 Audit 日志）。

审计标准示例（自动分离审计文件）：

csharp:

```c#
public void UpdateDetectThreshold(double newVal)
{

    DetectThreshold = newVal;

    LogHelper.Info("操作审计", $"修改缺陷阈值，原值{old:F3}，新值{newVal:F3}");
```

### 模块 4：MES / 数据库通信

1. MES 上报成功 / 失败、重传次数；
2. 数据库连接超时、写入异常；
3. 接口返回错误码，完整记录请求关键字段。

### 模块 5：全局异常兜底（防止静默吞错无日志）

程序入口绑定全局未捕获异常，强制记录 Fatal 日志并刷盘：

csharp:

```c#
static Program()
{
    AppDomain.CurrentDomain.UnhandledException += (s, e) =>
    {
        var ex = e.ExceptionObject as Exception;
        LogHelper.Fatal("主程序", "全局未捕获异常，程序即将退出", ex);
        LogHelper.FlushAndShutdown();
    };
}
```

## 四、阶段 4：运行时环境优化（部署上线配套规范）

### 1. 目录权限规范

1. 工控机程序使用管理员权限运行，保证日志文件夹读写权限；
2. Audit 审计日志文件夹设置 NTFS 只读权限（仅程序追加，禁止人工删除修改，满足合规）。

### 2. 磁盘监控兜底（无人黑灯产线必备）

业务层增加磁盘剩余空间检测，定时打印 Warn 日志预警：

csharp:

```c#
// 定时任务每5分钟执行
void CheckDiskSpace()
{
    var drive = new DriveInfo("D");
    double freePercent = (double)drive.AvailableFreeSpace / drive.TotalSize;
    if (freePercent < 0.1)
    {
        LogHelper.Warn("磁盘监控", $"日志盘剩余空间不足10%，请清理历史日志");
    }
}
```

### 3. 程序退出强制刷盘

窗口关闭、正常停机按钮触发时调用日志关闭方法，避免异步队列残留日志丢失：

csharp:

```c#
private void Window_Closing(object sender, System.ComponentModel.CancelEventArgs e)
{
    LogHelper.FlushAndShutdown();
}
```

## 五、阶段 5：开发 / 测试 / 生产三套环境分级管控

### 1. 开发环境（Debug 模式）

`minlevel="Debug"`，完整输出逐帧、通信细节，方便调试。

### 2. 现场测试环境

`minlevel="Info"`，关闭逐帧 Debug，保留告警与错误；可临时修改配置开 Debug，无需重启程序（autoReload=true）。

### 3. 量产生产环境

固定`minlevel="Info"`，禁止长期开启 Debug；

- 运行日志 30 天自动清理；
- 错误日志 90 天；
- 审计日志 180 天；
- 禁止删除 NLog.config，禁止修改异步、队列溢出参数。

### 生产环境禁止行为

1. 禁止在相机、PLC 实时循环打印 Info；
2. 禁止日志明文记录数据库密码、PLC 密钥、核心工艺配方；
3. 禁止将图像二进制、超大报文写入日志；
4. 禁止手动删除当日未归档日志。

## 六、阶段 6：运维故障追溯标准化流程（落地最佳实践价值）

### 故障排查标准步骤

1. 优先打开`error-xxxx.log`，筛选 Fatal/Error，直接定位异常堆栈；
2. 携带异常内的线程 ID，去 run 日志筛选对应线程时序；
3. 产品 NG / 批次问题，打开 audit 日志，通过 BatchNo 串联全流程操作；
4. 取图卡顿、CT 过高，筛选性能耗时 Info 日志，对比历史耗时定位性能退化。

### 日志定期运维规范

1. 每周远程巡检磁盘占用，提前清理异常膨胀日志；
2. 设备年度保养时备份全年审计日志，归档存储；
3. 程序升级不删除历史日志目录，只新增当日日志文件。

## 七、完整项目落地检查清单（代码提交 / 上线前校验）

### 配置检查

-  targets 开启全局 async 异步，queueLimit=5000，overflowAction=Discard
-  日志文件按天切割，配置 maxArchiveDays 自动清理
-  日志路径为 D 盘非系统分区，分 run/error/audit 三类文件
-  autoReload=true，支持热更新日志级别

### 代码检查

-  全部日志统一使用 LogHelper，传入模块名
-  实时采集循环无 Info 刷屏，帧细节仅 Debug
-  所有 catch 异常均调用 LogHelper.Error 携带 ex
-  批次、操作员使用 ScopeContext 统一注入上下文
-  程序退出、全局异常执行 FlushAndShutdown 刷盘

### 上线环境检查

-  生产配置 minlevel=Info，未长期开启 Debug
-  审计目录设置只读防篡改权限
-  磁盘空间监控定时打印预警日志
-  无敏感密钥、配方明文输出日志
