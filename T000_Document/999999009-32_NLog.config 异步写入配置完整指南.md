# 999999009-32_NLog.config 异步写入配置完整指南

NLog 异步写入的核心是 `AsyncWrapper` 异步包装器，配置方式分两种：**全局异步（一行配置全量生效，工业首选）** 和 **单目标独立异步（模块队列隔离，高阶场景用）**。下面结合工控场景给出配置方法、关键参数、完整模板和避坑要点。

------

## 一、方式一：全局异步（工业首选，最简单通用）

### 配置方法

只需要在 `<targets>` 根节点上加 `async="true"` 属性，NLog 会自动给内部每一个 target 外层包裹一层 `AsyncWrapper`，所有日志自动升级为后台线程异步写入，业务代码零改动。

xaml:

```xaml
<!-- 核心：给 targets 加 async="true"，内部所有目标自动异步 -->
<targets async="true">
  <!-- 你的所有日志目标，原封不动放这里 -->
  <target xsi:type="File" name="MainLog" ... />
  <target xsi:type="File" name="ErrorLog" ... />
</targets>
```

> 本质：这是 NLog 提供的语法糖，等价于自动给每个 target 套了一层 `AsyncWrapper`，无需手动逐个包装。

### 适用场景

绝大多数工业上位机项目，快速落地、配置简洁，满足 90% 以上的工控需求。

------

## 二、方式二：单目标独立异步（队列物理隔离）

### 配置方法

手动给指定 target 外层包裹 `<target xsi:type="AsyncWrapper">`，可以给不同模块（相机、PLC、MES）分配独立的内存队列和消费线程，避免高流量的视觉日志挤压高优先级的控制日志。

xaml:

```xaml
<targets>
  <!-- 相机日志：独立异步队列，大流量，溢出丢弃 -->
  <target xsi:type="AsyncWrapper"
          name="CameraAsync"
          queueLimit="5000"
          overflowAction="Discard"
          batchSize="200">
    <target xsi:type="File" name="CameraLog"
            fileName="D:/Logs/camera-${shortdate}.log"
            ... />
  </target>

  <!-- PLC控制日志：独立异步队列，优先级高 -->
  <target xsi:type="AsyncWrapper"
          name="PlcAsync"
          queueLimit="2000"
          overflowAction="Discard">
    <target xsi:type="File" name="PlcLog"
            fileName="D:/Logs/plc-${shortdate}.log"
            ... />
  </target>
</targets>
```

### 适用场景

- 线扫相机等高帧率模块 + PLC 实时控制模块并存的工位；
- 需要隔离不同优先级日志，避免普通日志挤占故障告警的场景。

------

## 三、异步核心参数详解（工业场景推荐值）

所有异步参数都可以加在 `<targets async="true">`（全局）或 `<target xsi:type="AsyncWrapper">`（单目标）节点上。

| 参数                        | 作用                           | 工业推荐值                  | 关键说明                                                     |
| :-------------------------- | :----------------------------- | :-------------------------- | :----------------------------------------------------------- |
| `queueLimit`                | 内存队列最大容纳日志条数       | `5000`                      | 防止异常疯狂刷屏撑爆内存，必须设上限                         |
| `overflowAction`            | 队列满后的处理策略             | **`Discard`（丢弃新日志）** | 工业场景铁律：绝对不能设 `Block`，否则队列满会直接卡住业务线程，异步白做 |
| `batchSize`                 | 后台线程一次批量写入的条数     | `100`                       | 攒够一批再写盘，大幅减少磁盘 IO 次数；数值越大性能越高，落地延迟略高 |
| `timeToSleepBetweenBatches` | 两次批量写盘的休眠间隔（毫秒） | `1`                         | 平衡 CPU 占用和日志实时性，1ms 几乎无感知                    |

> 三个可选溢出策略：
>
> - `Discard`：丢弃新日志，业务线程不阻塞（工业必选）
> - `Block`：阻塞业务线程等待空位（工控严禁使用）
> - `Grow`：无限扩容队列，极端情况会导致内存溢出 OOM（不推荐）

## 四、完整工业级配置模板（可直接复制使用）

包含：全局异步、按天切割、自动清理 30 天、错误日志单独归档、工业标准格式，适配线扫视觉 + PLC 控制的典型上位机场景。

xaml:

```xaml
<?xml version="1.0" encoding="utf-8" ?>
<nlog xmlns="http://www.nlog-project.org/schemas/NLog.xsd"
      xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
      autoReload="true"
      internalLogLevel="Warn"
      internalLogFile="D:/Logs/nlog-internal.log">

  <!-- ========== 核心：全局异步 + 工业级参数 ========== -->
  <targets async="true"
           queueLimit="5000"
           overflowAction="Discard"
           batchSize="100"
           timeToSleepBetweenBatches="1">

    <!-- 1. 主运行日志：按天切割，保留30天 -->
    <target xsi:type="File"
            name="MainLog"
            fileName="D:/Logs/app-${shortdate}.log"
            archiveEvery="Day"
            maxArchiveDays="30"
            keepFileOpen="true"
            concurrentWrites="false"
            encoding="utf-8">
      <layout>${longdate} | ${level:uppercase=true:padding=-5} | 线程${threadid:padding=2} | ${event-properties:item=Module:padding=-10} | ${message} ${onexception:inner=${newline}   ${exception:format=ToString,StackTrace:maxInnerExceptionLevel=3}}</layout>
    </target>

    <!-- 2. 错误专属日志：仅Error/Fatal，保留90天 -->
    <target xsi:type="File"
            name="ErrorLog"
            fileName="D:/Logs/error-${shortdate}.log"
            archiveEvery="Day"
            maxArchiveDays="90"
            keepFileOpen="true"
            encoding="utf-8">
      <layout>${longdate} | ${level:uppercase=true} | ${event-properties:item=Module} | ${message}
${exception:format=ToString,StackTrace:maxInnerExceptionLevel=5}
----------------------------------------------------------------------</layout>
    </target>

    <!-- 3. 控制台输出（开发调试用） -->
    <target xsi:type="ColoredConsole"
            name="ConsoleLog"
            layout="${time:format=HH\:mm\:ss.fff} | ${level:uppercase=true:padding=-5} | ${event-properties:item=Module} | ${message}" />
  </targets>

  <!-- 日志路由规则 -->
  <rules>
    <logger name="*" minlevel="Info" writeTo="MainLog" />
    <logger name="*" minlevel="Error" writeTo="ErrorLog" />
    <logger name="*" minlevel="Debug" writeTo="ConsoleLog" />
  </rules>
</nlog>
```

## 五、常见坑与注意事项

### 1. `async="true"` 放错节点（90% 的新手踩坑）

✅ **正确**：写在 `<targets>` 根节点上

xaml:

```xaml
<targets async="true"> ... </targets>
```

❌ **错误**：写在单个 `<target>` 节点上，完全不生效

xaml:

```xaml
<target xsi:type="File" async="true" ... /> <!-- 无效 -->
```

### 2. 配置文件没复制到输出目录

`NLog.config` 必须设置属性：**复制到输出目录 → 如果较新则复制**，否则程序运行时找不到配置，默认退化为同步模式，甚至完全不输出日志。

### 3. 溢出策略设为 `Block`

工业场景绝对禁止 `overflowAction="Block"`，队列满时会阻塞相机回调、PLC 控制等实时线程，直接导致丢帧、控制超时，失去异步的意义。

### 4. 误以为异步了就可以疯狂刷屏

异步只是把磁盘 IO 转移到后台线程，**字符串格式化、对象封装、入队操作依然在业务线程执行**。高帧率回调里逐帧打 Info 依然会占用 CPU、产生 GC，逐帧细节必须降级为 Debug 级别，生产环境默认关闭。

### 5. 程序退出不刷盘

异步日志存在内存队列，程序异常崩溃或强制退出时，未写入磁盘的日志会丢失。必须在全局异常、窗口关闭时调用：

csharp:

```c#
LogManager.Shutdown();
```

## 六、快速验证异步是否生效

1. **耗时法（最直观）**

   

   在日志调用前后加 `Stopwatch`，单条日志耗时 <0.1ms（显示 0ms）即为异步生效；

2. **延迟法**

   

   连续打 10 条日志，打完立刻看文件，不会立刻全部出现，有轻微延迟即为异步；

3. **内部日志法**

   把 `internalLogLevel`改成 `Debug`，运行后在内部日志里搜索 `AsyncWrapper`，能找到初始化记录即为配置生效。
