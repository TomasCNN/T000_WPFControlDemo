这段代码是 WPF 中 `System.Windows.Shapes.Shape` 核心基类的成员精简定义，它是所有内置矢量图形（`Rectangle`/`Ellipse`/`Line`/`Polygon`/`Polyline`/`Path`）的共同父类。其核心设计思想是：**把底层几何绘图能力封装为标准 `FrameworkElement`**，让矢量图形天然融入 WPF 布局、数据绑定、样式动画、路由事件体系，是工业上位机绘制检测框、运动轨迹、工位示意图、缺陷标记的核心 UI 基类。

下面逐字段、逐属性、逐方法深度解析其官方定义、设计意图与工业场景用法。

------

## 一、静态依赖属性字段：WPF 属性系统的底层支撑

开头 11 个 `public static readonly DependencyProperty` 字段，是 WPF 依赖属性系统的**标识符字段**，与下方每一个实例属性一一对应（命名规则：`属性名 + Property`）。

### 设计意义

1. **原生支持 WPF 核心特性**：所有图形属性都基于依赖属性注册，天然支持数据绑定、样式复用、动画驱动、属性值继承、变更通知，这是 Shape 能完美适配 MVVM 模式的根本原因；
2. **内存高效**：静态字段在类的静态构造函数中完成属性元数据注册，所有 Shape 实例共享同一份属性定义，避免每个实例重复存储属性元数据；
3. **统一变更通知**：属性值变化时自动触发布局重排、渲染重绘，不需要开发者手动刷新界面。

------

## 二、构造函数

csharp:

```c#
protected Shape();
```

1. 访问修饰符为 `protected`：因为 `Shape` 是抽象类，**禁止直接实例化**，只能由派生类（如 `Rectangle`、`Ellipse`）在构造时调用基类构造；
2. 构造函数仅做轻量初始化：如应用属性默认值、初始化渲染资源，不执行重量级几何计算，保证实例化性能。

------

## 三、实例属性逐类深度解析

### 1. 填充属性：控制图形内部区域

csharp:

```c#
public Brush Fill { get; set; }
```

- **类型**：`System.Windows.Media.Brush`
- **默认值**：`null`（无填充，内部完全透明）
- **官方作用**：定义封闭图形内部区域的填充画刷，支持纯色、线性渐变、径向渐变、图像、纹理等所有 WPF 画刷类型。
- **注意事项**：`Line`、`Polyline` 等非闭合图形没有内部区域，设置 `Fill` 无效。
- **工业场景**：用不同颜色填充区分 OK/NG 检测区域、工位状态高亮、选中区域标记。

------

### 2. 描边属性族：控制图形轮廓线条（工业最高频）

这是 Shape 最庞大的属性组，完整对应底层 `Pen` 对象的全部参数，控制线条粗细、端点、拐角、虚线等所有轮廓特性。

| 属性                                   | 类型               | 核心作用                                                     | 工业场景典型用法                                             |
| :------------------------------------- | :----------------- | :----------------------------------------------------------- | :----------------------------------------------------------- |
| `Stroke`                               | `Brush`            | 轮廓线条的画刷 / 颜色，为 `null` 时线条完全不显示            | 必须和 `StrokeThickness` 同时设置，轮廓才会生效              |
| `StrokeThickness`                      | `double`           | 轮廓线条厚度，单位为**与设备无关像素**（1/96 英寸），支持小数 | 检测框、标记线粗细控制，高精度场景可设为 0.5 等亚像素值      |
| `StrokeStartLineCap``StrokeEndLineCap` | `PenLineCap` 枚举  | 开放线条起点 / 终点的端点样式，可选：`Flat`(平端)、`Square`(方端)、`Round`(圆端)、`Triangle`(三角端) | 刻度线、指示线用 `Round` 圆端，避免尖锐毛刺                  |
| `StrokeLineJoin`                       | `PenLineJoin` 枚举 | 多段线条拐角的连接方式，可选：`Miter`(尖角)、`Bevel`(斜切)、`Round`(圆角) | 矩形检测框用 `Miter` 保持棱角，曲线轨迹用 `Round` 平滑过渡   |
| `StrokeMiterLimit`                     | `double`           | 斜接尖角的最大延伸比例，默认值 10，限制小角度拐角的尖刺长度  | 小角度多边形必须设置，防止出现异常超长尖角                   |
| `StrokeDashArray`                      | `DoubleCollection` | 虚线样式序列，按「实线长度、空白长度」交替循环               | 绘制虚线检测框、辅助线，例如 `4,2` 表示 4 像素实线 + 2 像素空白 |
| `StrokeDashOffset`                     | `double`           | 虚线起始位置的偏移量                                         | 配合动画实现流动虚线，模拟扫描方向、传送带运动效果           |
| `StrokeDashCap`                        | `PenLineCap` 枚举  | 虚线段每一小段的端点样式                                     | 虚线端点平滑处理，避免虚线段出现尖锐边缘                     |

------

### 3. 布局拉伸属性

csharp:

```c#
public Stretch Stretch { get; set; }
```

- **类型**：`System.Windows.Media.Stretch` 枚举
- **默认值**：`None`
- **官方作用**：控制图形如何适配布局系统分配的可用空间，逻辑与 `Image.Stretch` 完全一致：
  - `None`：按图形原始坐标尺寸渲染，不拉伸，完全尊重坐标定义；
  - `Fill`：强制拉伸填满整个布局区域，宽高比可能失真；
  - `Uniform`：等比例缩放至完全容纳在区域内，不变形，完整保留图形；
  - `UniformToFill`：等比例缩放至完全覆盖区域，超出部分裁剪。
- **工业场景**：Canvas 绝对定位绘图用 `None`；自适应容器大小的工位示意图用 `Uniform`。

------

### 4. 几何核心属性：形状定义与渲染结果分层

这三个属性是 Shape 封装几何体系的核心，严格区分「原始设计定义」和「最终渲染结果」两个层级，是理解 Shape 底层原理的关键。

#### ① DefiningGeometry（受保护抽象）

csharp:

```c#
protected abstract Geometry DefiningGeometry { get; }
```

- **访问级别**：`protected abstract`，**所有派生类必须重写实现**，也是自定义 Shape 的唯一核心扩展点；
- **含义**：图形的**原始定义几何**，仅包含形状本身的坐标逻辑，不包含描边厚度、拉伸变换、虚线样式的影响；
- **示例**：`Rectangle` 重写后返回矩形几何，`Line` 重写后返回直线几何；
- **设计意图**：把「形状定义」和「布局、渲染、描边填充」完全分离，派生类只需要关心形状怎么定义，其余逻辑全部由基类统一处理，保证所有图形行为一致。

#### ② RenderedGeometry（公开虚拟只读）

csharp:

```c#
public virtual Geometry RenderedGeometry { get; }
```

- **含义**：**最终渲染生效的几何对象**，是在 `DefiningGeometry` 基础上，应用了 `Stretch` 拉伸、描边厚度扩展、坐标变换等全部渲染参数后的结果；
- **核心用途**：**精确命中测试、边界计算、碰撞检测**。比如判断鼠标点击是否落在图形轮廓上，必须用 `RenderedGeometry` 才能包含线条厚度的影响；
- **关键区别**：`DefiningGeometry` 是「设计图纸」，`RenderedGeometry` 是「实际渲染出来的实体」。

#### ③ GeometryTransform（公开虚拟只读）

csharp:

```c#
public virtual Transform GeometryTransform { get; }
```

- **含义**：应用在原始几何上的变换，主要是 `Stretch` 模式对应的缩放变换，以及布局对齐对应的平移变换；
- **工业用途**：可以获取图形从原始坐标到最终屏幕坐标的完整变换矩阵，用于坐标换算（比如把图像坐标转屏幕坐标）。

## 四、核心方法：融入 WPF 布局渲染流水线

三个重写方法分别对应 WPF 布局渲染流水线的三个核心阶段，这也是 Shape 能成为标准 `FrameworkElement`，而不是单纯绘图原语的关键。

### 1. MeasureOverride：布局测量阶段

csharp:

```c#
protected override Size MeasureOverride(Size constraint);
```

- **所属环节**：WPF 布局系统的「测量」pass，父容器调用此方法询问 Shape：给你 `constraint` 的可用空间，你需要多大尺寸？
- **内部逻辑**：
  1. 获取 `DefiningGeometry` 的原始边界尺寸；
  2. 结合 `Stretch` 模式、`StrokeThickness` 带来的边界扩展，计算出期望的 `DesiredSize`；
- **设计价值**：让 Shape 能和按钮、文本框等控件一样，参与 `Grid`、`StackPanel` 等容器的自动布局，而不是只能在 Canvas 里绝对定位。

### 2. ArrangeOverride：布局排列阶段

csharp:

```c#
protected override Size ArrangeOverride(Size finalSize);
```

- **所属环节**：WPF 布局系统的「排列」pass，父容器分配 `finalSize` 的最终空间，Shape 在此确定自己的最终渲染区域；
- **内部逻辑**：根据最终空间大小和 `Stretch` 模式，计算缩放比例和偏移量，生成 `GeometryTransform`，为渲染阶段做坐标变换准备；
- **返回值**：图形实际占用的最终尺寸。

### 3. OnRender：渲染绘制阶段

csharp:

```c#
protected override void OnRender(DrawingContext drawingContext);
```

- **地位**：Shape 渲染的核心入口，由 WPF 可视化渲染系统回调执行；
- **内部固定执行流程**：
  1. 基于 `DefiningGeometry`，应用 `GeometryTransform` 得到最终渲染几何；
  2. 若 `Fill` 不为 null，先用填充画刷绘制几何内部区域；
  3. 根据 `Stroke`、`StrokeThickness`、虚线、线帽等全部描边属性构造 `Pen` 对象；
  4. 用 `Pen` 绘制几何的轮廓线条；
- **设计价值**：所有派生类都不需要自己实现渲染逻辑，只需要定义好 `DefiningGeometry`，渲染逻辑统一由基类完成，保证所有图形行为一致、性能最优。

## 五、设计逻辑总结与工业场景价值

### 1. 核心设计思想

Shape 本质是 **「Geometry 几何 + FrameworkElement 框架能力 + 便利属性封装」** 的组合体：

- 底层用 `Geometry` 做形状定义和硬件加速渲染；
- 继承 `FrameworkElement` 获得完整的 WPF 框架能力（布局、绑定、事件、动画）；
- 把 `Pen`、`Brush` 等底层绘图对象拆分为一个个独立易用属性，大幅降低开发门槛。

### 2. 工业上位机的核心价值

1. **MVVM 友好**：所有属性都是依赖属性，可直接绑定视图模型中的缺陷坐标、工位状态、检测结果，无需跨线程操作 UI；
2. **矢量无损**：任意缩放不模糊，适配不同分辨率工控屏，支持放大查看细节；
3. **交互便捷**：天然支持鼠标点击、悬停路由事件，点击缺陷标记弹出详情、拖拽调整检测框等功能实现成本极低；
4. **扩展灵活**：通过重写 `DefiningGeometry` 可以自定义任意工业图形（十字标记、标尺、特殊工位符号），复用全部基类能力。

### 3. 常见开发误区

1. 只设置 `StrokeThickness` 不设置 `Stroke`，导致线条完全不显示；
2. 混淆 `DefiningGeometry` 和 `RenderedGeometry`，做命中测试用了原始几何，导致线条边缘点击不响应；
3. 高频刷新大量 Shape 实例：每个 Shape 都是完整的 `FrameworkElement`，有布局开销，上百个动态图形同时刷新时，性能不如 `DrawingVisual` 等低层绘制方案。
